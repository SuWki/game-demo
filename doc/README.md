# 项目文档总览

本目录的目标不是堆积资料，而是让任何接手者都能在不依赖聊天上下文的前提下，快速理解项目、继续开发、完成验证并留下可复盘记录。

## 阅读顺序

1. `00_接手入口/START_HERE.md`
2. `00_接手入口/当前交接卡.md`
3. `20_设计闭环/设计基线与约束.md`
4. `00_接手入口/项目总览.md`
5. `10_设计文档/完整体验设计方案.md`
6. `00_接手入口/技术架构总览.md`
7. 本轮相关的专题设计文档
8. `20_设计闭环/玩法假设与验证闭环.md`
9. `30_持续优化/策划落地任务清单.md`
10. `30_持续优化/测试与验证手册.md`
11. 最新一篇开发复盘

## 目录说明

- `00_接手入口`
  当前真相入口。给人和给 AI 的第一阅读层。
- `10_设计文档`
  当前有效的游戏设计说明。
- `20_设计闭环`
  记录为什么这样设计、怎么判断对不对、当前风险是什么。
- `30_持续优化`
  记录开发流程、验证方式、待办优先级、文档维护和每轮复盘。
- `40_AI协作`
  记录 AI 接手协议、提示词模板和协作要求。
- `90_历史归档`
  保留旧版阶段文档、封版记录和历史路线图，只用于追溯，不再作为第一入口。
- `skills`
  仓库内的技能资料。属于辅助资产，不承担当前项目真相入口职责。

## 使用原则

- 当前真相优先看新结构下的文档，不先翻历史日志。
- 如果新文档与归档文档冲突，以新文档为准。
- 每轮开发结束后，必须新增一篇复盘，并更新 `00_接手入口/当前交接卡.md`。
- 如果设计边界发生变化，必须同步更新 `10_设计文档` 与 `20_设计闭环` 对应文档。
- `progress.md` 仍保留为历史工作笔记，但不再视为项目事实源头。
