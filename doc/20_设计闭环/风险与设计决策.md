# 风险与设计决策

## 当前有效风险

### 风险 1：普通战回报链仍可能不够上头

- 现象：
  - 命中反馈已经成立，但“击杀 -> 掉落 -> 吸附 -> 升级”的节奏仍可能偏软
- 风险含义：
  - 玩家会觉得系统能跑，但战斗本身不够爽，不够愿意追下一波
- 当前策略：
  - 优先补击杀兑现、经验吸附和拾取回报，而不是继续堆更多说明性 UI

### 风险 2：首领后段覆盖率偏低

- 现象：
  - `屏卫主核` 的后段火线阶段在普通构筑样本里覆盖率偏低
- 风险含义：
  - 首领收尾体验仍可能偏薄
- 当前策略：
  - 继续作为监控项，而不是贸然重开大改

### 风险 3：路线连续性回归风险

- 现象：
  - 当前路线稳读和承接已经补过多轮，后续战斗打磨如果过度偏向单点爽感，可能反向打散路线读法
- 风险含义：
  - 项目会从“整体更爽”退回“局部更亮但整局更散”
- 当前策略：
  - 所有战斗打磨都优先走轻量反馈、掉落节奏和承接优化，不重开新路线系统

## 当前保留的关键设计决策

### 决策 1：不重写主流程

- 原因：
  - 当前问题已缩小到体验收口层，不是主循环结构性失效

### 决策 2：继续走数据驱动补量

- 原因：
  - 当前最有效的迭代方式仍是调模板、权重、强化和异常，而不是开新系统

### 决策 3：先补回报链，再扩新主题

- 原因：
  - 当前更缺的是战斗和循环的即时回报，不是又一轮新主题内容

### 决策 4：保留异常节点独立语义

- 原因：
  - 它承担变化感和记忆点，退回普通事件会让项目失去重要层次

### 决策 5：路线不前移成强制锁死

- 原因：
  - 当前问题是核心战斗打磨，不是路线出现太晚到必须一开局写死

## 风险更新规则

- 这里只保留当前仍有效的风险
- 历史风险与旧结论统一放归档
- 每次开发后，如果风险判断变化，先更新本文件，再更新交接卡
## 2026-04-28 决策：Boss 降弹幕密度，转向可读阶段压力

### 背景

玩家反馈 Boss 关弹幕过密，已经影响正常移动和躲避；同时 Boss 和精英的机制感不足，容易被理解成“血更厚的木桩”。

### 决策

- 不通过继续堆血量或增加弹幕密度制造难度。
- 优先把 Boss 压力改为“阶段切换 + 安全窗 + 可读弹幕”。
- 精英和 Boss 的差异优先来自行为、护卫、转阶段、裂口和安全窗，而不是单纯数值。

### 风险

- 弹幕密度回落后，Boss 可能短期显得不够压迫。
- 精英/Boss 机动提高后，近身压迫可能变强，需要通过自然样本继续观察玩家是否还有躲避空间。

### 验证重点

- Boss 终盘是否仍能移动、躲避和反打。
- 安全窗是否在视觉上可见，在时间上可进入。
- 精英是否更像有职责的敌人，而不是只更硬。
- 如果难度不足，下一步优先补阶段前摇和技能节奏，不直接把弹幕密度加回旧值。
