# 设计基线与约束

## 当前基线

本项目是一个短局节点推进自动射击原型，目标是验证单局里三条流派路线是否能清楚成立，而不是扩成完整商业项目。

## 设计红线

- 技术栈以当前 Phaser Web 原型为准，不按仓库名误判为 Unity。
- 主循环必须保留：开始 -> 节点推进 -> 战斗 / 整备 / 异常 -> 最终整备 -> 首领战 -> 结算 -> 重开。
- 三条主路线必须都能在真实整局中成立。
- 路线不能在前段普遍直接锁死。
- 异常节点必须维持独立语义，不能退回普通补给事件。
- 首领节点必须维持独立语义，不能退回普通战的换名版本。
- 主流程稳定优先，不因为局部问题随意重写 `RunEngine`。

## 当前结构约束

- 不做复杂大地图
- 不做大量局外成长
- 不新增无明确验证价值的新系统
- 内容补量优先走数据层，不优先开新运行时系统

## 当前数值约束

- 流派强化不从最低品质出现
- 同一强化来源单局内不重复发放
- 品质与推进深度挂钩
- 经验、掉落、压力变化应可被公式追踪

## 当前表现约束

- HUD 和结果页优先服务理解
- 音效优先服务反馈验证
- 表现层不负责掩盖玩法问题
- 玩家周围不允许恢复常驻路线线条、路线冷却条、无意义圆环或大型路线素材；路线触发优先放到敌人受击层、弹道命中层和短音效层。
- 游戏内可见文案不能出现内部设计/开发语言，例如“推进、构筑、承接、回切、主路线、功能开发中、检查装备、调整构筑”。这些词只能出现在设计文档或代码注释里。

## 当前开发约束

- 每轮只解决一个主问题
- 每轮开发必须留下复盘
- 设计变化必须同步文档
