# 版本目标与验收标准

## 0.9 阶段目标

### 目标

- 主循环跑通
- 三条主路线可玩
- 首领与异常语义成立
- 最低限度表现层与音效成立
- 可完成本地验证和结果导出

### 当前结论

- 已达到可测试版状态
- 不代表无风险，只代表没有阻断封版的系统问题

## 1.0 第一阶段目标

### 目标

- 在 `0.9` 稳定骨架上继续补内容和读法
- 提高自然样本中的路线连续性
- 提高不同局之间的差异感和重开动机
- 不重写主流程

### 当前阶段重点

- 核心循环的即时回报链打磨
- 普通战的击杀、掉落、吸附和升级衔接提纯
- 在继续打磨战斗爽感时守住路线连续性和首领监控项不回退

## 当前轮次验收标准

### 当前轮次：核心循环与核心战斗打磨

判断当前轮次是否签收，至少看三件事：

- 普通战里是否更容易读出“打中 -> 打死 -> 掉落 -> 拾取 -> 继续追击”的回报链
- 战斗爽感提升是否主要来自战斗本身，而不是单纯 UI 包装
- 路线连续性和首领监控项是否没有明显回退

### 当前判断

- 当前已经进入以核心战斗和回报链打磨为主的阶段
- 旧的路线收口工作不再是唯一主线，但仍需要作为回归项持续观察
- 当前是否签收，应以后续战斗实测和 Boss 监控回归结果共同判断

## 2026-04-26 当前验收补充：全链路游玩体验补强

### 当前目标

下一轮不以扩内容池为主，而是检查并补强玩家实际能感知到的完整链路：

- 进游戏是否知道要做什么。
- 移动、闪避、自动攻击和拾取是否顺手。
- 命中、击杀、受伤、擦弹、压力上升是否看得见、听得清。
- 节点、升级、危险提示和结算文字是否短、准、通俗。
- `crit / pierce / dash` 三路线是否仍保留基本差异。

### 签收标准

- `npm run build` 通过。
- 菜单 -> 战斗 -> 节点 / 升级 / 异常 / 整备 -> Boss -> 结算至少完成一次 full-flow。
- 玩家可见文案不出现乱码、编码残留或无法理解的技术词。
- `shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot` 在混战里比当前更容易区分。
- 操控和打击手感的修改必须是小步、可解释、可回归的，不允许用大幅数值膨胀掩盖问题。
- 如改动影响精英裂口、Boss 火线或路线 payoff，必须做对应定向观察并写入复盘。

## 2026-04-29 当前验收补充：Kimi 修复复检

### 当前目标

Kimi 已对玩家反馈的体验问题做过一轮小步修复。下一轮验收重点不是继续扩新内容，而是确认这些修复是否真正改变玩家侧感受：

- 音量面板是否从“点不开 / 关不掉”变成可用控件。
- 暂停继续是否从“游戏动了但窗口还在”变成 UI 与状态同步。
- 素材透明背景是否在实机画面中没有黑底残留。
- 子弹拖尾是否从硬线段残留变成更自然的速度反馈。
- 属性显示是否不再暴露内部倍率，尤其是暴击伤害不出现 `0.51x` 这类格式。
- Boss 弹幕是否从不可躲变成高压但有安全窗。
- 精英 / Boss 是否开始具备行为差异，而不是只靠血量制造难度。

### 签收标准

- `npm run build` 通过。
- 菜单 -> 战斗 -> 暂停 -> 继续 -> 结算 full-flow 至少完成一次。
- 开始页音量面板可打开、可调节、可关闭，且没有层级遮挡。
- 战斗中暂停后点击继续作战，暂停窗口必须隐藏，游戏继续运行。
- 玩家弹、敌弹、Boss 弹幕拖尾都不应像硬直线残留。
- 暴击率、暴击伤害、射速、冷却等属性显示必须是玩家能理解的格式。
- Boss 战必须至少出现可观察安全窗，不能连续封死玩家移动空间。
- 精英战必须能观察到普通怪没有的行为差异，但不能让近战压迫失控。

### 当前风险

- Boss 弹幕降密后可能变得过于安全。若出现该问题，优先补阶段预警、弱点窗口和反打节奏，不要直接把弹幕密度加回去。
- 精英横移增强可能让近战压迫过强。若出现该问题，优先限制贴脸时长或补硬直窗口，不要继续单纯加速度。
- 部分问题被标记为“代码已存在”或“前序已修”，仍需要用实机样本验证玩家侧是否真的感知到修复。

## 2026-05-01 当前验收补充：玩家实机反馈 15 项

### 当前目标

玩家实机反馈表明，当前版本的主要问题不是缺少新内容，而是若干基础规则和反馈没有被玩家读到。下一轮验收必须围绕这些问题确认：显示是否通俗、路线是否可感知、异常是否像玩法事件、Boss 安全区是否可信、数值是否仍然超模。

### 必须验收

- 玩家可见时间单位不再出现 `ms`，穿梭冷却和无伤窗口统一显示为秒。
- 穿梭触发后，玩家能通过提示或表现知道自己触发了穿梭收益。
- 歼灭关显示 `当前击杀/目标击杀`，生存关显示倒计时。
- 异常节点不再出现与普通强化无差别的单项数值卡。
- `crit / pierce / dash` 三路线都能出现多样化强化，而不是只反复给暴击率、穿透次数或穿梭冷却。
- 强化选择不默认立刻回血，生命回复速度不会让受伤失去意义。
- 同一组选择中不能出现效果几乎相同、只是换名字的卡。
- Boss 弹幕要高压但可读；安全区内应明显更安全，安全区外应有威胁。
- Boss 关完成必须来自 Boss 本体死亡，不能莫名其妙完成。
- 玩家移动不能因为 Boss 安全区惩罚或压力状态出现无法解释的减速。
- 默认音量为 `40%`，重启游戏不应自动变成 `0`。
- HP、EXP 和玩家可见属性摘要必须取整显示。
- 穿透路线不能无脑秒杀精英和 Boss，必须有上限、递减或其他强度边界。

### 签收方式

- `npm run build` 通过。
- 至少跑一次菜单 -> 战斗 -> 选择 -> Boss/结算 full-flow，且 `consoleErrors=[]`。
- 人工实机至少 3 局，分别优先走 `crit / pierce / dash`。
- 每局记录：路线、等级、是否通关、是否出现异常、是否遇到 Boss、安全区是否可读、是否仍然无压力秒杀。
- 如果某项没有被实机确认，必须标记为“待验”，不能写成已签收。
