# 通用项目接手提示词模板

下面这份模板可以直接复制到另一个项目里使用，只需要把占位符替换掉。

```md
你现在接手的是一个【项目类型】项目，当前目标是【一句话目标】。

你必须先读项目文档，再决定是否改代码。不要依赖聊天上下文，不要猜测项目历史。

请严格按以下顺序工作：

1. 先阅读：
   - `doc/00_接手入口/START_HERE.md`
   - `doc/00_接手入口/当前交接卡.md`
   - `doc/20_设计闭环/设计基线与约束.md`
   - `doc/00_接手入口/项目总览.md`
   - `doc/00_接手入口/技术架构总览.md`
   - 本轮相关的 `doc/10_设计文档/*`
   - `doc/20_设计闭环/玩法假设与验证闭环.md`
   - `doc/30_持续优化/测试与验证手册.md`
   - `doc/30_持续优化/开发复盘/` 下最新一篇文档

2. 阅读后先用中文输出以下内容：
   - 这个项目是什么
   - 当前阶段是什么
   - 当前最重要的问题是什么
   - 本轮明确不该做什么
   - 你准备先做什么

3. 在没有明确本轮目标前，不要直接改代码。

4. 执行时遵守以下规则：
   - 默认用中文输出
   - 如果文档冲突，以 `当前交接卡`、`设计基线与约束`、`版本目标与验收标准` 为准
   - 不把历史归档当成当前真相
   - 不做与本轮目标无关的大改
   - 优先做最小闭环修改

5. 每次开发结束后，必须：
   - 新增一篇开发复盘文档
   - 更新 `doc/00_接手入口/当前交接卡.md`
   - 如果设计边界变化，更新对应设计文档和设计闭环文档
   - 在回复中说明：
     - 改了什么
     - 为什么这么改
     - 怎么验证
     - 还剩什么风险

补充项：

- 项目类型：【例如 Web 游戏原型 / 前端应用 / 服务端项目 / 工具链项目】
- 一句话目标：【例如 在 10 分钟内验证核心玩法是否成立】
- 当前阶段：【例如 1.0 第一阶段 / MVP 收口 / 稳定性修复】
- 当前主问题：【例如 用户首次体验不清楚 / 某条主流程成功率偏低】
- 当前不做什么：【例如 不重构架构 / 不扩新系统 / 不改数据模型】
```

## 推荐搭配文档结构

- `00_接手入口`
- `10_设计文档`
- `20_设计闭环`
- `30_持续优化`
- `40_AI协作`
- `90_历史归档`
