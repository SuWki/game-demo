## 当前实现判断

### 已经合理的地方

- `RunEngine` 已经有比较完整的手感状态：`killFlowSec`、`pickupFlowSec`、`pickupLeadSec`、`tempoPulseSec`、`critOverdriveSec`、`dashDriveSec`、`eliteCrackWindowSec`。
- 移动已经不是纯位置位移，而是带有加速、转向爆发、滑行阻尼、受击控制衰减和击退。
- 射击已经按 `crit / pierce / dash` 做了差异：暴击偏爆点，穿透偏长线，穿梭偏近身和回摆。
- 掉落已经有磁吸、连锁拾取和拾取后续推进，说明“击杀 -> 掉落 -> 追过去 -> 再开火”的闭环已经存在。
- 音频已经有 `menu / battle / boss / result` 四态、`AudioCue` 语义、ducking、上下文 `routeFocus / encounter / intensity`。
- `PilotAudio` 已经开始为 `shoot / hit / kill / pickup / enemyShot / nearMiss / pressure` 做变体和上下文差异，不再是纯占位音。

### 仍然需要优化的地方

- 手感链条存在，但“连续动作的身体感”还可以更强。玩家移动、开火、击杀、拾取、再开火之间还需要更明确的节奏递进。
- `pierce` 已经有机制，但它的爽点仍更偏数值和弹道逻辑，和 `crit / dash` 相比，持续体感仍需要加强。
- `hit / kill / pickup` 已经有 cue，但需要进一步检查混在高频战斗里是否会变成一团短促提示音。
- `hurt / nearMiss / pressure` 语义是对的，但需要继续拉开危险等级：擦边、受击、高压压迫不能只靠音量差异。
- 普通战、精英战、Boss 战现在有状态差异，但“进入不同战斗后马上听出场景身份”的程度还可以继续提高。
- 精英裂口与 Boss 压力已经能画出来、播出来，但需要更稳定地推动玩家行动，而不是只当作提示层。

## 优化目标

本轮优化不是扩系统，而是让当前版本更像“能玩的战斗版本”：

- 玩家移动要更跟手，但不能变成漂移失控。
- 射击要更有落点确认，但不能噪音过多。
- 击杀要更推动追掉落，而不是只给一个死亡反馈。
- 拾取要更像回报链的一环，而不是普通收集音。
- 危险反馈要更清楚地区分“快要出事”和“已经受伤”。
- `crit / pierce / dash` 要在手感和音效上都有基本性格。
- 普通战、精英战、Boss 战要在压力节奏和声音层级上拉开。

## 开发优先级

### P0：先打磨基础手感闭环

优先检查和优化：

- 起步响应是否够快
- 停手和转向是否清楚
- 受击后的短暂失控是否明显但不过长
- 开火 recoil / muzzle pulse 是否能让玩家感到“正在输出”
- 命中是否比开火更实
- 击杀是否比命中更有收口
- 拾取是否能推动下一拍行动

对应代码：

- `src/systems/RunEngine.ts`
- `src/scenes/GameScene.ts`
- `src/data/balance.ts`
- `src/systems/PilotAudio.ts`

优先不要动：

- `RunEngine` 主流程
- 节点结构
- 大量数值表
- 大规模敌人 AI

### P1：强化 `pierce` 的持续手感和音效签名

`pierce` 不能只读成“子弹多穿几次”。它需要稳定读成：

- 长线
- 贯穿
- 拉轨
- 延续
- 清屏后的回收

建议优化方向：

- 让 `pierce` 子弹穿透成功后有更稳定的轨迹残留或细长回声。
- 让 `pierce` 命中和击杀 cue 带更清晰的“切线 / 拉链 / 金属贯穿”感。
- 让 `pierce` 在对精英裂口或护卫线时更容易触发短暂推进感。
- 保持它和 `crit` 的爆点、`dash` 的脉冲差异。

对应代码：

- `RunEngine.updatePlayerAutoFire(...)`
- `RunEngine.updateBullets(...)`
- `RunEngine.trySpawnPierceEchoShots(...)`
- `GameScene` 中 bullet / route overlay / player aura 相关绘制
- `PilotAudio` 中 `shoot / hit / kill / pickup` 的 route tint

### P1：拉开危险音频层级

当前危险音频不要继续只堆音量，应优先拉语义：

- `enemyShot`：敌方建立火线，偏“来袭”。
- `nearMiss`：玩家刚刚擦边，偏“掠过”。
- `hurt`：玩家已经受伤，必须更重、更短、更确定。
- `pressure`：场面压迫上升，偏低频、持续压迫，不要像普通提示音。

优化目标：

- 玩家闭眼也能分出“擦边”和“受伤”。
- 精英 / Boss 的 `pressure` 不能和普通敌方射击混在一起。
- `hurt` 必须拥有更高混音优先级。

对应代码：

- `PilotAudio.applyCueDuck(...)`
- `PilotAudio.getProfile(...)`
- `GameScene.syncAudioState(...)`
- `RunEngine` 中 near miss、hurt、pressure 触发点

### P1：让普通战、精英战、Boss 战听感更早分层

不是要新增很多音乐状态，而是用已有上下文增强：

- 普通战：稳定底拍，`hit / kill / pickup` 清楚。
- 精英战：`pressure` 更有重量，护卫和裂口反馈更突出。
- Boss 战：更低、更紧、更有阶段压迫，`enemyShot / pressure / boss` 要和普通战分开。

对应代码：

- `GameScene.syncAudioState(...)`
- `PilotAudio.setCombatContext(...)`
- `PilotAudio` 中 `enemyShot / pressure / hit / kill` 的 encounter tint
- `battleTemplates.ts` 仅在确实需要时微调压力节奏

### P2：补动作后的短反馈窗口

当前系统已经有 `killFlowSec` 和 `pickupFlowSec`，后续可以继续把它们变成更稳定的手感窗口：

- 击杀后短时间内移动、磁吸、射击节奏略微更顺。
- 连续拾取时音效不要每个都同样响，应有轻微连段感。
- 打出小高潮后，要能在 0.5 到 1 秒内被玩家真实感知。

对应代码：

- `RunEngine.updateExperienceOrbs(...)`
- `RunEngine.feedBattleFlow(...)`
- `PilotAudio.pickup`
- `GameScene` 的 pickup guide / flow overlay

## 本轮不建议做

- 不建议重写 `RunEngine`。
- 不建议新增复杂输入系统。
- 不建议重做自动瞄准规则。
- 不建议一次性新增大量 `AudioCue`。
- 不建议引入正式音频资源导入系统。
- 不建议把 Boss 或精英整套重做。
- 不建议为了手感直接大幅提高移速、射速、掉落吸附半径。
- 不建议把所有反馈都转成 UI 提示。

## 可以允许的最小扩展

如果开发判断确实需要扩接口，只允许做这些小扩展：

- 在现有 battle 状态里增加极少量手感窗口字段。
- 在 `PilotAudio` 内整理 cue profile helper。
- 在 `GameScene.syncAudioState(...)` 中补更准确的 `encounter / intensity` 判断。
- 在不膨胀 `AudioCue` 的前提下，增强同 cue 的变体和上下文染色。
- 为 `pierce` 增加少量视觉残留数据，但不要新开复杂特效系统。

## 验收标准

### 手感验收

开发完成后必须能回答：

- 起步是否比之前更清楚？
- 停手是否不拖？
- 转向是否有短爆发但不飘？
- 命中是否比开火更“实”？
- 击杀是否比命中更“收口”？
- 拾取是否推动下一拍？
- `pierce` 是否不再只是数值，而有持续体感？

### 音效验收

开发完成后必须能回答：

- `shoot / hit / kill / pickup` 是否在混战里仍能分辨？
- `nearMiss` 是否明显不是 `hurt`？
- `pressure` 是否明显不是 `enemyShot`？
- 精英战和 Boss 战是否一进场就比普通战更有压力身份？
- `crit / pierce / dash` 是否至少能听出三种方向？
- 音乐是否没有压过关键 cue？

### 技术验收

至少执行：

1. `npm run build`
2. 菜单 -> 普通战 -> 节点 / 强化 -> 精英或生存 -> Boss -> 结果页完整流程
3. 使用调试面板分别观察普通战、精英战、Boss 战
4. 使用 `window.__pilotAudioDebug()` 查看 cue 触发和音乐状态
5. 至少分别观察 `crit / pierce / dash` 三条路线一次
