## 项目一句话

这是一个基于 Phaser + TypeScript + Vite 的 Web 端短局节点推进自动射击原型。

玩家体验重点不是大地图探索，而是：

- 快速开局
- 在战斗中成型三条路线之一
- 在精英与 Boss 压力里读局、走位、追击
- 用很短的结案页把一局收干净，再推动重开

## 当前已经锁定的视觉结论

- 页面结构主方向：居中、粗块、强按钮、非黑盒
- 开始页：全屏背景 + 居中标题 + 居中按钮
- 结算页：中部结算信息 + 底部两个按钮
- HUD：左上 HP/EXP，顶部中间波次与玩法，角色头顶血条
- 选择界面：顶部标题 + 4 个选择框

这些结论来自用户明确给定的页面参考，不允许在未确认的情况下改回：

- 黑框黑底
- 科技终端首页
- 网页式双栏布局
- 结算页第三按钮
- 选择页顶部摘要区和右侧说明栏

## UI 协作者要产出的东西

- 基于 `UI页面固定规则.md` 和 `界面线框与落地清单.md` 的逐屏结构优化建议
- 开始页、HUD、路线选择、强化选择、异常处理、最终整备、结果页的布局细化
- 主按钮、HUD 条带、选择框的统一图形件规范
- 移动端或窄屏下如何继续保护中场的建议

## UI 协作者不该产出的东西

- 新增玩法层无关的大前台系统页
- 用长说明和大段描述填充页面
- 把结果页做成报表
- 把开始页做成平台官网落地页
- 把页面改回黑框黑底科技托盘

## 美术协作者要产出的东西

- 玩家、四类普通敌、精英、Boss 的轮廓方案
- 普通敌弹、Boss 弹道、Boss 火线、XP 球、危险区、安全窗的画面语言
- 开始页背景、按钮牌面、结算板、选择框的图形风格
- 与 `美术资产规格表.md` 对应的资源切图、图件或概念稿

## 美术协作者不该产出的东西

- 大批量剧情立绘
- 写实地景大图
- 与当前版本无关的 meta 包装
- 会压坏读局的复杂背景

## 交付前必须自检的四件事

- 玩家、敌人、敌弹、XP 球是否会混淆。
- HUD 是否仍然保护中场。
- 精英裂口是否先被画面读到。
- 结果页和开始页是否仍有重开冲动。

## 推荐工作顺序

1. 先看 `视觉与UI设计规范.md`
2. UI 看 `界面线框与落地清单.md`
3. 美术看 `美术资产与画面设计规范.md` 和 `美术资产规格表.md`
4. 交付前对照 `画面与UI验收清单.md`
