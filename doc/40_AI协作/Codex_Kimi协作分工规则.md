# Codex / Kimi 协作分工规则

## 一句话规则

后续默认由 `Codex` 做方向、设计、素材/音效草案、文档和开发提示词，由 `Kimi` 做代码实现、构建验证和实机 QA。

## Codex 负责什么

- 判断下一步开发方向。
- 整理和更新项目文档。
- 写清开发边界、验收标准和风险。
- 产出图片素材、音效、预览板、素材清单和接线说明。
- 给 Kimi 输出可直接执行的开发提示词。
- Kimi 开发完成后，继续做设计验收、文档补全和下一轮计划。
- 每次修改文档后，提交到当前开发分支。

## Codex 默认不做什么

- 不默认直接修改 `src/` 代码。
- 不默认替 Kimi 做代码落地。
- 不在没有用户明确要求时重写系统、改主流程或修运行时代码。
- 不把聊天上下文当成唯一事实来源，必须同步当前 docs。

## Kimi 负责什么

- 严格按 Codex 提示词读取指定文档和代码。
- 输出自己的理解、当前问题判断、实施计划。
- 修改代码、资源接线、构建脚本或 QA 脚本。
- 运行 `npm run build` 和提示词指定的 QA。
- 修改必要文档和新增开发复盘。
- 提交本轮代码和文档变更。

## Kimi 默认不做什么

- 不擅自扩系统。
- 不重写 `RunEngine` 或主流程，除非提示词明确允许。
- 不用自己的判断覆盖当前设计基线。
- 不只改代码不改文档。
- 不把 `output/`、`progress.md` 或历史归档当成当前真相。

## 标准交接流程

1. 用户提出方向、问题或体验目标。
2. Codex 读取当前文档，判断下一轮优先级。
3. Codex 更新必要规则/设计/交接文档。
4. Codex 输出 Kimi 开发提示词。
5. Kimi 按提示词开发、验证、提交。
6. 用户把 Kimi 回复给 Codex。
7. Codex 做验收判断，更新文档并决定下一轮方向。

## Kimi 提示词必须包含

- 本轮目标。
- 必读文档。
- 必读代码。
- 当前问题判断。
- 允许修改范围。
- 明确不允许做的事。
- 体验验收标准。
- 构建和 QA 要求。
- 文档同步要求。
- 最终回复格式。

## 当前推荐节奏

- Codex 轮：方向规划、文档整理、素材/音效预览、Kimi 提示词。
- Kimi 轮：代码开发、构建、QA、复盘、提交。
- Codex 轮：验收 Kimi 结果、补文档、定下一轮。
