# 开发GPT：商业化未来科技暗色UI实现提示词

## 使用场景

当需要让开发 GPT 继续优化本项目 UI 时，直接把本文件作为提示词使用。

本提示词的目标是让开发 GPT 按最新商业化未来科技暗色 UI 布局继续实现和优化。

## 必读文档

开发前必须先阅读：

- `doc/10_设计文档/UI页面固定规则.md`
- `doc/10_设计文档/商业化未来科技暗色UI布局与Web实现文档.md`
- `doc/10_设计文档/商业化未来科技暗色UI设计方案.md`

如果这些文档冲突，优先级如下：

1. `UI页面固定规则.md`：决定页面布局，最高优先级。
2. `商业化未来科技暗色UI布局与Web实现文档.md`：决定 Web 实现方式和组件层级。
3. `商业化未来科技暗色UI设计方案.md`：决定视觉风格。

## 给开发GPT的完整提示词

```md
你现在要继续优化一个 Phaser + TypeScript + Vite 的 Web Roguelite 自动射击游戏 UI。

重要约束：
- 页面布局以 `UI页面固定规则.md` 和 `商业化未来科技暗色UI布局与Web实现文档.md` 为准。
- 开始页必须是左侧主信息区 + 右侧环形核心视觉锚点。
- 结算页必须是左侧战报信息区 + 右侧环形核心视觉锚点。
- 选择页必须是中下区域商业化节点/强化卡组。
- 不允许回退到居中小卡片开始页。
- 不允许回退到绿色卡通风。
- 不允许做成 SaaS 后台、普通网页 landing page 或报表页。

固定布局：
- 开始页：左侧眉标、主标题、副标题、状态信息、主按钮、次按钮；右侧雷达环/核心机体视觉。
- 战斗 HUD：左上 HP / EXP，顶部中间波次 + 玩法，角色头顶血条，可保留轻量右上目标模块。
- 选择页：战场中下区域浮层，顶部选择标题，下方 3 张主要卡；如果系统给 4 个选项，可以做 4 卡但不得加侧栏说明。
- 结算页：左侧结果标题、本局统计、总结和两个按钮；右侧雷达环/核心机体视觉和简短 debrief。

视觉方向：
- 商业化未来科技暗色 UI。
- 深黑、深蓝灰、枪铁色为主底。
- 青蓝能量光作为主强调。
- 橙红用于危险。
- 金色用于奖励或胜利点缀。
- 紫色用于异常。
- 使用切角面板、细描边、半透明深色材质、扫描线、环形雷达元素。
- 整体要克制、专业、像商业化科幻战术射击游戏，不要像网页后台、SaaS 仪表盘、绿色卡通页或低端手游。

实现方式：
- UI 继续使用 DOM + CSS。
- Phaser 继续负责战斗场景、角色、敌人、弹道和场内反馈。
- 优先修改 `src/style.css`。
- 如必须调整 DOM class，可以修改 `src/ui/OverlayController.ts`，但不得改变页面结构。
- 不要重写 RunEngine。
- 不要引入新的大型 UI 框架。

当前主要文件：
- `src/ui/OverlayController.ts`
- `src/style.css`
- `src/scenes/GameScene.ts`
- `src/scenes/MainMenuScene.ts`
- `src/scenes/ResultScene.ts`

优化目标：
1. 开始页实现左信息右核心视觉的商业化科幻入口。
2. 结算页与开始页同构，形成战报结案页。
3. HUD 保持轻量，不遮挡战场。
4. 选择卡保持原始选择框结构，但材质、描边、品质色和 hover 反馈更商业化。
5. 页面文字必须无乱码。
6. 桌面和移动端都不能破版。

开发完成后必须验证：
- 运行 `npm run build`。
- 用浏览器检查开始页、战斗 HUD、选择页、结算页。
- 截图确认开始页是左侧信息区 + 右侧核心视觉。
- 截图确认结算页是左侧战报 + 右侧核心视觉。
- 截图确认选择页是商业化节点/强化卡组，不是网页卡片。
- 确认控制台没有报错。

输出结果时说明：
- 改了哪些文件。
- 是否符合最新布局文档；如果回退到旧布局必须说明并回滚。
- 构建是否通过。
- 截图路径或验证方式。
```

## 开发注意事项

- 如果用户只说“优化风格”，不要改当前商业化布局。
- 如果用户说“像商业化未来科技暗色 UI”，优先改 CSS token、材质、描边、发光、背景层。
- 如果用户说“选择框坏了”，优先检查是否还在使用 `choice-strip` 结构，不要改成新的卡片体系。
- 如果用户说“开始页布局不对”，优先检查是否仍为左侧主信息区 + 右侧核心视觉锚点。
