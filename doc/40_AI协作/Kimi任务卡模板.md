# Kimi 任务卡模板

## 使用原则

这是给 Kimi 的轻量交接模板。适用于小步开发、QA、补验、截图、音效/素材接线、局部修复。

如果本轮涉及阶段切换、玩法方向改变、大系统边界变化，再改用完整长提示词。

## 任务卡

```md
你现在接手的是本项目【填写任务名】任务。

语言要求：开发过程中可以用英文记录工具日志、代码字段、命令输出和临时草稿；但开始前判断、实施计划、验证结论、开发复盘和最终回复必须使用中文。除代码、命令、文件名、字段名、commit hash 和工具原始输出外，不要用英文作为主要叙述语言。

## 1. 本轮一句话目标

【用一句话说明本轮目标。例：用真实浏览器补验 boss-bastion 安全窗是否高压但可读。】

## 2. 最少必读文档

1. `doc/00_接手入口/当前交接卡.md`
2. `doc/30_持续优化/当前待办与优先级.md`
3. `doc/30_持续优化/开发复盘/【最新相关复盘】.md`
4. `doc/40_AI协作/Codex_Kimi协作分工规则.md`

## 3. 文件级导航

- `文件路径`：为什么要看这个文件。
- `文件路径`：本轮只需要关注哪些函数 / 片段。

## 4. 先输出判断

开始前先用中文说明：

1. 当前项目阶段
2. 本轮为什么只做这个目标
3. 本轮先验证什么
4. 验证失败才允许修什么
5. 本轮明确不做什么

## 5. 代码骨架草案

### 推荐修改文件

- `文件路径`
- `文件路径`

### 接口 / 函数草案

```ts
// 这里只放结构，不要求逐字照抄。
type ExampleSnapshot = {
  ok: boolean;
  reason: string;
};

function collectExampleSnapshot(): ExampleSnapshot {
  // TODO(Kimi): 从现有状态读取数据。
  return { ok: false, reason: 'not implemented' };
}
```

### 实现顺序

1. 先补最小数据出口或验证脚本。
2. 再跑验证。
3. 如果验证失败，只修失败项。
4. 最后更新文档和复盘。

## 6. 验证要求

- `npm run build`
- 【本轮 QA 命令】
- 【截图 / 人工观察要求】
- 【console error 要求】

## 7. 允许修改

- `文件路径`
- `文件路径`

## 8. 禁止事项

- 不重写 `RunEngine`
- 不重开主流程
- 不新增大系统
- 不混入无关改动
- 不提交 `output/`，除非本轮明确要求提交展示素材或截图索引

## 9. 文档同步

完成后至少更新：

1. `doc/00_接手入口/当前交接卡.md`
2. `doc/30_持续优化/开发复盘/` 下新增本轮复盘
3. 【如有对应设计文档，列出】

## 10. 提交与推送

1. `git status`
2. 只暂存本轮相关文件
3. 提交到 `codex-dev`
4. 推送到 Gitee：`origin/codex-dev`

## 11. 最终回复格式

请用中文汇报：

1. 本轮目标
2. 实际验证 / 修改内容
3. 修改文件
4. 验证结果
5. 文档更新
6. commit hash
7. Gitee 推送状态
8. 最大残留风险
```

## 常用骨架编号

- `QA-BOSS-01`：Boss 定向触发和安全窗采样。
- `QA-FLOW-01`：菜单 -> 战斗 -> 暂停 -> 继续 -> 结算 full-flow。
- `AUDIO-CUE-01`：音效 cue 触发计数和 ducking 层级检查。
- `VISUAL-SHOT-01`：截图采样、素材透明背景和画面可读性检查。
- `DOC-REVIEW-01`：只验收结果、更新文档和下一轮计划，不改代码。
