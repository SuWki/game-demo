# 音频方案_策划GPT评审对接文档

## 文档目的

这份文档不是再重复一遍音频设计方案，而是把当前项目的音频设计上下文、评审重点、判断标准和期望输出格式整理成一份可以直接交给策划 GPT 的输入件。

如果你只需要一份更短、更快、更适合重复投喂的版本，请优先使用 `音频方案_快速评审对接文档.md`；本文件保留为完整版评审输入件。

使用场景很明确：

- 你已经有一套音频设计方案
- 你希望策划 GPT 从玩法、节奏、路线辨识、Boss 收尾、资源优先级这些角度来判断方案是否成立
- 你不希望它只给泛泛意见，而是给出结构化结论

## 给策划 GPT 的角色定义

请把自己视为“负责核心体验与版本节奏的游戏策划”，不是纯音频工程师，也不是纯审美顾问。

你的判断重点应该是：

- 这套声音方案是否真正服务当前玩法目标
- 它是否强化了玩家读局、追击、收尾和重开动机
- 它是否和项目当前阶段匹配
- 它是否存在过度设计、偏题设计或优先级错误

## 先给你一句话项目定义

这是一个基于 `Phaser + TypeScript + Vite` 的 Web 端短局节点推进自动射击原型。

单局目标不是大地图探索，也不是长线养成，而是：

- 开始页进入一局
- 在普通战 / 整备 / 异常 / 精英 / Boss 收尾之间推进
- 通过击杀、拾取、升级和节点选择，把一条路线逐步扶到站稳
- 在结算后产生“想马上再开一局”的动机

## 当前项目阶段

当前项目处于 `1.0 第一阶段` 的体验收口阶段。

这一阶段的主线不是：

- 重写系统
- 新开地图玩法
- 新开 Boss 专项轮
- 做完整商业化包装

这一阶段的主线是：

- 核心循环回报链继续压实
- 普通战 / 精英战 / Boss 战的读感继续拉开
- 三条路线在实战里的辨识度继续变稳
- 结果页和重开动机继续成立

## 你需要先接受的设计红线

在评审时，请不要默认项目可以随意扩成完整商业项目。

当前明确红线：

- 不做复杂大地图
- 不做长线局外成长
- 不重写 `RunEngine`
- 不新增没有明确验证价值的新系统
- 音效优先服务反馈验证，而不是纯装饰
- 表现层不负责掩盖玩法问题

如果你给出的建议依赖这些红线之外的前提，请明确标注为“超出当前阶段，不建议现在执行”。

## 为什么现在要做音频方案评审

当前项目已经有最小可用的程序音频骨架，但它仍属于“反馈闭环版本”，不是正式资产方案。

目前已经成立的基础：

- 菜单、战斗、Boss、结果页有状态音乐
- `shoot / hit / kill / pickup / hurt / nearMiss / enemyShot / pressure / relay*` 等关键 cue 已经在跑
- 低血危险感、受击确认、家族 relay、精英压力层次都已经在代码和复盘里有明确接线

现在要评审，不是因为“项目完全没声音”，而是因为已经到了该判断下面几件事的时候：

- 当前音频方向是否真的服务核心玩法
- 哪些声音应该优先正式化
- 哪些高光应该保留，哪些其实可以砍
- 哪些地方是“做更多会更好”，哪些地方是“做太多反而偏题”

## 当前音频方案摘要

为了让你不用先读完所有细文档，这里先给出方案摘要。

## 1. 声音总目标

声音的首要职责不是把场面做满，而是帮助玩家更快读懂、打得更顺、并更想再开一局。

当前声音方案重点服务五件事：

- 让玩家立刻知道自己是否打中了、打死了、捡到了
- 让玩家在低血、近失和高压阶段更快读到危险
- 让普通战、精英战、生存战、Boss 战一进场就不像同一张皮
- 让 `crit / pierce / dash` 三条路线在实战里有可重复辨识的听觉性格
- 让开始、阶段推进、结果和重开构成完整单局闭环

## 2. 声音风格方向

当前总方向定为：

- 近未来训练场
- 电子脉冲
- 金属火花
- 低频撞击
- 压缩过的战场能量

这意味着它不是：

- 写实军武
- 空灵太空歌剧
- 复古像素芯片乐
- 长混响电影动作片

## 3. 当前分层结构

方案把声音分成六层：

- 音乐状态层：`menu / battle / boss / result`
- UI 交互层：`click / confirm / start / upgrade / anomaly / result`
- 玩家动作层：`shoot / dash / hurt`
- 战斗结果层：`hit / kill / pickup / crit`
- 压力与预警层：`enemyShot / nearMiss / pressure`
- 家族与路线层：`relayStandard / relaySkirmisher / relayBrute / relayRanged` 以及路线高光

## 4. 当前优先级思路

方案把正式制作优先级分成三档：

### `P0`

核心循环和战斗读感必须依赖的声音：

- `shoot`
- `hit`
- `kill`
- `pickup`
- `hurt`
- `nearMiss`
- `enemyShot`
- `pressure`
- `start`
- `upgrade`
- `menu / battle / boss / result` 四个音乐状态

### `P1`

用于拉开敌人、路线和结尾辨识的声音：

- 四类 `relay`
- `crit`
- `dash`
- `anomaly`
- `victory`
- `defeat`

### `P2`

用于提升层次和记忆点的结构型声音：

- 精英裂口打开
- 精英裂口 follow-through
- Boss phase shift
- Boss fireline sweep
- 连续拾取叠层
- 路线成型签名

## 5. 当前方案的关键设计判断

方案里有几个重要判断，请你重点审：

### A. 核心回报链优先

当前认为音频第一优先级必须围绕：

- 打中
- 打死
- 掉落/拾取
- 继续追下一拍

也就是说，先把主链做顺，再谈高光和签名。

### B. 精英和 Boss 必须有结构差异

当前认为精英和 Boss 不应该只比普通战“更响”，而应该在声音结构上体现：

- 精英：先顶、先封、再出现裂口
- Boss：阶段切换、持续压迫、最终收束

### C. 三条路线必须听起来不同

当前认为：

- `crit` 应该更像升温和收割
- `pierce` 应该更像切线和贯穿
- `dash` 应该更像换位和反打

如果听起来只是颜色不同，那路线辨识是不成立的。

### D. 不建议现在就无限扩 cue

当前方案刻意保持克制，不建议立刻把所有战斗事件细拆成大量独立 cue。

当前判断是：

- 先替换和强化已有核心 cue
- 再在必要时增加少量结构型 cue
- 避免系统膨胀和混音失控

## 你需要重点判断的内容

请你重点回答以下问题。

## 1. 方案是否真的服务当前玩法目标

请判断：

- 这套音频方案是否真正强化了核心循环
- 它是否帮助玩家更快读懂“打中 -> 打死 -> 拾取 -> 继续追击”
- 它是否有助于提升重开动机

## 2. 音频重点是否放对了地方

请判断：

- `P0 / P1 / P2` 的排序是否合理
- 现在先做核心主链，而不是先做大量高光或大主题音乐，是否对
- 有没有某些被放在 `P2` 的内容其实应该前提到 `P1` 或 `P0`

## 3. 路线和战斗层次是否被声音正确表达

请判断：

- `crit / pierce / dash` 这三条路线的听觉区分是否足够清楚
- 普通战、精英战、生存战、Boss 战的声音角色是否拉得开
- 精英裂口和 Boss 转段是否有必要成为独立结构音

## 4. 是否存在过度设计

请判断：

- 当前方案里有没有明显“做了会更复杂，但对当前项目收益不大”的内容
- 有没有某些资产或概念更像完整商业项目才需要，现在不该做
- 有没有某些声音设计会把项目从“战斗读感优化”带偏到“纯包装”

## 5. 是否存在缺漏

请判断：

- 当前方案是否漏掉了某些对玩法理解很关键的声音
- 现有清单里有没有缺少某种关键结构音
- 结果页和重开动机这一段是否需要额外补强

## 6. 实施顺序是否合理

请判断：

- 第一轮只替换 `P0` 是否合理
- 第二轮再拉开 `relay / crit / dash / anomaly / result` 是否合理
- 第三轮才做精英裂口和 Boss phase 的结构音，是否过晚或合适

## 你评审时不要做的事

请不要：

- 默认可以新增完整音频系统
- 默认可以重做战斗玩法去适配声音
- 默认可以新增大量 UI 说明来配合音频
- 用“做成更商业”替代“当前版本更成立”
- 用纯审美偏好取代玩法判断

如果你想提出超出当前阶段的大改建议，请单独标注：

- `超出当前版本范围`

## 期望你给出的输出格式

请按下面格式输出，不要只给散点意见。

### 1. 总结论

一句话结论：

- 这套方案是否整体成立
- 是否适合当前阶段继续推进

### 2. 总体判断

请简要判断：

- 方案最正确的地方是什么
- 最大的问题是什么
- 最需要先确认的风险是什么

### 3. 详细评审

请按以下维度分别给结论：

- 核心循环支持度
- 战斗读感支持度
- 路线辨识支持度
- Boss / 精英层次支持度
- 项目阶段匹配度
- 实施优先级合理度

每个维度请给：

- `成立 / 基本成立 / 不成立`
- 简短理由

### 4. 问题清单

请只列真正重要的问题，按优先级分级：

- `P0`
  如果不处理，会直接影响当前方案是否值得推进
- `P1`
  重要，但可以在第一轮后修正
- `P2`
  可优化项，不影响主线推进

### 5. 建议保留的部分

请明确指出：

- 哪些设计应该保留，不要被误砍
- 哪些优先级安排是对的

### 6. 建议删减或延后的部分

请明确指出：

- 哪些内容是过度设计
- 哪些声音现在不值得做
- 哪些可以推迟到后续阶段

### 7. 建议新增或前提的部分

请明确指出：

- 哪些当前缺漏值得补
- 哪些 `P2` 内容应该提到 `P1`
- 哪些当前没有写清的地方需要补文档或补方案

### 8. 最终建议

请在下面三种结论里选一个，并给出理由：

- `可以按当前方案推进`
- `需要小改后推进`
- `建议先重排方案再推进`

## 可选评分模板

如果你愿意，也可以按 10 分制给分，但请不要只有分数没有解释。

建议评分维度：

- 核心循环契合度
- 战斗读感提升潜力
- 路线辨识潜力
- Boss / 精英结构契合度
- 当前阶段匹配度
- 实施性

## 对你最终回答的额外要求

- 优先说判断，不要先长篇复述方案
- 优先指出真正影响推进的点，不要堆很多小意见
- 如果你认为某个点超出当前版本边界，请明确写出来
- 如果你认为方案整体成立，也请指出最需要防回退的地方

## 这份文档的用途

这份文档的目标不是让策划 GPT “帮忙润色方案”，而是让它做一次更像正式策划评审的判断：

- 这套音频方案是不是在做对的事
- 有没有抓住当前项目真正需要的声音问题
- 有没有把优先级排对
- 有没有过度设计

如果你的判断能回答这四个问题，这次评审就是有效的。
