# 音频方案_快速评审对接文档

## 文档目的

这是一份给策划 GPT 或协作者使用的短版输入件。

它只回答三件事：

1. 这个项目现在到底处在哪个阶段。
2. 当前音频方案最该评什么、不该评什么。
3. 评审输出应该长什么样。

如果需要完整上下文、完整红线和完整评审格式，请再读 `音频方案_策划GPT评审对接文档.md`。

## 你的角色

请把自己视为“负责当前版本体验成立的游戏策划”，不是纯音频工程师，也不是单纯审美顾问。

你要判断的是：

- 这套音频方案是否真的服务当前玩法目标。
- 它是否适合当前版本继续推进。
- 它有没有优先级错位或过度设计。

## 一句话项目定义

这是一个基于 `Phaser + TypeScript + Vite` 的 Web 端短局节点推进自动射击原型。

单局体验重点是：

- 进入一局
- 在普通战 / 整备 / 异常 / 精英 / Boss 收尾之间推进
- 通过击杀、拾取、升级和节点选择把一条路线扶起来
- 在结算后产生“马上再来一局”的动机

## 当前阶段

当前处于 `1.0 第一阶段` 的体验收口期。

这一阶段优先做的是：

- 把核心循环回报链压实
- 把普通战 / 精英 / Boss 的读感继续拉开
- 把 `crit / pierce / dash` 的实战辨识度做稳
- 把结果页和重开动机做成立

这一阶段不优先做的是：

- 重写系统
- 大幅扩玩法
- 新开复杂音频状态机
- 为了声音去反推重做战斗玩法

## 当前音频方案的核心判断

请先接受下面几条当前方案前提：

1. 声音第一职责不是把场面做满，而是让玩家更快读懂局势。
2. 第一优先级是 `shoot -> hit -> kill -> pickup` 这条主链。
3. `hurt / nearMiss / pressure` 三者必须明确分家。
4. `crit / pierce / dash` 必须听起来方向不同，但第一轮不追求把每条路线都拆成完整新系统。
5. 普通战、精英战、Boss 战不能只靠“更响”区分，必须有结构差异。

## 当前文档收口后的重点

你在评审时，请默认这些已经是当前正式口径：

- 继续维持 `menu / battle / boss / result` 四个音乐状态。
- 优先沿现有 `routeFocus / encounter / intensity` 上下文做差异，不优先新开很多 cue。
- `P0` 继续围绕主链、危险链和四个音乐状态。
- `P1` 明确包含：
  - 四类 `relay`
  - `crit`
  - `dash`
  - `result / victory / defeat`
  - `elite_crack_open`
  - `boss_phase_shift`
- `P2` 继续后置：
  - `elite_crack_follow`
  - `boss_fireline_sweep`
  - `boss_safe_window_open`
  - 路线成熟签名
  - 连续拾取叠层

## 你必须重点判断的 5 个问题

### 1. 这套方案是不是在强化当前核心循环

请判断它是否真的让玩家更容易听懂：

- 打中了
- 打死了
- 捡到了
- 应该继续追

### 2. 优先级是不是排对了

请判断：

- 先做主链和危险链，再做高光和签名，是否合理
- `elite_crack_open` 和 `boss_phase_shift` 前提到 `P1` 是否合理
- 还有没有被放错档位的内容

### 3. 路线辨识是不是足够

请判断：

- `crit` 是否应该更热、更收割
- `pierce` 是否应该更线性、更切线
- `dash` 是否应该更像换位反打

如果只是“颜色不同”，请明确指出不成立。

### 4. 精英和 Boss 是否真的有结构差异

请判断：

- 精英是否体现了“先顶、先封、再裂口”
- Boss 是否体现了“阶段切换、持续压迫、最终收束”

### 5. 方案有没有过度设计

请特别判断下面这类风险是否存在：

- cue 拆得过细
- 高光做得太多
- 文档比当前代码和版本承载更快
- 用装饰性声音代替玩法可读性

## 输出格式

请按下面格式输出，不要只给散点意见。

### 1. 一句话总判断

从下面三种结论里选一个：

- `可以按当前方案推进`
- `需要小改后推进`
- `建议先重排方案再推进`

### 2. 最正确的部分

请指出 1 到 3 个最应该保留的判断。

### 3. 最大问题

请指出 1 到 3 个真正影响推进的问题。

### 4. 优先级判断

请按 `P0 / P1 / P2` 格式列出你认为需要调整的项。

### 5. 边界提醒

如果你的建议超出当前阶段，请单独标注：

- `超出当前版本范围`

## 额外要求

- 优先给判断，不要先长篇复述方案。
- 优先指出真正会影响推进的点，不要堆很多小意见。
- 如果你认可方案整体方向，也请指出最需要防回退的地方。
- 不要默认可以新开完整音频系统。
