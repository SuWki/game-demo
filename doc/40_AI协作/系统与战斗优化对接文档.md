# 系统与战斗优化对接文档

## 文档状态

- 状态：`当前生效 / 已落地后的复检对接稿`
- 适用对象：开发、策划、接手协作者
- 文档目标：同步 2026-04-27 已落地的系统与战斗优化，并明确下一步只做验证、打磨和作品集支撑，不再误判为“待开发大功能”。

## 当前判断

当前项目已经不是“缺系统入口”，而是“系统骨架已经接上，需要确认自然游玩中是否稳定、清楚、好用”。

已经接上的能力：

- 开始页音量入口。
- 局内暂停按钮。
- 暂停面板：继续、重开、返回主页、音量。
- 结果页右侧对局数据。
- 升级卡片 tooltip。
- `crit / pierce / dash` 特殊 buff 伤害声纹拆分。
- 更轻的击中镜头抖动。
- 移除 XP 拾取线段拖尾。
- 上调拾取范围和磁吸范围。
- 强化档位差异继续修正。

因此下一步不应继续补“按钮有没有”，而应确认：

- 这些入口是否在 full-flow 里稳定可用。
- 重开、返回主页、暂停恢复是否不会打断流程。
- 音量调整是否真的影响 `PilotAudio`。
- 结果页数据是否对玩家和作品集展示都有价值。
- 战斗表现是否更清楚，而不是只是更安静。

## 下一步优先级

### P0：版本验收与回归

必须先做：

1. `npm run build`
2. 菜单 -> 战斗 -> 节点 / 升级 / 异常 / 最终整备 -> Boss -> 结算 full-flow
3. 暂停 / 继续 / 音量 / 重开 / 返回主页专项验证
4. 3~5 分钟自然战斗样本
5. 乱码扫描

当前已知复检风险：

- full-flow 已能到结算，但重开检测需要继续复核。
- 暂停 / 音量脚本能完成截图，但音量字段写出不完整，需要确认是脚本问题还是选择器问题。

### P1：自然样本下的战斗稳定性

重点观察：

- 第 2~3 节点是否仍容易打断节奏。
- `shoot / hit / kill / pickup` 是否形成连续回报链。
- `hurt / nearMiss / pressure / enemyShot` 是否仍能压过爽感音效。
- 拾取范围上调后，是否更顺手且不造成奖励失真。
- 镜头抖动压轻后，是否仍有命中冲击。

### P2：作品集支撑材料

当前项目后续要服务“战斗策划作品集”，因此系统与战斗优化也要能产出材料：

- 结果页数据可以作为演示视频中的结论画面。
- 战斗参数、敌人参数、Boss 火线覆盖、精英裂口追击都应能转成表格或案例页。
- 素材与音效优化优先服务演示视频可读性，不抢设计主线。

## 本轮不建议做

- 不重写 `RunEngine`。
- 不新开复杂系统。
- 不继续扩大战斗内容池。
- 不急着新增 Boss 或精英，除非作品集案例证明当前内容说服力不足。
- 不一次性替换所有正式素材。
- 不把素材和音效优化做成独立美术/音频作品集。

## 素材与音效同步优化原则

可以与作品集制作同步推进，但必须遵守三条规则：

1. 先替换最影响视频观感和读局的资产：玩家、标准敌、精英核心、Boss Bastion、XP 球、玩家弹道、敌弹。
2. 先替换最影响手感判断的音效：`shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot`。
3. 每次替换都要做 A/B 观察，确认正式素材没有降低可读性。

## 验收口径

本阶段完成后，应能回答：

- 当前版本能否稳定跑完一局。
- 暂停、音量、重开、结果页是否都可用。
- 普通战回报链是否比之前更顺。
- 三路线声纹是否比之前更容易区分。
- 素材替换是否让画面更清楚，而不是更花。
- 这些结果是否能支撑作品集的一页总览、参数表、敌人表和演示视频。
