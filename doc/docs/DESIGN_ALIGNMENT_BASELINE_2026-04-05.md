# 2026-04-05 设计基线澄清与对齐清单

## 文档优先级
- 本文件记录 2026-04-05 用户最新确认的设计口径。
- 如果旧文档中的“当前实现口径”与本文件冲突，后续开发与审计应优先以本文件和最新 `DEV_ISSUE_LOG.md` 为准。
- 本文件的用途是“校准当前实现是否偏离设计”，不是授权随意重做无关系统。

## 一、核心操作与单局循环
- 战斗操作参考《土豆兄弟》：`WASD` 移动，攻击保持自动进行。
- 敌人被击败后掉落经验，玩家通过拾取经验球完成战斗内成长。
- 每次升级都进入一次属性强化三选一。
- 单局循环目标口径：
  - 开始页
  - 地图推进
  - 战斗 / 强化 / 异常
  - 击杀与拾取经验
  - 升级三选一
  - 进入最终 Boss 收尾
  - 结算
  - 重开

## 二、强化系统设计基线
- 强化分为两大类：
  - 通用属性强化
  - 三条流派的特殊强化
- 强化品质固定为五档：
  - 白 `common`
  - 绿 `uncommon`
  - 蓝 `rare`
  - 紫 `epic`
  - 金 `legendary`
- 高品质强化的出现概率应随着关卡推进、阶段深入而上升。
- `upgrade` 节点允许相较普通战斗内升级，提供更偏高品质的三选一。
- 每个强化都应有可比较的 `valueScore` 或等价价值公式，高价值强化应更倾向于对应更高品质。
- 三流派特殊强化只允许从绿 `uncommon` 开始出现，不应在白 `common` 中出现。
- 每个强化在单局内只允许被选择一次：
  - 应按强化源 `sourceId` 或等价唯一标识去重
  - 不应因为品质不同就允许重复获取同一强化
- 强化出现概率与强化价值必须有公式支撑，并在 `NUMERIC_FORMULAS.md` 中可追踪。

## 三、地图与关卡设计基线
- 地图表达参考《杀戮尖塔 2》的路线推进模式，但保持轻量化。
- 玩家可以自主选择下一关去向，但不是每次都必须给出多个选项。
- 整局末尾必须由一个 Boss 关收尾。

### 目标关卡类型
- `boss`
- `battle`
- `upgrade`
- `anomaly`

### 说明
- `anomaly` 是玩家可感知的异常关卡口径，不只是普通事件的换名。
- 如果当前实现仍临时复用 `event` 数据层，也需要在文档与审计中明确它和目标 `anomaly` 口径之间的差距。
- 如果最终 Boss 仍临时复用 battle 模板，也需要明确记录“当前实现”与“目标设计”之间的差异，而不能默认视为完全一致。

## 四、战斗关卡设计基线
`battle` 关卡下至少要覆盖三种战斗子类型：

1. 普通关
- 目标是击败指定数量敌人通关。
- 用来承担最稳定的推进与成长。

2. 精英关
- 目标是击败精英怪通关。
- 精英怪应读取玩家操作意图，更多地做反方向位移与拉扯。
- 精英怪需要尽量让小怪挡在自己身前，避免被轻易秒杀通关。
- 精英关的难点应来自“拆掩护 + 追击本体”，而不是单纯堆血。

3. 生存关
- 持续刷新敌人，玩家坚持到时间结束即通关。
- 最后 `10s` 必须进入更高压阶段，重点提高敌人移动速度与追压感。
- 生存持续时间应随关卡推进逐步增长。
- 压力增长必须有平滑公式，不能因为最后 `10s` 突然把玩家直接判成必死。

## 五、敌人族群设计基线
基础小怪至少应有四种，并且每种都要能被玩家快速区分：

1. 普通怪
- 属性均衡，用来提供基准压力。

2. 厚血慢速大体型怪
- 移动稍慢，但血量更高、体积更大。
- 作用是顶线、占空间、挤压走位。

3. 高速脆皮怪
- 移动更快，但血量更低。
- 作用是制造追压和失误惩罚。

4. 远程怪
- 具备明确的远程攻击能力。
- 作用是打断玩家直线走位，迫使其重新规划路径。

### 额外说明
- 精英与护卫可以继续存在，但它们不能替代上述四种基础敌人族群。
- 四类基础敌人至少需要在体型、速度、血量、攻击方式或表现上具备明确差异。

## 六、公式与数据化要求
- 继续遵守数据驱动原则：
  - `RunEngine` 只负责驱动流程
  - 玩法内容继续落在 `nodes / templates / events(or anomaly) / upgrades / effects`
- 本轮以后至少要能在文档中明确追踪这些公式或等价规则：
  - `expToNext(level)`
  - 品质随阶段/深度变化的权重公式
  - `upgradeValueScore`
  - `routeSpecialEligible(rarity) = rarity >= uncommon`
  - `upgradeOfferAllowed(sourceId) = sourceId not in pickedUpgradeIds`
  - 生存关持续时间与阶段增长公式
  - 生存关最后 `10s` 的压力增长公式
  - 精英怪的生存与护卫压制规则

## 七、当前实现的重点偏离检查项
- `NodeType` 当前仍可能只有 `battle / upgrade / event`，需要检查是否已经偏离 `boss / battle / upgrade / anomaly` 口径。
- 最终战当前可能仍被实现为 battle 模板，而不是玩家可感知的独立 Boss 关定义。
- 当前异常关若只是晚期 rare event，仍不等于“异常关卡”设计口径。
- 当前强化池里若仍有大量 `repeatable: true`，则与“每个强化单局只选一次”的设计口径冲突。
- 当前三流派特殊强化如果仍能从白 `common` 里出现，则与“特殊强化从绿开始”的设计口径冲突。
- 当前品质概率与价值公式若各自独立但没有建立可追踪关系，也需要记录为待对齐项。
- 当前普通敌人如果仍主要只有 `regular / escort / elite` 角色区分，而没有四类基础小怪族群，也需要记录为待对齐项。
- 当前远程怪如果尚未形成明确独立敌种，也需要优先记录。
- 当前精英行为如果只是在通用追击/拉扯层面近似，而没有稳定体现“反向移动 + 小怪挡前”的读数，也需要标记为偏离点。
