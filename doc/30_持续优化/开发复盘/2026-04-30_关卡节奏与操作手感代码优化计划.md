# 2026-04-30 关卡节奏与操作手感代码优化计划

## 本轮判断

Boss 安全窗已经签收，作品集 Boss 案例页也已完成一轮整理。但当前用户明确要求先回到代码性开发，不继续推进作品集材料。

因此下一轮应回到游戏本体，把优先级放在：

- 关卡/节点节奏。
- 普通战回报链。
- 操作手感。
- 中段路线站稳。
- 后段收束感。

## 本轮目标

让当前版本更好玩，而不是更会展示。

具体目标：

- 第一轮更容易读懂并进入“击杀 -> 掉落 -> 拾取 -> 继续追击”的循环。
- 第二轮更像路线站稳点。
- 第三轮更像收束，而不是普通战拉长。
- 移动、反向、拾取吸附、击杀后继续追击更顺。
- 不破坏 `crit / pierce / dash` 的现有差异。

## 推荐开发落点

### 1. 关卡 / 节点节奏

优先查看：

- `src/data/nodes.ts`
- `src/data/contentSelectors.ts`
- `src/data/battleTemplates.ts`

建议方向：

- 第二轮提高“桥接/站稳”类节点或内容的稳定性。
- 第三轮减少过于前段化的内容，强化收束压力。
- 最终整备只补拼图，不开新方向。

### 2. 成长 / 升级承接

优先查看：

- `src/data/upgrades.ts`
- `src/data/contentSelectors.ts`
- `src/systems/RunEngine.ts`

建议方向：

- 前段给方向，不给完成度。
- 中段给站稳，不给碾压。
- 后段给收尾，不继续发泛用稳定器。
- 升级选择更像回应上一场战斗。

### 3. 操作 / 战斗手感

优先查看：

- `src/scenes/GameScene.ts`
- `src/data/balance.ts`
- `src/systems/RunEngine.ts`

建议方向：

- 微调移动起停和反向响应。
- 微调拾取吸附范围或吸附速度。
- 微调击杀后继续追击的反馈或节奏窗口。
- 不用大幅数值增强掩盖手感问题。

## 验收标准

必须验证：

- `npm run build`
- 一次 full-flow
- 一次 3~5 分钟自然样本
- 如改移动/拾取/战斗节奏，至少人工观察一次前 2 分钟普通战
- 如改节点/成长分发，至少说明第二轮和第三轮差异是否更清楚

观察重点：

- 普通战是否更容易一拍接一拍。
- 第二轮是否更像路线站稳。
- 第三轮是否更像收束。
- 操作是否更顺，但没有变成无脑碾压。
- Boss / 精英 / 三路线没有明显回退。

## 本轮不做

- 不新增 Boss。
- 不新增精英。
- 不新增路线。
- 不重写 `RunEngine`。
- 不重开主流程。
- 不继续作品集材料整理。
- 不大幅提高玩家数值。
- 不用 UI 文案代替战斗读感。
