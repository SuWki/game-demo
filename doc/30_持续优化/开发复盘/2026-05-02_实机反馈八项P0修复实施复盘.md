# 实机反馈八项 P0 修复实施复盘

## 基本信息

- 日期：`2026-05-02`
- 主题：实机反馈八项 P0 修复实施
- 负责人：Kimi
- 对应阶段：`1.0 第一阶段：核心玩法可玩性与体验闭环打磨`

## 改动前判断

根据用户提供的 8 项 P0 实机反馈和代码审查，本轮需要处理：

1. **流派牌出现过频**：`rollLevelUpChoices` 中 `routeWindowPool` 权重过高
2. **升级面板出现两个路线牌**：`rollLevelUpChoices` 返回前未做路线牌数量兜底
3. **节点面板出现两个强化关卡**：`pickWeightedUniqueBlueprints` 未排除已选的 `upgrade` 类型
4. **玩家周围绿色横线**：`GameScene` 中 dash 路线的视觉反馈绘制
5. **穿透路线超模**：`pierce` 卡片 `projectileSpeed` 过高、starter 权重过高、混入非核心属性
6. **Boss 压力不足**：安全区过大、区外伤害过低
7. **专属名词缺少解释**：路线 starter 描述过于技术化
8. **卡死 bug**：`gainExperience` 可能因 `Infinity` XP 进入无限循环

## 实际修改

### 代码

#### `src/data/contentSelectors.ts`

**修复升级面板出现两个路线牌**：
- 新增 `limitRouteCardsInUpgradeChoices` 辅助函数
- 在 `rollLevelUpChoices` 返回前调用，确保最多 1 张路线卡
- 超出部分用 generic fallback 替换或删除

**降低流派牌出现概率**：
- `routeWindowPool` 权重倍率下调：
  - `hasCommittedRoute`: 0.9 → 0.82
  - `dominantRoute` earlyMid: 1.28 → 0.92
  - `dominantRoute` otherwise: 0.88 → 0.78
  - `openingLevelUp` no dominant: 1.34 → 0.88
  - `earlyMidLevelUp` no dominant: 0.98 → 0.82
  - otherwise: 0.72 → 0.68
- `genericSecondaryPool` 权重倍率小幅上调，恢复普通强化性价比

#### `src/data/nodes.ts`

**修复节点面板出现两个强化关卡**：
- 修改 `pickWeightedUniqueBlueprints` 跟踪 `upgradePicked` 和 `anomalyPicked`
- 已选 `upgrade` 的节点不再选第二个 `upgrade`
- 已选 `anomaly` 的节点不再选第二个 `anomaly`
- 当 `eligiblePool` 为空时回退到 `battlePool`

**降低强化/异常节点出现概率**：
- `upgrade` 权重倍率：0.78 → 0.55
- `anomaly` 权重公式收紧：
  - round <= 3: `0.14 + round*0.06` → `0.08 + round*0.04`
  - round > 3: `min(0.46, ...)` → `min(0.36, ...)`

#### `src/scenes/GameScene.ts`

**移除玩家周围绿色横线**：
- 删除 `renderRouteFeedbackTexts` 调用（浮动文字反馈）
- 删除 dash 路线窗口标记绘制（2 条线 + 1 三角形）
- 删除 dash 路径轨迹线绘制（1 中心线 + 2 侧边线 + 2 三角形）
