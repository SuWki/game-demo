# 2026-04-22 UI / 美术 / 音频实际落地优化

## 本轮目标

- 在不重写主流程、不重开系统的前提下，把开始页 / 局内 / 结算页收成同一套战术终端语言。
- 继续清理局内仍像测试占位的 UI / 画面元素，让节点、强化、异常、整备页更像同一套系统。
- 延续上一轮的战斗表现和音频补强，再把 `dash` 的视觉 / 音频存在感往前推一步。

## 实际改了哪些表现内容

### 代码文件

- `src/scenes/MainMenuScene.ts`
- `src/scenes/ResultScene.ts`
- `src/scenes/GameScene.ts`
- `src/ui/OverlayController.ts`
- `src/systems/PilotAudio.ts`
- `src/style.css`
- `src/systems/MetaProgression.ts`
- `src/game/types.ts`

### UI / 页面

- 菜单页补了摘要卡、路线卡和更完整的主次按钮区。
- 结算页补了构筑摘要、收尾判断和关键节点回看，结果页不再只是标题加按钮。
- HUD 追加了阶段 / 节点锚点、战斗状态短句和路线状态短句。
- 节点 / 强化 / 异常 / 整备页统一成同一套 `标题 + progress summary + phase track + choice grid` 结构。

### 画面 / 美术

- 延续上一轮的敌我轮廓、弹道、XP 球和安全窗收口。
- 本轮在 `GameScene.ts` 再补了 `dash` 的前推三角、双轨尾迹和冲刺轨迹，让它在移动战斗里更容易被一眼认出来。

### 音效 / 音频

- 沿现有 `routeFocus / encounter / intensity` 上下文继续补强，没有新增复杂系统。
- `dash` 在 `shoot` 与 `dash` cue 里都增加了更明显的低频起冲和次级尖啸，让它不再只像普通 `shoot / hit` 的副本。

## 为什么先改这些

- 当前最影响玩家观感的不是缺少更多新内容，而是页面、战斗、结果页之间的完成度不一致。
- 只要开始页 / HUD / 结算页的锚点统一起来，节点类面板的信息结构统一起来，当前版本就会明显更像“完整可玩的短局战斗版本”。
- 在路线差异里，`crit / pierce` 已经有一定辨识度，最值得继续补的是 `dash`。

## 哪些问题被改善了

- 开始页 / 局内 / 结算页现在更像一套完整产品，而不是三块分开的原型页。
- 节点 / 强化 / 异常 / 整备页在切换时不再只剩卡片内容不同，头部信息结构也开始统一。
- 结果页从“空”和“散”收成了“有过程、有结论、有重开推动力”的状态。
- `dash` 的视觉和音频都比之前更容易被识别出来。

## 哪些仍然只是临时状态

- 菜单和结果页当前用的仍是程序化壳体，不是最终商业包装。
- `dash` 虽已补强，但持续记忆点仍弱于 `crit / pierce`。
- 精英 / Boss 的自动定向验证脚本仍然不够稳，当前更多是在确认没有明显回退，而不是已完成彻底签收。

## 如何验证

- `npm run build`
- `node output/playwright/battle-feel-pass/round20/full-flow.mjs`
- `node output/playwright/battle-feel-pass/round20/family-check.mjs`
- `node output/playwright/battle-feel-pass/round20/elite-quick-check.mjs`
- `node output/playwright/battle-feel-pass/round20/elite-targeted-check-fixed.mjs`

### 本轮观察结论

- full-flow 通过，`resultSeen = true`，`consoleErrors = []`。
- family-check 通过，普通战没有因为本轮页面与表现收口而回退。
- 菜单截图、节点截图、结果页截图都能看出统一壳体、摘要区和按钮语言已经成型。
- `audio-polish-check` 的既有样本仍能读到 `shoot / hit / kill / pickup` 主回报链，以及 `hurt / nearMiss / pressure` 的分层。
- elite quick check 仍未稳定命中 elite；targeted check 路径能跑通，但自然样本脚本稳定性仍是当前验证缺口。

## 下一步建议

1. 继续补 `dash` 的持续视觉 / 音频签名，让它和 `crit / pierce` 的差异更稳。
2. 优先补精英 / Boss 的自动验证样本稳定性，再决定是否继续加表现。
3. 如果继续做 UI / 页面，不要开新结构，优先继续收菜单 / 结果页的最终文案和 route card 内容。
