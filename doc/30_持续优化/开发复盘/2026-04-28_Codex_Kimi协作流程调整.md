# 2026-04-28 Codex / Kimi 协作流程调整

## 本轮目标

把后续开发分工从“Codex 直接规划并开发”调整为“Codex 负责规划与文档，Kimi 负责代码落地”，并把这条规则写入项目文档。

## 实际修改

- 更新 `doc/30_持续优化/文档维护规则.md`，补充 Codex / Kimi 分工、每轮职责和提示词交接原则。
- 更新 `doc/40_AI协作/AI接手协议.md`，明确当前默认协作模式为 Codex 规划、Kimi 开发。
- 新增 `doc/40_AI协作/Codex_Kimi协作分工规则.md`，作为后续协作的专门规则入口。
- 更新 `doc/00_接手入口/当前交接卡.md`，把新分工加入当前真相。

## 新协作规则

- Codex 默认不直接修改 `src/` 代码。
- Codex 负责方向、设计、素材/音效草案、文档、验收标准、Kimi 提示词。
- Kimi 负责代码实现、构建、QA、必要文档同步和代码提交。
- 如果用户明确要求 Codex 直接写代码，必须在该轮开始前重新确认范围。

## 为什么这么调整

当前项目已经进入“持续体验优化 + 素材音效逐步替换 + 作品集同步整理”的阶段。Codex 更适合承担方向判断、文档结构、设计闭环和提示词拆解；Kimi 用于执行具体代码开发，可以让流程更清晰，也能减少同一轮里方向、代码和文档互相抢上下文的问题。

## 后续流程

1. 用户提出下一步体验目标或问题。
2. Codex 先看当前文档，整理方向和优先级。
3. Codex 更新必要 docs，并给出 Kimi 开发提示词。
4. Kimi 按提示词修改代码、运行验证并提交。
5. 用户把 Kimi 结果发回 Codex。
6. Codex 验收、补文档、决定下一轮。

## 验证

- 本轮只修改文档和协作规则，没有修改运行时代码。
- 不需要执行 `npm run build`。
- 已按规则准备提交本轮文档变更。

## 下一步建议

下一轮建议先让 Kimi 做“Boss/精英自然样本复检与安全窗提示补强”或“素材/音效 A/B 接线复检”，Codex 先给出明确提示词，不直接动代码。
