# 2026-05-05 路线牌价值修复与生命上限回血修复

## 修复内容

### 问题 #1: 路线牌价值过高
**问题描述**: 
- 路线牌除了给路线进度，还额外给了属性加成（critChance, pierce, dashPulseDamage等）
- 导致路线牌价值远超其他属性强化牌
- 例如：`crit-aim` 给 critChance: 0.05 + critMultiplier: 0.15 + 路线进度

**修复方案**: 
- 移除所有64张路线牌的stats effect
- 只保留route effect（路线进度）
- 使用自动化脚本批量修复

**修复结果**:
- 成功修复58张路线牌（脚本报告）
- 实际应该是64张，需要确认剩余6张
- 构建通过：`npm run build` ✅
- 路线审计通过：硬违规 0，超预算 0，健康度 100% ✅

**修复前示例** (`crit-aim`):
```typescript
effects: [
  {
    type: 'stats',
    modifiers: {
      critChance: 0.05,
      critMultiplier: 0.15,
    },
  },
  {
    type: 'route',
    routeId: 'crit',
  },
]
```

**修复后示例** (`crit-aim`):
```typescript
effects: [
  {
    type: 'route',
    routeId: 'crit',
  },
]
```

### 问题 #2: 生命上限不回血
**问题描述**: 
- 拿了加生命上限的牌后，当前血量不变
- 例如：110/110 → 拿+26生命上限 → 110/136（无用强化）
- 应该是：110/110 → 拿+26生命上限 → 136/136

**修复方案**: 
- 修改 `RunEngine.ts` 的 `applyModifiers` 方法
- 加生命上限时同时回复相同数值的血量

**修复代码**:
```typescript
private applyModifiers(modifiers: Partial<PlayerStats>): void {
  const maxHpGain = modifiers.maxHp ?? 0;
  this.state.stats.maxHp += maxHpGain;
  // 加生命上限时同时回复相同数值的血量
  if (maxHpGain > 0) {
    this.state.stats.hp = clamp(this.state.stats.hp + maxHpGain, 0, this.state.stats.maxHp);
  } else {
    this.state.stats.hp = clamp(this.state.stats.hp, 0, this.state.stats.maxHp);
  }
  // ... 其他属性
}
```

**修复位置**: 
- 文件：`src/systems/RunEngine.ts`
- 行号：2346-2348

## 影响评估

### 正面影响
1. **路线牌价值合理化**: 路线牌不再因为额外属性而过强
2. **三路线平衡改善**: 移除属性加成后，路线强度更依赖机制而非数值堆叠
3. **生命上限牌可用**: 加生命上限不再是"无用强化"

### 可能的负面影响
1. **路线成型变慢**: 路线牌不再给属性加成，可能需要更多牌才能感到变强
2. **前期偏弱**: 失去了路线牌的属性加成，前期可能更依赖通用牌
3. **需要重新平衡**: 可能需要调整路线机制的强度来补偿属性损失

### 缓解方案
- Week 1实机测试时重点观察路线成型时间
- 如果路线成型过慢，考虑：
  - 增强11张关键牌的机制效果
  - 调整路线进度阈值
  - 增加通用牌的属性加成
