# 2026-04-26 全链路游玩体验补强

## 本轮目标

本轮目标不是继续扩 `dash` 内容池，也不是新增系统，而是把当前已经跑通的短局射击循环打磨得更顺、更清楚、更像可玩的版本。

重点覆盖：

- 清理玩家可见乱码和难懂提示。
- 小步补强移动、反向转向、停手、拾取吸附和拾取后续开火。
- 拉开 `shoot / hit / kill / pickup` 与 `hurt / nearMiss / pressure / enemyShot` 的音效层级。
- 让开始页、节点/升级页和结算页文案更通俗。

## 实际改了哪些代码文件

- `src/systems/RunEngine.ts`
- `src/systems/PilotAudio.ts`
- `src/scenes/GameScene.ts`
- `src/ui/OverlayController.ts`
- `src/style.css`

## 改善了哪些操控手感

- 移动起步窗口从 `0.18s` 小幅提高到 `0.2s`，起步 pulse 稍微更明显，减少刚按方向时的拖感。
- 反向转向触发阈值从更严格的反向改为更容易触发的回切窗口，并把 turn burst 从 `0.14s` 提到 `0.16s`。
- 输入速度插值略提高，停手阻尼略加重，目标是让“起步更快、松手更干净、反向更清楚”。
- 拾取后的 follow-through 时间、吸附半径、吸附拉力和拾取后射击冷却回补都做了小幅增强，让 `kill -> pickup -> continue firing` 更容易接上。

## 改善了哪些打击手感

- `hit` 音色更短促、更硬，作为命中确认不再和 `shoot` 糊在一起。
- `kill` 比 `hit` 多一点兑现感，但仍低于 `hurt / pressure` 的危险优先级。
- `pickup` 更轻快、更短，和升级/续射节奏连接更自然。
- 拾取吸附的场内 pulse 和后续目标提示略增强，XP 回收更像奖励链，而不是单点闪烁。

## 改善了哪些音效反馈

- `shoot` 降低抢戏程度，保留自动开火节奏底噪。
- `hit`、`kill`、`pickup` 拉开响度和时长差异。
- `enemyShot`、`nearMiss`、`pressure`、`hurt` 的 duck 和峰值优先级提高，确保危险语义压过爽感音效。
- 沿现有 cue profile 调整，没有新增复杂音频系统，也没有引入新资产。

## 改善了哪些玩家提示 / 文案

- 修复 `RunEngine.ts` 中精英裂口玩家可见乱码，替换为短句中文：
  - `裂口出现，穿过火线`
  - `精英裂口打开，贴近反打`
  - `安全窗打开，追回一拍`
  - `精英裂口打开，追击本体`
- `GameScene.ts` 同步更新强制 toast 条件，确保新裂口短句不会被过滤掉。
- 开始页从英文短句改为“移动躲弹，自动开火 / 打倒敌人，拾取能量，撑到 Boss”。
- 节点、升级和结算页的 eyebrow / button small / debrief 文案改为更直接的中文短句。
- toast 文本增加最大宽度和行高，避免短提示在宽屏中过散。

## 如何验证

- `npm run build`：通过。
- 乱码扫描：无 `src` 命中；剩余命中仅是文档里的扫描命令示例。
- 辅助 full-flow：用 Playwright + debug `timeScale=2 / invulnerablePlayer=true` 覆盖菜单、战斗、升级、节点、异常、最终整备、Boss、结算，无 console error。
- 180 秒自然样本：非无敌，自动重开观察普通战，4 次结算、36 次选择，无 console error。
- 定向精英样本：`elite-screen` 样本出现 `eliteCrackSeen=true`、`eliteCrackFollowThroughMoments=2`。
- 定向 Boss 火线样本：`boss-bastion` 样本出现 `bossFirelineCoverage=1`、`bossSafeWindowMoments=94`，火线和安全窗可视。

## 结论

- 玩家可见乱码已清理。
- 普通战手感更顺，尤其是起步、转向、停手和拾取回收。
- 命中、击杀、拾取和危险音效的层级更清楚。
- 开始页和结算页不再主要依赖英文占位，玩家一眼更容易知道“怎么打、为什么再来”。
- `crit / pierce / dash` 的基础差异没有被本轮手感调优抹平：本轮没有改路线内容池，也没有继续强化 `dash`。

## 仍然只是临时状态

- 这轮音频仍是程序合成 cue，没有正式音频资产替换。
- 自动化验证无法真实“听见”混音，只能结合代码层级、duck 逻辑和实机视觉样本判断；后续仍需要人工听感复检。
- 自然样本仍容易在第 2~3 节点被打断，说明普通玩家的中段稳定性仍是后续重点。

## 下一步建议

- 不要马上扩内容池；优先继续观察自然样本里玩家是否能稳定进中后段。
- 如果普通战仍频繁早死，优先小步检查敌弹压力、拾取节奏和节点前回血，而不是直接堆玩家移速。
- 后续音频若接正式资产，必须先守住 `hurt / nearMiss / pressure / enemyShot` 的危险优先级。
