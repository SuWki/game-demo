# 2026-05-15 P0/P1 体验收口与玩家可见信息清理

## 本轮目标

解决当前 P0/P1 中最影响第一印象的问题：游戏内残留设计语、调试/占位表达、玩家周围无意义路线线条和路线圆环，让当前版本更像可玩的原型，而不是开发调试版。

## 用户问题与解决方案

1. 玩家可见文案仍有 `推进 / 阶段 / 构筑 / 回切 / 承接 / 主路线` 等设计性语言。
   - 解决方案：清理 `OverlayController.ts`、`GameScene.ts`、`RunEngine.ts`、`upgrades.ts`、`events.ts`、`battleTemplates.ts`、`nodes.ts` 中的玩家可见文本。
   - 当前状态：已改为更直接的玩家语言，例如 `继续前进`、`某某流 +1`、`本局暂未记录`。

2. 结果详情和部分 UI 像调试版。
   - 解决方案：结果详情不再写 `功能开发中`，改为说明本局暂未记录对应数据；节点/强化说明不再使用流程解释句。
   - 当前状态：已完成。

3. 玩家周围仍可能出现路线线条、圆环、冷却条或无意义路线素材。
   - 解决方案：删除玩家路线充能环、穿梭冷却条、路线弹道额外圆环素材叠加，并清掉横向车道残留注释块，避免后续误恢复。
   - 当前状态：已完成代码层清理，仍需实机确认是否还有残留。

4. 后续 Codex/Kimi 容易只汇报“做了什么”，没有逐条回应用户问题。
   - 解决方案：更新 `Codex_Kimi协作分工规则.md`，要求最终汇报必须逐条回应“用户原问题 / 解决方案 / 当前状态 / 仍需验收点”。
   - 当前状态：已写入规则。

## 为什么先改这些

这些问题不会改变核心玩法，但会直接影响新玩家和面试官的第一判断。内部设计语、占位语和玩家身上的无意义线条会让项目显得像调试版，也会干扰玩家理解三条流派到底在战斗中发生了什么。

## 验收方式

- `npm run build`
- `node tools/audit-route-upgrade-value.mjs`
- `node tools/qa-current-version.mjs`
- `PILOT_QA_BOSS=boss-bastion node tools/qa-boss-directed-v2.mjs`
- 人工实机重点看：角色周围是否还有路线线条/圆环，升级/节点/结算页是否还出现设计语，`crit / pierce / dash` 的受击层反馈是否仍可读。

## 自动验证结果

## 仍需人工确认

- 自动 QA 无法判断“是否像人话”“是否刺眼”“是否干净”。这轮必须由玩家实机确认视觉残留是否真的消失。
- 如果清理后路线辨识度下降，下一轮只允许增强敌人受击层和音效，不恢复玩家周围常驻线条。
