# 2026-05-07 背景素材修正与运行时接入

## 本轮目标

检查 `docs/background-generation-prompts.md` 是否符合当前项目，并在有问题时修正文档，再生成一组与现有项目风格一致、可直接运行时接入的背景素材。

## 发现的问题

原文档更适合通用 AI 出图工具，不适合直接用于当前版本：

1. 提示词强调 `4K / PBR / cinematic lighting / high contrast`，容易抢走弹幕、安全区、XP 球和敌人轮廓的可读性。
2. 文档倾向生成大型 PNG 位图，但当前项目的预览素材管线主要是 SVG，并且之前已经多次遇到黑底问题。
3. 路线色映射与当前项目不一致。当前项目应保持 `crit` 橙金、`pierce` 蓝青、`dash` 绿青，而不是把 `crit` 写成红色、`dash` 写成橙色。
4. 文档中粒子、光束、扫描线等内容太容易变成全屏遮罩，应谨慎后置。

## 实际修改

### 文档

在 `docs/background-generation-prompts.md` 顶部新增“Codex 落地修正版”，明确：

- 当前背景资产优先 SVG / 透明 PNG。
- 背景只做低干扰氛围层，不解释玩法。
- Boss 危险色不能遮挡安全区。
- 后续生成背景素材前必须先检查读局、透明叠加和色彩一致性。

### 素材

新增 6 个 SVG 背景资产：

- `public/assets/preview-runtime/visual/bg-space-nebula.svg`
- `public/assets/preview-runtime/visual/bg-floor-hex-tile.svg`
- `public/assets/preview-runtime/visual/bg-floor-holo-tile.svg`

这些素材均按低对比、低透明、无黑底装饰层设计。

### 代码

- `src/scenes/BootScene.ts`：预加载 6 个背景 SVG。
- `src/scenes/GameScene.ts`：扩展运行时预览图片 helper，使其支持非正方形显示和自定义层级；在战斗地形层接入星云、地面贴片、碎片贴花；在 Boss 战接入危险 / 核心氛围层。

## 为什么这么设计

当前游戏最重要的是战斗读局，而不是背景细节。背景资源必须给场景“托底”，不能变成玩家误判敌弹、安全区、XP 球和路线命中特效的原因。

因此本轮没有照文档生成完整 4K 背景图，也没有接入强扫描线、强光束、全屏红层，而是选择了可控的 SVG 低透明层。这样后续如果觉得太亮或太脏，可以直接在代码里降透明度或减少贴片出现频率。

## 验证

- `npm run build`：通过。
- `node tools/qa-current-version.mjs`：通过，`consoleErrors=[]`，`resultSeen=true`。

## 复查修正

用户实机反馈“背景没有修改，还是之前的样式”。复查后确认不是素材缺失，而是渲染层级问题：

- 背景 SVG 被放在较低 depth。
- 主 `Graphics` 同时负责地形和战斗实体，并在较高 depth 画了深色底层。
- 因此背景素材虽然加载成功，但实际被整块盖住。

修正方式：

- 新增独立 `terrainGraphics`，专门绘制地形底色和程序化地面。
- 背景 SVG / 地面贴片 / Boss 氛围层放在 `terrainGraphics` 上方、主战斗 `graphics` 下方。
- 主战斗层继续负责玩家、敌人、弹幕和 UI 辅助反馈，避免背景压住读局信息。

复查截图：`output/qa/current-version/background-check.png` 已确认战斗中能看到六边形地板、星云层和碎片贴花。

## 仍需人工实机确认

1. 背景是否增加场景感，而不是增加视觉噪音。
2. Boss 背景是否有压迫感，但不遮挡安全区。
3. 地面贴片是否会被误认为敌弹、XP 或路线特效。
4. 如出现遮挡，优先降低透明度和贴片频率，不修改战斗主逻辑。

## 下一步建议

如果本轮背景实机观感通过，下一步再考虑少量环境动画或更细的 Boss 场景差异；如果不通过，先回调背景透明度、出现频率和 Boss 氛围层强度，不继续补大图。
