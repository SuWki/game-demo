# 2026-04-24 内容密度与分发权重小步补强

## 本轮目标

- 不重写 `RunEngine`、不新增系统，只在 `nodes / upgrades / events` 上做一轮小批量高收益补丁。
- 提高 `crit / pierce / dash` 三条路线在开局选择、中段承接和后段收束上的分化度。
- 检查前中后期内容分布，减少明显重复和节奏断档，优先修补 `dash` 在中段“不像一条完整路线”的问题。

## 实际改了哪些表现内容

### 1. 节点分发

- 新增 `round-2-battle-dash-cutback`
  - 用 `elite-lockdown / elite-vice / elite-screen` 组合出一张明确偏 `dash` 的中段战斗节点。
  - 目的不是加新系统，而是补齐中段“换边 -> 回切 -> 借窗反打”的战斗语义锚点。

- 调整 `round-2-battle-screen`
  - 提高 `dash` 路线加权，让 dash 中段更容易遇到需要换边处理的护卫压线战。

- 调整 `round-2-battle-vice`
  - 提高出现率，避免中段精英层只剩一两种更常见模板在轮换，增强 `pierce` 路线的拆屏/裂口体感稳定性。

- 调整 `round-2-upgrade-bridge / round-2-upgrade-turn`
  - 给 `dash` 补上路线加权，减少中段节点对 `dash` 的承接偏弱问题。

- 调整 `round-3-battle / round-3-battle-crossfire`
  - 略微压低通用后段生存战权重，抬高 `crossfire` 权重和 `dash` 倾向，减少后段重复撞通用生存战导致的节奏发平。

### 2. 升级分发

- 新增 `dash-lanebreak`
  - 类型：`starter`
  - 作用：把 `dash` 的 starter 数量从 2 补到 3，让开局更容易读到 “移速 / 换边 / 反打” 这条路线。

- 调整 `dash-phasebank`
  - 提高基础权重，增强 `dash` 在中段拿到第一张明确承接牌的概率。

- 调整 `dash-slipstream`
  - 提高基础权重，增强 `dash` 在 starter 之后继续锁路线的稳定性。

## 3. 异常分发

- 新增 `dash-sidewake-memory`
  - 类型：`hybrid anomaly`
  - 位置：中后段 `dash` 路线异常池
  - 设计意图：补一个“压实回切窗口 / 留宽喘息拍”的明确分叉，让 `dash` 的异常不只停留在泛移动强化，而是开始围绕路线节奏本身做选择。

## 为什么先改这些

- `crit` 和 `pierce` 在现有内容表里已经有比较完整的“开局 starter -> 中段节点锚点 -> 后段 closeout”骨架。
- `dash` 并不是完全没内容，而是最缺“中段像路线”的承接点，导致玩家前两轮即便开始偏 `dash`，也更容易在节点与异常上被拉回泛 build。
- 后段重复感主要不是“内容总量不够”，而是通用战节点权重偏高，导致某些 route-specific 模板出得不够稳定。
- 所以这轮优先补的是“关键缺口”和“分发权重”，不是继续往表里堆大量新条目。

## 哪些问题被改善了

- `dash` 开局更容易和 `crit / pierce` 分开：
  - starter 数量补平后，不再明显比另外两条路线少一个开局锚点。

- `dash` 中段承接更清楚：
  - 新增中段专属战斗节点后，路线不再主要依赖升级牌自己讲故事，节点层也开始给它明确战斗语义。

- `pierce / dash` 的中后段差异更稳定：
  - `pierce` 继续偏拆屏、裂口、清线回收。
  - `dash` 更偏换边、借窗、回切反打。

- 后段重复略有下降：
  - 通用生存战权重下调后，`crossfire` 这类更有路线识别度的后段节点更容易出现。

## 哪些仍然只是临时状态

- 这轮仍然是数据驱动补丁，不是完整内容扩容。
- `dash` 虽然比之前更完整，但后段 payoff 的实际“爽点兑现”仍然偏依赖战斗内手感与读局，不如 `crit / pierce` 那么直观。
- 异常池整体仍然偏“同一语言的不同变体”，后续还需要再做一轮更谨慎的差异化清理，避免只是在词面上换皮。

## 如何验证

- 构建验证：`npm run build` 通过。
- 静态分布复核：
  - `dash` starter 数量由 2 提升到 3，与 `pierce` 拉平。
  - 中段 battle 节点中新增了明确的 `round-2-battle-dash-cutback`。
  - `dash-sidewake-memory` 已进入异常池，形成新的中后段 route-specific 分叉。

## 下一步建议

1. 做一轮轻量 smoke，观察 `dash` 在 round 2 前后是否更稳定拿到“战斗节点 + 升级承接 + 异常分叉”组合。
2. 如果 `dash` 仍然偏弱，下一轮优先补的是 payoff 呈现，不是继续堆 starter。
3. 如果后段仍然重复，优先再调节点权重与模板露出率，不要先扩大量新模板。
