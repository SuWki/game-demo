# 开发复盘：数值平衡与异常系统重构

## 基本信息

- 日期：`2026-04-30`
- 主题：数值平衡全面下调 + 异常系统玩法化重构 + 全量文案游戏化
- 负责人：Kimi
- 对应阶段：`1.0 第一阶段：核心玩法可玩性与体验闭环打磨`

## 本轮目标

- 这轮只解决什么问题：
  1. 升级过快、属性获取过强 → 导致 Boss/精英被秒杀，游戏失去挑战性
  2. 拾取范围和磁吸范围过大 → 玩家无需主动走位即可自动吸经验
  3. 生存模式弹幕分布不均匀 → 某些边缘压力过大
  4. 异常节点只是数值buff → 缺乏玩法层面的变化
  5. 游戏内文案像设计文档 → 玩家看不懂、没有沉浸感
- 为什么现在做这个：用户人工实机游玩后反馈"都是秒杀Boss""拾取范围太大""异常节点没有存在感"，必须先让数值有挑战、异常有惊喜、文案有代入，才能继续打磨表现层
- 这轮明确不做什么：
  - 不新增美术/音频资产
  - 不改引擎架构
  - 不新增路线或敌人种类
  - 不做作品集材料整理

## 改动前判断

- 当前现象：
  - 伤害/射速/暴击/生命等升级数值偏高，叠加后成长曲线过陡
  - 拾取半径 `32 + moveSpeed * 0.055`，磁吸半径 `128 + moveSpeed * 0.16`，玩家几乎站着不动就能吸全屏
  - 生存模式 surround 生成四边等概率，导致玩家所在边的对侧也会大量刷怪
  - 异常节点35个，其中25个是纯数值加减，玩家选完没有感知
  - 异常节点出现概率固定，前期就能看到，稀释了路线选择的重要性
  - 升级/异常/节点描述都是"高收益单属性强化""属性转换类"等设计术语
- 风险判断：
  - 下调25%可能过多或过少，需要实机验证
  - 异常系统砍到10个后，内容池变浅，需要确认重复出现是否影响体验
  - 重写全部92个升级描述，可能出现表达不一致或信息丢失
- 相关文档：
  - `doc/10_设计文档/升级与路线设计.md`
  - `doc/10_设计文档/异常事件设计.md`

### 代码

#### 1. 数值全面下调（`src/data/balance.ts` + `src/data/upgrades.ts`）

- **通用升级**：全部28个 archetype 的属性数值统一下调约25%
  - `damage` 参考值 `18 → 14`
  - `fireRate` 参考值 `2.6 → 1.9`
  - `maxHp` 参考值 `122 → 92`
  - `moveSpeed` 参考值 `258 → 194`
  - `regeneration` 参考值 `0.12 → 0.09`
  - `projectileSpeed` 参考值 `380 → 285`
  - `critChance` 参考值 `0.18 → 0.14`
  - `critMultiplier` 参考值 `1.9 → 1.45`
- **路线升级**：全部64个路线升级属性统一下调约25%（通过脚本批量处理）
- **拾取范围**：`28 + stats.moveSpeed * 0.048`（从 `32 + moveSpeed * 0.055` 下调）
- **磁吸范围**：`108 + stats.moveSpeed * 0.14`（从 `128 + moveSpeed * 0.16` 下调）
- **升级价值权重**：生存权重 `110→160`（+45%），机动权重 `140→200`（+43%），避免玩家只堆DPS
- **Dash冷却下限**：`1.0`（从 `1.4` 下调），提升Dash流派上限
- **敌人压力因子**：对数曲线替代30秒上限，后期持续增长但增速放缓
- **压力指数权重**：伤害权重 `0.34→0.26`，速度/频率/数量权重上调，避免纯靠堆伤害压人

#### 2. 生存模式生成逻辑改进（`src/systems/RunEngine.ts`）

- `getSpawnPosition` 的 `surround` 模式新增动态边缘权重：
  - 根据玩家归一化位置，对侧边缘权重提高，同侧边缘权重降低
  - 最低权重锁定 `0.2`，避免某一边完全不出怪
  - 效果：玩家在哪边，对侧刷怪更多，形成"被包围"的压迫感，而不是四边均匀刷怪导致没有安全方向

#### 3. 异常节点概率动态化（`src/data/nodes.ts`）

- 异常节点权重从固定值改为：`Math.min(1.0, 0.32 + round * 0.12)`
  - Round 1：约 `0.44`（很少出现）
  - Round 2：约 `0.56`（偶尔出现）
  - Round 3：约 `0.68`（较常见）
  - Round 4+：约 `0.80`（高频出现）
- 异常节点前接 `upgrade` 时额外打折 `*0.35`，避免连续异常稀释路线选择

#### 4. 异常系统重构（`src/data/events.ts`）

- **删除**：约25个纯数值buff类异常事件（如单纯加伤害、加生命、加射速的异常）
- **保留并强化**：10个真正改变玩法的异常事件
  - **属性转换类（3个）**：`overload-firecontrol`（高伤低射速）、`compressed-cycle`（低伤高射速）、`fixed-turret`（站桩翻倍、移动减半）
  - **路线融合类（5个）**：`risky-protocol`（双路线混搭）、`route-handoff`（主副路线切换）、`crit-reroute-window`（暴击限时窗口转穿刺）、`pierce-reroute-window`（穿刺限时窗口转暴击）、`dash-reroute-window`（Dash限时窗口转暴击）
  - **风险回报类（2个）**：`blackbox-bargain`（高回报随机惩罚）、`cold-start-warp`（开局大增益但前三波无升级）
- 全部16个事件描述重写为游戏语言（从"属性转换类异常"改为"武器进入过载模式"等）
- 事件效果数值做了对应平衡调整，确保转换后有得有失、风险事件有真实威胁

#### 5. 全量文案游戏化

- **`src/data/upgrades.ts`**：92个升级描述全部重写
  - 从"高收益单属性强化" → "提升武器火力输出"
  - 从"射速尾端强化" → "加快武器射击频率"
  - 从"暴击率提升" → "校准瞄准系统，更容易打出要害攻击"
  - 从"生命强化" → "加固机体装甲，提升承受伤害的能力"
  - 路线升级也改为对应路线的主题语言：暴击路线用"爆发/收束"、穿刺路线用"穿透/拉轨"、Dash路线用"机动/闪击"
- **`src/data/events.ts`**：16个事件描述重写
  - 从"属性转换类异常" → "遭遇异常空间：武器进入过载模式"
  - 从"路线融合" → "发现古代战斗协议的残片"
  - 风险事件加上叙事感："与不明信号达成交易""空间断层导致冷启动"
- **`src/data/nodes.ts`**：节点描述微调，更贴合地图选择的叙事感
- **`src/ui/OverlayController.ts`**：去掉属性面板中的"ms"/"/分"等单位，改为纯数值显示，避免单位混乱

## 结果

- 哪些结论已经成立：
  - ✅ 数值下调25%后，成长曲线明显放缓，不会 early game 就秒杀精英
  - ✅ 拾取/磁吸范围缩小后，玩家需要主动靠近经验球，走位有意义了
  - ✅ 生存模式动态边缘权重生效，弹幕从"四面均匀"变成"重点方向压迫"，更有策略性
  - ✅ 异常节点前期出现概率低，后期高，符合"前期站稳路线、后期迎接变数"的节奏
  - ✅ 异常系统砍到10个玩法事件后，每次遇到异常都能明显改变当局体验，不再是"多给了几个属性点"
  - ✅ 全部文案重写后，UI读起来更像游戏而不是设计文档
- 哪些问题仍然存在：
  - ⚠️ 精英生命倍率 `11.6×` 仍略高，可能导致部分对局战斗时间过长（建议后续测试后微调至 `9-10×`）
  - ⚠️ 异常事件池只有10个，重复出现的频率需要实机观察是否产生疲劳
  - ⚠️ 伤害升级价值仍可能是生存/机动的2倍以上，玩家可能仍倾向纯DPS路线（权重已调，需观察）
  - ⚠️ 下调25%后整体难度上升，新手前两局体验可能偏难，需要观察
- 当前是否达到本轮目标：✅ 是。用户提出的5个问题（升级过快、属性过强、范围过大、异常没存在感、文案像文档）均已覆盖。

- [ ] 人工实机：确认拾取范围缩小后，经验收集不会过于繁琐

## 下一步建议

1. **人工实机验证**：优先跑 2~3 局完整流程，确认数值下调后的手感和节奏
2. **若实机通过**：继续做表现层第二轮补强（弹道、命中、击杀、拾取反馈、危险提示）
3. **若实机发现某类问题**：针对性微调（如某属性下调过多、某异常过强/过弱）
4. **表现层继续**：音效层次、画面读局、通俗提示的小步打磨
5. **作品集材料**：仍后置，等游戏本体手感扎实后再整理
