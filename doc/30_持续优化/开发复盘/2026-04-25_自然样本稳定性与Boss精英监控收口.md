- 统一补齐 `BattleState / BattleDebugSnapshot / MetricsTracker` 的监控字段：
  - `lateDashWindowMoments`

  - `eliteCrackSeen`

  - `bossFirelineCoverage`
  - `bossSafeWindowMoments`

- 补了一个只服务验证的 debug 注入：
  - `window.__pilotDebug.setPressureState()`
  - 作用是把当前 battle 压到指定血线 / 剩余时间，用于定向复检 Boss 火线阶段。
- 这轮没有新增正式玩法系统，也没有继续扩 `dash starter / payoff / finisher`。

## 自然样本结论

- `npm run build`：通过。

- 抓到一局 `dash` 路线自然样本：
  - `dashCounterMoments = 6`
  - `lateDashWindowMoments = 0`
  - `eliteCrackSeen = true`
  - `eliteCrackFollowThroughMoments = 2`

### 更长的自然复检

- 3 轮更长自然样本里没有抽到 `dash` 主路线，`dashRuns = 0`。
- 这说明当前自然样本量还不足以证明“`lateDashWindowMoments` 已经稳定成为自然常态”。
- 但同一批样本里：
  - `eliteCrackRuns = 3`
  - `averageKillPickupContinueMoments = 18.33`
  - 每轮都能看到 `hurt / nearMiss / pressure / enemyShot`
- 结论是：目前没有证据显示上一轮 `dash` 补强把普通战回报链或危险语义层带偏。

## 精英裂口结论

- 定向精英裂口扫描复检了多个 elite 模板。
- 结果：
  - `elite-screen`：`eliteCrackSeen = true`，`eliteCrackFollowThroughMoments = 1`

  - 本轮新增监控能把这个过程抓出来，不再只能靠截图和体感判断。

## Boss 火线结论

- 第一次 Boss 样本复检里，阶段没有稳定推进，不是 Boss 结构变薄，而是脚本没处理中途升级面板，导致 `RunEngine.tick()` 暂停。
- 修正脚本后，用 `invulnerablePlayer + setPressureState()` 做定向火线复检，抓到：
  - `bossFirelineCoverage = 0.91`
  - `bossSafeWindowMoments = 5+`
  - `pressure = 7`
  - `enemyShot = 45`
  - `nearMiss = 59`
- 结论：
  - `boss-bastion` 火线阶段仍然稳，压迫覆盖和安全窗都还在。
  - 这轮没有把 `屏卫主核` 的火线阶段做薄。
