# 2026-04-29 Kimi 修复验收与下一轮体验计划

## 本轮目标

对 Kimi 提交的“体验问题修复与 Boss/精英机制补强”结果做设计侧判断，并给出下一轮开发计划。

这轮不是继续要求 Codex 改代码，而是按新的协作规则完成三件事：

- 判断 Kimi 本轮修复是否可以直接进入下一阶段。
- 明确下一轮应该先验收什么、再优化什么。
- 把计划同步到当前交接卡、当前待办和验收标准里，供 Kimi 下一轮接手。

## 对 Kimi 本轮结果的判断

Kimi 本轮方向基本正确，属于“小步修体验问题”，没有重写主流程，也没有把问题扩大成系统重构。

已经完成的有效改动包括：

- 开始页音量面板层级修复。
- Boss 弹幕密度下调，安全窗和停留时间增加。
- 精英 / Boss 横移和压力阶段机动性增强。
- 玩家、敌人、Boss 弹幕拖尾变短、变细、变透明。
- 属性显示公式复查，暴击率和暴击伤害不再使用裸倍率格式。

但这些结果仍然不能直接视为“玩家体验签收”，原因是：

- 有些问题被描述为“前序已修”或“代码逻辑已存在”，仍需实机确认玩家侧是否真的可用。
- Boss 弹幕降密后可能从“不可躲”变成“压力不足”，需要专项样本判断。
- 精英横移增强后可能解决木桩感，也可能带来贴脸压迫过强，需要自然样本观察。
- Boss / 精英机制差异目前更多来自数值和模板行为，下一步如果仍不够，需要补可读预警、弱点窗口或单点机制，而不是继续加血量。

## 下一轮优先级

### P0：体验修复验收

目标：确认 Kimi 本轮修复在玩家侧真的成立。

必须验收：

- 开始页音量面板是否可打开、可调节、可关闭。
- 战斗暂停后点击继续作战，暂停窗口是否隐藏，游戏状态是否同步。
- 玩家、敌人、Boss 子弹拖尾是否不再像硬线段残留。
- 素材透明背景是否没有黑底残留。
- 暴击率、暴击伤害、射速、冷却等属性是否全部以玩家可理解格式显示。
- Boss 弹幕是否有可观察安全窗，不能持续封死玩家移动。
- 精英是否有普通怪没有的行为差异，但不能让玩家被过度贴脸压迫。

### P1：Boss / 精英机制可读性小补

触发条件：P0 发现 Boss / 精英仍然像“血厚木桩”，或玩家仍然不知道何时躲、何时打。

推荐方向：

- Boss 增加阶段预警短句或视觉预警。
- Boss 在强攻击后给短暂弱点 / 反打窗口。
- Boss 安全窗用更清晰的视觉边界或音效提示表达。
- 精英只补一个清晰机制，例如护卫遮线、裂口蓄力、短冲锋、短暂硬直、召援间隔。
- 不直接加回弹幕密度，不通过加血量制造“像 Boss”。

### P2：音效与文字复检

目标：确认修复没有让音效或提示变得混乱。

重点观察：

- `kill` 是否盖过 `hurt / pressure`。
- Boss 预警和普通敌射击是否能分清。
- 升级、节点、Boss、精英提示是否足够短、准、通俗。
- 新增或改动文案必须跑乱码扫描。

### P3：作品集材料同步

如果 P0 验收通过，再推进作品集材料，而不是继续加系统。

推荐产物：

- 普通战回报链标注截图。
- 精英战“先拆护卫 / 再打本体”标注截图。
- Boss 战“预警 / 安全窗 / 反打窗口”标注截图。
- 30~60 秒短视频脚本。
- 素材和音效 A/B 对照说明。

## 下一轮不建议做

- 不新增新路线。
- 不新增大 Boss。
- 不重写 `RunEngine`。
- 不继续堆弹幕密度。
- 不把精英强化成高血高移速怪。
- 不一次性替换全量素材和音效。
- 不做大规模 UI 主题重做。

## 给 Kimi 的开发边界

下一轮如果交给 Kimi，建议使用“验收优先、失败项小修”的方式：

- 先跑 QA 和样本。
- 如果全部通过，只更新文档和样本证据，不强行改代码。
- 如果某项失败，只修失败项。
- 不允许把验收轮扩大成新系统开发轮。
