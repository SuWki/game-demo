# 2026-04-18 选择面板排版与异常承载收口

## 本轮目标

- 优化升级、路线、异常选择面板的排版，解决双选面板左侧空、正文瘦、异常卡像网页确认栏的问题。
- 复查当前属性强化与异常节点内容，让普通强化继续保持单主属性，异常节点改成更明显的玩法承接与路线变化。
- 在不改主流程、不加新系统的前提下做一轮整体自检，确认核心循环与战斗体验没有被这轮 UI / 内容修改带坏。

## 实现内容

- `src/ui/OverlayController.ts`
  - 选择面板新增双选居中布局判定，双卡不再沿用三列容器硬铺。
  - 强化卡继续保持品质配色，同时补了主属性标签，读起来更像“这张卡主加什么”。
  - 异常卡改成完整卡面结构，不再使用右侧瘦确认栏。
  - 异常卡现在会直接显示：
    - `改道窗 / 并线 / 预读 / 失真`
    - `续当前线 / 真改道 / Boss 承接`
    - `暴击推进 +1 / 当前路线推进 +1`
    - `承压 / 留余量`
- `src/style.css`
  - 新增 `is-two-choice` 双列居中排版。
  - 调整异常卡的结构、阴影、底纹和标签布局，让正文更满、更容易读。
  - 补了统一的功能标签样式，减少说明性文字占比。
- `src/data/events.ts`
  - 异常选项的规范化后追加了轻量“隐式路线承接”：
    - `routeWindow` 的 hold / keep 选项会继续承接当前路线
    - `hybrid / bossEcho / distortion` 会优先补当前路线或显式路线上一拍承接
  - 结果是异常节点不再大面积停留在“单属性 + 回血”的普通补给语义，而是更像改道、并线、预读或风险换读法。

## 数据结论

- 普通强化复检：
  - 通过 `buildUpgradeChoice(...)` 抽样确认，当前强化仍然是单主属性输出，没有回退到多属性组合卡。
- 异常复检：
  - 本轮前：异常池中仍有大量 `1 个 stats + 0 route` 的普通补给式选项。
  - 本轮后：异常池 `blandCount = 0`，所有异常选项都至少带一层路线承接或改道语义。

## 结果判断

- 路线、强化、异常三类选择现在更容易一眼区分。
- 双选面板已明显收口，不再保留一个空白第三列。
- 异常节点已经更接近“玩法改写器”，而不是换名字的属性强化。
- 主流程 `开始 -> 节点 -> 战斗 / 强化 / 异常 -> 结算 -> 重开` 未回退。
- `full-flow` 里的 `replaySeen` 仍显示 `false`，但这是旧 HUD 选择器口径未同步；截图已确认重开后正常回到战斗。

## 后续建议

- 如果继续打磨 UI，优先收口卡面与战斗层之间的空间关系，不要重新堆说明性文案。
- 如果继续打磨玩法，优先观察异常节点在自然样本里是否已经足够读成“这一拍改变了玩法”，而不是立刻再开新主题轮。
