# 2026-05-07 镜头稳定与关卡提示修复

## 本轮目标

解决用户实机反馈的两个体验问题：
- 操控时有眩晕感、恶心感，需要检查镜头缩放和抖动。
- 关卡开始前的提示像进度条，但没有说清楚它的作用。

## 问题判断

镜头层并不是只有“抖动”会造成不适。当前版本里还有三类会让玩家感觉画面不稳的因素：
- 镜头预测偏移：镜头会根据玩家速度向移动方向偏一点，急停和反向时容易产生漂移感。
- 旧穿梭缩放：虽然此前已经弱化，但需要在代码层防止 `zoomTo` 回归。
- 视觉边框缩放：连杀边框会随连杀动态变宽，虽然不是镜头缩放，但会造成画面整体呼吸感。

关卡提示层的问题是：左侧三条装饰线本意是“路线推进”，但玩家看到的更像进度条或倒计时，且没有解释选择规则。

## 实际修改

### 镜头稳定

- `GameScene.ts` 创建场景时强制 `this.cameras.main.setZoom(1)`。
- `GameScene.ts` 移除玩家速度带来的镜头预测偏移，镜头稳定居中跟随。
- `GameScene.ts` 移除渲染端 shake 偏移计算，战斗视窗不再左右上下抖动。
- `GameScene.ts` 穿梭状态下如果检测到镜头缩放不是 `1`，立即重置为 `1`。
- `GameScene.ts` 连杀边缘反馈改为固定宽度和固定角标长度，只保留透明度变化。
- `RunEngine.ts` `kickBattleShake()` 保留接口但直接返回，避免命中、受击、击杀等事件重新写入镜头抖动。

### 关卡提示

- `OverlayController.ts` 删除路线选择面板里的装饰节点和三条线。
- `OverlayController.ts` 改为显示“下一站”和“选择规则”。
- `style.css` 将路线说明改成小信息卡，明确告诉玩家这不是倒计时或血条，而是本局推进位置。

## 为什么这样改

这轮不继续“调轻一点抖动”，而是先把会移动整个画面的效果尽量归零。射击游戏里玩家本来就要同时读敌人、弹幕、XP、路线特效和 Boss 安全区，如果镜头也在漂移，会明显提高视觉负担。

关卡提示同理，路线选择前最重要的是让玩家知道“现在要选下一站”，不是让装饰线看起来更酷。先把信息说清，再考虑美术包装。

## 验证

- `npm run build`：通过。

## 仍需人工验证

- 移动、转向、穿梭、连杀、受击时是否仍有眩晕感。
- Boss 战、安全区伤害、压力音效触发时是否还有画面整体晃动。
- 路线选择面板是否能清楚解释“推进位置”和“选择规则”。

## 下一步建议

如果仍然晕，下一轮优先检查：
- 背景层是否有大面积移动或滚动感。
- 全屏闪白/闪红是否过强。
- Boss 安全区或危险背景是否覆盖面积太大。
- 玩家周围是否仍有常驻线条或大范围脉冲。
