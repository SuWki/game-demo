# 2026-04-24 战斗手感与音效优化复盘

## 本轮目标

- 按 `doc/40_AI协作/战斗手感与音效优化对接文档.md` 做实际落地，不重写主流程。
- 让普通战、精英战、Boss 战更像完整可玩的短局战斗，而不是只靠功能骨架成立。
- 优先提升移动 / 开火 / 命中 / 击杀 / 拾取之间的连续身体感。
- 优先拉开 `shoot / hit / kill / pickup` 与 `hurt / nearMiss / pressure / enemyShot` 的听觉语义。
- 让 `pierce` 在视觉和音频上拥有更稳定的持续签名。

## 实际改了哪些手感内容

- `BattleState` 新增 `pierceFlowSec / pierceFlowCount`，作为轻量贯穿持续窗口。
- `RunEngine` 在穿透命中、同弹多次命中、回声弹、精英裂口贯穿和拾取承接时注册 `pierceFlow`。
- `pierceFlow` 会短暂托住移动、转向、开火退款与 `tempoPulse`，让“切开一条线后继续压”更容易被手感读到。
- 起步阈值、转向爆发和停手阻尼略微收紧，让移动响应更干脆，但没有改主数值表。

## 实际改了哪些音效内容

- `PilotAudio` 沿现有 cue 增强 route tint，没有新增复杂 cue 系统。
- `pierce` 的 `shoot / hit / kill / pickup` 更偏冷色拉线、切线噪声和中高频拖尾。
- `hurt` 更低、更重、duck 更强，作为最高危险确认。
- `nearMiss` 更尖、更薄、更短，强调擦边而非受击。
- `pressure` 更偏低频和持续压迫，Boss / 精英语境下更厚，避免和普通 `enemyShot` 混在一起。
- `window.__pilotAudioDebug()` 增加 `routeFocus / encounter / intensity`，便于后续验证上下文是否正确同步。

## 为什么先改这些

- 当前核心循环已经能跑通，最缺的是“手上和耳朵里是否觉得在打一局游戏”。
- `pierce` 已有机制和画面线索，但持续爽点相比 `crit / dash` 仍偏弱，因此优先补最小手感窗口。
- 高频战斗里最容易糊的是 `hit / kill / pickup` 和危险层，因此优先用现有 cue 拉开语义，而不是新增一堆事件。

## 哪些问题被改善了

- `pierce` 不再只靠穿透次数读路线，命中、回声、裂口和拾取后会短暂形成可见/可听的贯穿连续感。
- 移动起步、转向和停手更清楚，普通战追资源后接下一枪更顺。
- `hurt / nearMiss / pressure / enemyShot` 的优先级和音色层级更明确。
- 普通战主链 cue 与高压场景 cue 更不容易混成同一类提示音。

## 哪些仍然只是临时状态

- 所有音效仍是程序化合成，不是正式资产签收态。
- `pierceFlow` 是轻量窗口，不是完整新路线系统；后续仍需自然样本验证是否过强或过弱。
- `dash` 的声音和持续视觉签名仍弱于 `crit / pierce`，后续路线专项应继续补。
- 精英 / Boss 的正式记忆点仍依赖后续资产和更稳定的自然样本验收。
