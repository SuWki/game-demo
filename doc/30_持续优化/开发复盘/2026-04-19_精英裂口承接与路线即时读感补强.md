# 2026-04-19 精英裂口承接与路线即时读感补强

## 本轮目标

- 继续停留在 `1.0 第一阶段` 的核心循环 / 核心战斗打磨主线。
- 不开地图可视化轮，不开 Boss 新主题轮，不引入新系统。
- 沿当前优先级继续推进：
  - 精英战自然样本稳定度
  - `crit / pierce` 在精英窗口里的即时读感
  - 场内追击反馈，而不是文字解释

## 本轮实现

- 在 `src/systems/RunEngine.ts` 中补了精英裂口命中后的 follow-through 承接：
  - 新增 `getEliteBreachFollowThroughRatio`，把精英 `crackWindow` 和 `recovery` 合并成一个轻量命中承接判定。
  - 新增 `applyEliteBreachHitFollowThrough`，只在精英战里工作，不碰 Boss 主流程。
  - 精英裂口命中现在会继续托住：
    - `tempoPulse`
    - `playerTurnBurst`
    - `playerMoveBoost`
    - `fireCooldown`
- 路线差异继续压在已有状态上，而不是新系统：
  - `crit`
    - 精英裂口命中时更稳地托住 `critOverdrive`
    - 低血线 / 裂口恢复态时更容易读成“继续追收”
  - `pierce`
    - 精英裂口命中时会轻量推开近护卫并续一拍节奏
    - 更像“拆缝 -> 穿线 -> 压本体”
  - `dash`
    - 只补了非常轻量的裂口续追，不把本轮重新做成穿梭专项轮
- 在 `src/scenes/GameScene.ts` 中补了只在精英裂口窗口出现的 route-shaped 场内读感：
  - `crit` 多了一层执行箭头与收束锁圈
  - `pierce` 多了一层贯穿轨道与护卫切线提示
  - 这些都只画在场内，不新增解释性 UI
- 同时对自动瞄准在精英裂口里的路由偏好做了轻量校准：
  - `crit` 更愿意继续咬住低血 / 裂口中的精英本体
  - `pierce` 更愿意顺着 lane score 继续压本体

## 为什么这样做

- 当前 docs 已经很明确：这条主线不再是“内容够不够多”，而是“核心战斗是不是已经足够愿意让人继续打”。
- 普通战的拾取追击链上一轮已经补到位，这轮更适合把同样的“继续追一拍”感压到精英裂口里。
- 继续沿现有 `BattleState` 和场内反馈层做，是为了让爽点更直接、风险更低，也避免把项目重新带回系统扩写。

  - `resultSeen = true`

  - 当前已确认它能稳定优先选择精英路线，但样本里仍会出现“进精英前先自然死亡”或长局挂起，导致精英裂口截图验证不稳定。
  - 这属于验证脚本稳定性缺口，不应直接解读为功能回退。

## 当前结论

- 精英裂口后的继续追击已经不再只靠 `pressure pulse` 本身成立，而是开始有“命中一下 -> 继续压 -> 再进一拍”的承接。
- `crit` 与 `pierce` 在精英窗口里的场内读感开始明显拉开：
  - `crit` 更像执行追收
  - `pierce` 更像拆缝穿线
- 下一步最适合继续推进的是：
  - 继续补精英定向 / 自然样本验证稳定度
  - 确认新增 route-shaped 裂口反馈在真实样本里可持续读到
  - 最后再顺手复检 Boss 监控项，避免被监控项反过来劫持主线
