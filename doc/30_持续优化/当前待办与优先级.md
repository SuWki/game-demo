# 当前待办与优先级

## 更新时间

- `2026-04-30`

## 当前总判断

当前项目已经完成玩家反馈问题修复、一轮专项验收、Boss 强制触发 QA 入口开发，以及 Boss 安全窗人工实机补验：音量面板、暂停继续、属性显示、拖尾、精英样本、素材黑底、音效层级、Boss 定向触发能力和 Boss 安全窗都已经基本可签收。

但当前用户明确要求先做代码性开发，因此作品集线暂缓。下一步应回到游戏本体，优先做关卡节奏、操作手感、普通战回报链和中段路线站稳的小步优化。当前目标不是加新系统，而是让已有核心循环更顺、更稳、更有继续玩的冲动。

正确方向仍然是双线并行：

- 游戏线：恢复为 P0，优先做关卡节奏和操作手感小步代码优化。
- 作品集线：暂缓，等本轮可玩性优化后再继续截图、短视频和 A/B 展示。

## P0：关卡节奏与操作手感小步优化

目标：不新增大系统、不重写主流程，只通过小步参数、数据分发和轻量手感承接，让一局前中段更顺，普通战更有追击感，中段更像路线站稳。

必须完成：

- 先跑 `npm run build` 和一次 full-flow，确认基线。
- 检查 `src/data/nodes.ts`、`src/data/contentSelectors.ts`、`src/data/battleTemplates.ts`、`src/data/upgrades.ts` 的中段/后段职责是否清楚。
- 小步优化第二轮和第三轮节点职责：第二轮更像站稳，第三轮更像收束。
- 小步优化普通战回报链：击杀、掉落、吸附、升级、下一拍的承接更顺。
- 小步优化玩家操作手感：移动起停、反向转向、拾取吸附、击杀后继续开火/追击。
- 如果需要补接口，只做最小 debug/metrics，不重开系统。
- 完成后跑 full-flow 和 3~5 分钟自然样本。

重点看：

- 第 1~2 场普通战是否更容易形成“打死 -> 捡 -> 继续追”的节奏。
- 第二轮是否更稳定感到路线开始站稳。
- 第三轮是否更像收束，而不是普通战拉长。
- 移动/拾取/射击承接是否更顺，但不变成无脑碾压。
- `crit / pierce / dash` 是否没有被手感调优抹平。

## P1：普通战回报链与路线站稳复检

目标：确认 P0 的小步优化不是“感觉更快”而是真正让核心循环更粘。

优先方向：

- 观察 `killPickupContinueMoments` 或类似 debug 字段是否保持/提升。
- 观察自然样本第 2~3 节点是否仍容易被打断。
- 观察路线倾向是否更早可见，但没有过早锁死。
- 观察升级卡是否更像回应上一场战斗，而不是孤立数值选择。

验收重点：

- 战斗爽感来自回报链和读局，而不是单纯调高数值。
- 中段站稳来自路线承接，而不是早早发终局强牌。
- 后段收束来自节点职责和压力变化，而不是堆怪。

## P3：作品集材料三件套

目标：把当前项目转成战斗策划作品，而不是继续做宽。

优先产出：

1. `项目总览一页纸`
2. `战斗参数表`
3. `敌人设计表`

为什么先做这三件：

- 它们能最早暴露“当前项目还缺哪些硬证据”。
- 它们能帮助判断是否真的需要新增 Boss 或精英。
- 它们比继续写大文档更接近可投递材料。

当前补充：

- `精英战案例页` 已经用于承接精英裂口与护卫拆解案例。
- `Boss战案例页` 已经用于承接 Boss 火线、安全窗与三路线答题案例。
- 下一步不是继续写长文，而是给这些材料补标注截图、短视频脚本和可投递排版。

## P4：素材与音效同步优化

目标：服务作品集展示和实机观感，不抢战斗设计主线。

允许做：

- 首批核心视觉资产预览：玩家、标准敌、精英核心、Boss Bastion、XP 球、基础弹道。
- 首批核心音效替换或制作：`shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot`。
- 演示视频需要的 UI / 结果页 / 战斗关键帧截图优化。

暂不建议做：

- 全量正式素材替换。
- 大规模 UI 主题重做。
- 把项目包装成美术或音频作品集。
- 为了素材好看牺牲战斗读局。

## P5：是否新增 Boss / 精英

暂时不建议立刻开做。

触发条件：

- `项目总览一页纸`、`战斗参数表`、`敌人设计表` 做完后，发现当前 Boss 或精英案例说服力不足。
- 演示视频脚本无法用现有 Boss / 精英讲清楚三路线答题方式。
- 当前硬数据不足以支撑作品集案例页。

如果满足上述条件，再考虑：

- 新增 1 个更考路线空间的 Boss。
- 新增 2 个分工明确的精英模板。
