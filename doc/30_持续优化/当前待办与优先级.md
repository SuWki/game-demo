# 当前待办与优先级

## 更新时间

- `2026-05-08`

## 2026-05-08 当前整体优先级

**当前判断**：项目已具备可运行主流程、三路线基础机制、Boss 安全区、素材接入和基础 QA。下一步不要急着继续补功能，也不要马上转作品集包装；应先完成体验验收和设计收口，让项目从“能玩”变成“能讲清楚为什么好玩”。

### P0：人工实机验收

**要做什么**：
- 各打一局 `crit / pierce / dash`。
- 记录路线牌数量、成型节点、精英/Boss 击杀速度、玩家主要死因。
- 观察镜头是否仍晕、背景是否干扰、路线特效是否看得清。

**为什么先做**：
- 当前很多问题不是自动 QA 能判断的，例如眩晕、爽感、路线是否“像构筑”、特效是否读得出来。
- 如果不先验收，就会继续凭猜测调数值，容易把项目改散。

### P0：路线构筑收口

**要做什么**：
- 保持路线牌审计硬违规 0、超预算 0。
- 继续检查路线牌是否仍偏“单张数值强”，优先改成“入口 -> 承接 -> 条件收益 -> 终局兑现”。
- `crit` 控制爆发强度，避免短时间压过 `pierce / dash`。
- `pierce` 提升裂纹、串线、扩散的可读性和构筑感，不直接加穿透数值。
- `dash` 保留绿色脉冲优势，但让回切、擦身、窗口收益更有决策感。

**为什么要做**：
- 这是本项目最适合求职展示的设计点：不是单纯做数值，而是做“流派如何形成打法”。

### P1：关卡职责强化

**要做什么**：
- 普通战负责回报链和手感。
- 生存战负责走位压力和安全路线。
- 精英战负责局部解题，例如护卫、裂口、追击窗口。
- Boss 战负责终局考试，分别验证暴击短窗、穿透串线、穿梭换位。

**为什么要做**：
- 当前如果每类战斗都只是清怪，玩家不会理解节点选择的意义，作品集里也讲不出关卡设计能力。

### P1：表现层与音效读局

**要做什么**：
- 继续把路线反馈放到敌人受击层、弹道短残痕和音效签名上。
- 控制背景、全屏闪、边框反馈，不再让画面整体晃动或覆盖战斗。
- 检查 `shoot / hit / kill / pickup / hurt / pressure / enemyShot` 是否仍能分清。

**为什么要做**：
- 自动射击游戏的信息密度很高，表现层不只是“好看”，而是决定玩家能不能读懂战斗。

### P2：求职作品证据链

**要做什么**：
- 等 P0/P1 验收通过后，再录制 30 到 60 秒核心玩法视频。
- 整理 3 个案例页：路线构筑、Boss 安全区、表现层读局。
- 每个案例页都写清：原问题、设计假设、改法、验证方式、最终效果。

**为什么后置**：
- 现在直接做包装，会把未验收的问题包装进去。求职作品要展示设计判断，不只是展示截图。

- 观察自然样本第 2~3 节点是否仍容易被打断。
- 观察路线倾向是否更早可见，但没有过早锁死。
- 观察升级卡是否更像回应上一场战斗，而不是孤立数值选择。

验收重点：

- 战斗爽感来自回报链和读局，而不是单纯调高数值。
- 中段站稳来自路线承接，而不是早早发终局强牌。
- 后段收束来自节点职责和压力变化，而不是堆怪。
