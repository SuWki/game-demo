# 当前待办与优先级

## 更新时间

- `2026-04-30`

## 当前总判断

当前项目已经完成玩家反馈问题修复、一轮专项验收、Boss 强制触发 QA 入口开发，以及 Boss 安全窗人工实机补验：音量面板、暂停继续、属性显示、拖尾、精英样本、素材黑底、音效层级、Boss 定向触发能力和 Boss 安全窗都已经基本可签收。

但当前用户明确要求先把表现层和手感打磨好，再做材料和作品集。因此作品集线继续暂缓。`f9fe44d` 已完成一轮较大规模的数值平衡与异常系统重构：通用/路线升级属性整体下调约 25%，拾取和磁吸范围缩小，异常事件从 35 个收束到 10 个玩法事件，生存模式刷怪逻辑和全量文案也已改动。下一步不应继续大范围改代码，而应先做人工实机验收，确认难度、成长、拾取、异常、路线和文案都站得住。

正确方向仍然是双线并行：

- 游戏线：恢复为 P0，当前先做 `f9fe44d` 实机验收和定向回调；通过后再做表现层和手感小步代码优化。
- 作品集线：暂缓，等本轮可玩性优化后再继续截图、短视频和 A/B 展示。

## P0：f9fe44d 实机验收与定向回调

目标：不新增大系统、不继续批量调数值、不重写主流程，先确认 `f9fe44d` 的大范围数值和异常系统改动在真实游玩中是否成立。只有发现明确问题，才做定向小回调。

必须完成：

- 人工实机至少 3 局，覆盖普通路线、异常路线、Boss 路线，记录每局路线、等级、死亡/胜利节点和主要感受。
- 确认精英和 Boss 是否不再被秒杀，但也不会变成过厚木桩。
- 确认拾取/磁吸缩小后，XP 收集是否更有参与感但不繁琐。
- 确认异常事件前期少、后期多的节奏是否成立，10 个异常是否重复感过强。
- 确认 `crit / pierce / dash` 是否都还能成型，没有某条路线被 25% 下调打废。
- 确认文案是否真的玩家能懂，没有因为去掉单位或重写描述导致信息丢失。
- 跑 `npm run build`、`tsc --noEmit`、平衡性测试和一次 full-flow。
- 只有实机发现明确问题，才允许定向回调 `balance.ts / upgrades.ts / events.ts / nodes.ts / battleTemplates.ts`。

重点看：

- 数值挑战来自敌我节奏和路线选择，不是单纯把玩家压弱。
- 异常事件要改变打法，而不是变成看不懂的惩罚。
- 文案要更游戏化，但不能牺牲关键信息。
- 如果实机通过，再转入表现层第二轮补强；不要在未验收前继续叠改动。

## P1：表现层与手感第二轮补强

目标：在 `f9fe44d` 实机验收通过或完成定向回调后，再继续补画面读局、打击反馈、音效层次、操控承接和通俗提示。

优先方向：

- 检查 `src/scenes/GameScene.ts` 的弹道、命中、击杀、拾取、危险提示、路线签名是否清楚。
- 检查 `src/systems/PilotAudio.ts` 的主反馈链、危险链、路线声纹是否分得开。
- 检查 `src/ui/OverlayController.ts` 和 `src/style.css` 的开始页、暂停页、升级、结算、局内提示是否通俗且不遮挡。
- 小步优化玩家操作手感：移动起停、反向转向、拾取吸附、开火承接、击杀后继续开火/追击。

## P2：关卡节奏与普通战回报链复检

目标：在 `f9fe44d` 实机验收和表现层补强后，再确认关卡节奏不是“感觉更快”，而是真正让核心循环更粘。

优先方向：

- 观察 `killPickupContinueMoments` 或类似 debug 字段是否保持/提升。
- 观察自然样本第 2~3 节点是否仍容易被打断。
- 观察路线倾向是否更早可见，但没有过早锁死。
- 观察升级卡是否更像回应上一场战斗，而不是孤立数值选择。

验收重点：

- 战斗爽感来自回报链和读局，而不是单纯调高数值。
- 中段站稳来自路线承接，而不是早早发终局强牌。
- 后段收束来自节点职责和压力变化，而不是堆怪。

## P4：作品集材料三件套

目标：把当前项目转成战斗策划作品，而不是继续做宽。当前暂缓，等表现层和手感更稳后再继续。

优先产出：

1. `项目总览一页纸`
2. `战斗参数表`
3. `敌人设计表`

为什么先做这三件：

- 它们能最早暴露“当前项目还缺哪些硬证据”。
- 它们能帮助判断是否真的需要新增 Boss 或精英。
- 它们比继续写大文档更接近可投递材料。

当前补充：

- `精英战案例页` 已经用于承接精英裂口与护卫拆解案例。
- `Boss战案例页` 已经用于承接 Boss 火线、安全窗与三路线答题案例。
- 下一步不是继续写长文，而是给这些材料补标注截图、短视频脚本和可投递排版。

## P5：素材与音效同步优化

目标：服务作品集展示和实机观感，不抢战斗设计主线。

允许做：

- 首批核心视觉资产预览：玩家、标准敌、精英核心、Boss Bastion、XP 球、基础弹道。
- 首批核心音效替换或制作：`shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot`。
- 演示视频需要的 UI / 结果页 / 战斗关键帧截图优化。

暂不建议做：

- 全量正式素材替换。
- 大规模 UI 主题重做。
- 把项目包装成美术或音频作品集。
- 为了素材好看牺牲战斗读局。

## P6：是否新增 Boss / 精英

暂时不建议立刻开做。

触发条件：

- `项目总览一页纸`、`战斗参数表`、`敌人设计表` 做完后，发现当前 Boss 或精英案例说服力不足。
- 演示视频脚本无法用现有 Boss / 精英讲清楚三路线答题方式。
- 当前硬数据不足以支撑作品集案例页。

如果满足上述条件，再考虑：

- 新增 1 个更考路线空间的 Boss。
- 新增 2 个分工明确的精英模板。
