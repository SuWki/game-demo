正确方向仍然是双线并行：

## P0：表现层与手感小步打磨

目标：不新增大系统、不重写主流程，只通过小步参数、反馈表现和轻量手感承接，让玩家看得清、听得懂、移动顺、打击爽、提示直白。

必须完成：

- 先验收 `74fa9bd`：跑 `npm run build`、一次 full-flow、一次 3~5 分钟自然样本和 2~3 局人工体验。
- 观察经验值提升是否导致升级过快，拾取/磁吸提升是否导致 XP 过于自动，第二轮精英权重提升是否导致中段过压。
- 只有验证失败，才允许回调 `balance.ts` 或 `nodes.ts` 的本轮参数。
- 检查 `src/scenes/GameScene.ts` 的弹道、命中、击杀、拾取、危险提示、路线签名是否清楚。
- 检查 `src/systems/PilotAudio.ts` 的主反馈链、危险链、路线声纹是否分得开。
- 检查 `src/ui/OverlayController.ts` 和 `src/style.css` 的开始页、暂停页、升级、结算、局内提示是否通俗且不遮挡。
- 小步优化玩家操作手感：移动起停、反向转向、拾取吸附、开火承接、击杀后继续开火/追击。
- 如果需要补接口，只做最小 debug/metrics 或 cue helper，不重开系统。
- 完成后跑 full-flow、3~5 分钟自然样本和一次人工听感/画面读局复检。

重点看：

- 第 1~2 场普通战是否更容易形成“看见目标 -> 打中 -> 击杀 -> 掉落 -> 拾取 -> 继续追”的连续体验。
- 玩家弹道、敌方弹道、XP、危险区域、精英/Boss 压力窗是否更容易区分。
- `shoot / hit / kill / pickup` 与 `hurt / nearMiss / pressure / enemyShot` 是否听感分明。
- 移动/拾取/射击承接是否更顺，但不变成无脑碾压。
- `crit / pierce / dash` 是否没有被表现和手感调优抹平。

## P1：关卡节奏与普通战回报链复检

目标：在 P0 的表现和手感更清楚后，再确认关卡节奏不是“感觉更快”，而是真正让核心循环更粘。

优先方向：

- 观察 `killPickupContinueMoments` 或类似 debug 字段是否保持/提升。
- 观察自然样本第 2~3 节点是否仍容易被打断。
- 观察路线倾向是否更早可见，但没有过早锁死。
- 观察升级卡是否更像回应上一场战斗，而不是孤立数值选择。

验收重点：

- 战斗爽感来自回报链和读局，而不是单纯调高数值。
- 中段站稳来自路线承接，而不是早早发终局强牌。
- 后段收束来自节点职责和压力变化，而不是堆怪。

## P3：作品集材料三件套

目标：把当前项目转成战斗策划作品，而不是继续做宽。当前暂缓，等表现层和手感更稳后再继续。

优先产出：

1. `项目总览一页纸`
2. `战斗参数表`

为什么先做这三件：

- 它们能最早暴露“当前项目还缺哪些硬证据”。

当前补充：

- `Boss战案例页` 已经用于承接 Boss 火线、安全窗与三路线答题案例。

## P4：素材与音效同步优化

目标：服务作品集展示和实机观感，不抢战斗设计主线。

允许做：

- 首批核心视觉资产预览：玩家、标准敌、精英核心、Boss Bastion、XP 球、基础弹道。

暂不建议做：

- 全量正式素材替换。
- 大规模 UI 主题重做。
- 把项目包装成美术或音频作品集。
- 为了素材好看牺牲战斗读局。

## P5：是否新增 Boss / 精英

暂时不建议立刻开做。

触发条件：

- `项目总览一页纸`、`战斗参数表`、`敌人设计表` 做完后，发现当前 Boss 或精英案例说服力不足。
- 演示视频脚本无法用现有 Boss / 精英讲清楚三路线答题方式。

如果满足上述条件，再考虑：

- 新增 1 个更考路线空间的 Boss。
