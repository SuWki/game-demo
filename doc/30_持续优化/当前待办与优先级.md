# 当前待办与优先级

## 更新时间

- `2026-05-01`

## 当前总判断

当前项目已经完成玩家反馈问题修复、一轮专项验收、Boss 强制触发 QA 入口开发、Boss 安全区刷新机制修正，以及 `2026-05-01` 玩家实机反馈定向修复：音量面板、暂停继续、属性显示、拖尾、精英样本、素材黑底、音效层级、Boss 定向触发能力都已经基本可签收；本轮进一步处理了 `ms` 单位、HP/EXP 小数显示、歼灭/生存目标显示、默认音量、升级回血、异常普通化、路线卡单一化、穿透超模、Boss 弹幕与安全区内中弹等问题。

但当前用户明确要求先把表现层和手感打磨好，再做材料和作品集。因此作品集线继续暂缓。下一步不应继续大范围改系统，而应先做人工实机验收，确认这轮回调后的难度、成长、拾取、异常、三路线、Boss 安全区和文案都站得住。

正确方向仍然是双线并行：

- 游戏线：恢复为 P0，当前先验收 `2026-05-01` 实机反馈定向修复；通过后再做表现层和手感小步代码优化。
- 作品集线：暂缓，等本轮可玩性优化后再继续截图、短视频和 A/B 展示。

## P0：玩家实机反馈修复验收

目标：不新增大系统、不继续批量调数值、不重写主流程，先确认 `2026-05-01` 这轮定向修复在真实游玩中是否成立。只有发现明确问题，才做定向小回调。

必须完成：

- 人工实机至少 3 局，分别优先走 `crit / pierce / dash`，记录每局路线、等级、死亡/胜利节点和主要感受。
- 确认穿透不再随便秒杀精英/Boss，但仍然有贯穿、拆线和回声的路线存在感。
- 确认暴击不再只有暴击率提升，且暴击触发提示、声音和命中反馈能被玩家感知。
- 确认穿梭不再只有冷却缩短，且穿梭触发提示能让玩家知道“我刚刚触发了穿梭收益”。
- 确认异常事件不再像普通强化，至少能看到路线融合、属性转换或风险回报。
- 确认 Boss 安全区内更安全，安全区外有真实威胁，但不会因为压力惩罚导致玩家移动莫名变慢。
- 确认歼灭关显示 `当前击杀/目标击杀`，生存关显示倒计时。
- 确认 HP/EXP 和属性面板对玩家显示为整数。
- 跑 `npm run build`、一次 full-flow 和一次 Boss 定向样本。
- 只有实机发现明确问题，才允许定向回调 `RunEngine.ts / battleTemplates.ts / balance.ts / upgrades.ts / events.ts / nodes.ts`。

重点看：

- Boss 安全区要“高压但可读”：玩家能理解躲哪里、怎么进安全区、什么时候反打。
- 数值挑战来自敌我节奏和路线选择，不是单纯把玩家压弱。
- 异常事件要改变打法，而不是变成看不懂的惩罚。
- 文案要更游戏化，但不能牺牲关键信息。
- 如果实机通过，再转入表现层第二轮补强；不要在未验收前继续叠改动。

## P1：表现层与手感第二轮补强

目标：在 `f9fe44d` 实机验收通过或完成定向回调后，再继续补画面读局、打击反馈、音效层次、操控承接和通俗提示。

优先方向：

- 检查 `src/scenes/GameScene.ts` 的弹道、命中、击杀、拾取、危险提示、路线签名是否清楚。
- 检查 `src/systems/PilotAudio.ts` 的主反馈链、危险链、路线声纹是否分得开。
- 检查 `src/ui/OverlayController.ts` 和 `src/style.css` 的开始页、暂停页、升级、结算、局内提示是否通俗且不遮挡。
- 小步优化玩家操作手感：移动起停、反向转向、拾取吸附、开火承接、击杀后继续开火/追击。

## P2：关卡节奏与普通战回报链复检

目标：在 `f9fe44d` 实机验收和表现层补强后，再确认关卡节奏不是“感觉更快”，而是真正让核心循环更粘。

优先方向：

- 观察 `killPickupContinueMoments` 或类似 debug 字段是否保持/提升。
- 观察自然样本第 2~3 节点是否仍容易被打断。
- 观察路线倾向是否更早可见，但没有过早锁死。
- 观察升级卡是否更像回应上一场战斗，而不是孤立数值选择。

验收重点：

- 战斗爽感来自回报链和读局，而不是单纯调高数值。
- 中段站稳来自路线承接，而不是早早发终局强牌。
- 后段收束来自节点职责和压力变化，而不是堆怪。

## P4：作品集材料三件套

目标：把当前项目转成战斗策划作品，而不是继续做宽。当前暂缓，等表现层和手感更稳后再继续。

优先产出：

1. `项目总览一页纸`
2. `战斗参数表`
3. `敌人设计表`

为什么先做这三件：

- 它们能最早暴露“当前项目还缺哪些硬证据”。
- 它们能帮助判断是否真的需要新增 Boss 或精英。
- 它们比继续写大文档更接近可投递材料。

当前补充：

- `精英战案例页` 已经用于承接精英裂口与护卫拆解案例。
- `Boss战案例页` 已经用于承接 Boss 火线、安全窗与三路线答题案例。
- 下一步不是继续写长文，而是给这些材料补标注截图、短视频脚本和可投递排版。

## P5：素材与音效同步优化

目标：服务作品集展示和实机观感，不抢战斗设计主线。

允许做：

- 首批核心视觉资产预览：玩家、标准敌、精英核心、Boss Bastion、XP 球、基础弹道。

暂不建议做：

- 把项目包装成美术或音频作品集。

## P6：是否新增 Boss / 精英

暂时不建议立刻开做。

触发条件：

- `项目总览一页纸`、`战斗参数表`、`敌人设计表` 做完后，发现当前 Boss 或精英案例说服力不足。
- 演示视频脚本无法用现有 Boss / 精英讲清楚三路线答题方式。
- 当前硬数据不足以支撑作品集案例页。

如果满足上述条件，再考虑：

- 新增 1 个更考路线空间的 Boss。
- 新增 2 个分工明确的精英模板。
