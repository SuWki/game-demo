# 当前待办与优先级

## 更新时间

- `2026-05-02`

## 当前总判断

当前项目已经完成多轮玩家反馈修复、Boss 安全区刷新机制修正、异常节点玩法化、素材透明化接入、路线强化价值收窄、Boss 火线遮罩关闭、Boss/精英压力补强和协作规则收口。

但当前最核心的问题已经从“单项 bug 修复”升级为“设计基线收口”：三条路线必须通过多张强化逐步构筑成打法，不能拿 1 到 2 张牌就杀穿；Boss 和精英必须作为出题单位，体现 `crit / pierce / dash` 的不同解法；表现层要减少浮字和玩家周围线条，把流派反馈转移到敌人、弹道、命中点和短时地面反馈上。

作品集线继续暂缓。下一步先清理设计文档并等待用户实机反馈，再根据真实体验给 Kimi 输出代码骨架和修改提示词。

正确方向是三步走：

1. 先收口设计文档：明确流派构筑、敌人出题、表现去遮挡。
2. 再由用户实机验收：反馈当前版本真实体感。
3. 最后让 Kimi 做定向代码回调：只修实机暴露出的明确问题。

## P0：流派构筑与敌人出题验收

目标：确认当前版本是否已经从“拿几张强牌杀穿”回到“通过构筑形成打法，再用打法解决精英/Boss 出题”。

### 2026-05-02 最新实机反馈

用户反馈当前最新版本仍存在以下 P0 问题：

- 流派增益出现概率过高，普通强化缺乏性价比。
- 专属名词浮动窗只告诉玩家“穿梭有什么强化”，没有解释“怎样才算穿梭、怎样会触发”。
- 开局偶发玩家周围有 3 条绿色横线固定跟随，需要去掉。
- 一次升级选择仍可能出现两个流派 buff。
- Boss 生存压力偏小，需要适度增加弹幕数量、缩小安全区，并提高安全区外真实伤害压力。
- 开局拿 `伤害 +4` 后再拿暴击流派增益会卡死，需要优先修复。
- 路线选择中仍出现两个强化关卡，必须写成硬规则：战斗节点可以多个，强化/异常节点最多一个，且概率远低于战斗。
- 暴击路线风险/收益方向是对的，但路线牌同时给暴击和爆伤，性价比明显高于普通强化。
- 穿透路线强度仍然无敌，需要按“构筑分层 + 条件触发 + 价值预算”重构。

下一轮 Kimi 应先修确定性 bug：卡死、节点数量、升级面板路线牌数量、玩家周围绿色横线。随后再做流派重构和 Boss 压力回调。

必须完成：

- 人工实机至少 3 局，分别优先走 `crit / pierce / dash`。
- 记录每局路线牌数量、是否成型、精英/Boss 是否被快速秒杀、死亡/胜利节点和主要感受。
- 确认 1 张路线牌只形成倾向，不形成完整流派。
- 确认 2 到 3 张路线牌开始有承接，但不能稳定跳过精英/Boss。
- 确认 4 张以上路线牌才开始形成稳定打法。
- 确认 Boss/精英能体现不同路线解法，而不是所有路线都靠 DPS 打穿。
- 确认素材和音效接入没有牺牲读局。
- 确认路线触发浮字和玩家周围线条是否仍然干扰画面，如果干扰，下一轮优先移除。

重点看：

- `crit` 是否通过短窗、弱点、爆点成立，而不是平均 DPS 碾压。
- `pierce` 是否通过角度、敌线、护卫和贯穿成立，而不是无脑清屏。
- `dash` 是否通过换位、安全窗、回切和反打成立，而不是冷却低就安全。
- Boss/精英是否像出题单位，而不是血厚木桩或数值沙包。
- 战斗画面是否干净，玩家周围是否还有不必要的线条。

## P1：表现层与手感第二轮补强

目标：在 P0 实机反馈明确后，再继续补画面读局、打击反馈、音效层次、操控承接和通俗提示。

优先方向：

- 检查 `src/scenes/GameScene.ts` 的弹道、命中、击杀、拾取、危险提示、路线签名是否清楚。
- 检查 `src/systems/PilotAudio.ts` 的主反馈链、危险链、路线声纹是否分得开。
- 检查 `src/ui/OverlayController.ts` 和 `src/style.css` 的开始页、暂停页、升级、结算、局内提示是否通俗且不遮挡。
- 小步优化玩家操作手感：移动起停、反向转向、拾取吸附、开火承接、击杀后继续开火/追击。
- 把路线触发文字逐步改为敌人身上的特效、命中点反馈和短时弹道反馈。
- 去掉玩家周围长期或半长期的解释性线条，让战斗画面更干净。

## P2：关卡节奏与普通战回报链复检

目标：在 `f9fe44d` 实机验收和表现层补强后，再确认关卡节奏不是“感觉更快”，而是真正让核心循环更粘。

优先方向：

- 观察 `killPickupContinueMoments` 或类似 debug 字段是否保持/提升。
- 观察自然样本第 2~3 节点是否仍容易被打断。
- 观察路线倾向是否更早可见，但没有过早锁死。
- 观察升级卡是否更像回应上一场战斗，而不是孤立数值选择。

验收重点：

- 战斗爽感来自回报链和读局，而不是单纯调高数值。
- 中段站稳来自路线承接，而不是早早发终局强牌。
- 后段收束来自节点职责和压力变化，而不是堆怪。

## P4：作品集材料三件套

目标：把当前项目转成战斗策划作品，而不是继续做宽。当前暂缓，等表现层和手感更稳后再继续。

优先产出：

1. `项目总览一页纸`
2. `战斗参数表`
3. `敌人设计表`

为什么先做这三件：

- 它们能最早暴露“当前项目还缺哪些硬证据”。
- 它们能帮助判断是否真的需要新增 Boss 或精英。
- 它们比继续写大文档更接近可投递材料。

当前补充：

- `精英战案例页` 已经用于承接精英裂口与护卫拆解案例。
- `Boss战案例页` 已经用于承接 Boss 火线、安全窗与三路线答题案例。
- 下一步不是继续写长文，而是给这些材料补标注截图、短视频脚本和可投递排版。

## P5：素材与音效同步优化

目标：服务作品集展示和实机观感，不抢战斗设计主线。

允许做：

- 首批核心视觉资产预览：玩家、标准敌、精英核心、Boss Bastion、XP 球、基础弹道。
- 首批核心音效替换或制作：`shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot`。
- 演示视频需要的 UI / 结果页 / 战斗关键帧截图优化。

暂不建议做：

- 全量正式素材替换。
- 大规模 UI 主题重做。
- 把项目包装成美术或音频作品集。
- 为了素材好看牺牲战斗读局。

## P6：是否新增 Boss / 精英

暂时不建议立刻开做。

触发条件：

- `项目总览一页纸`、`战斗参数表`、`敌人设计表` 做完后，发现当前 Boss 或精英案例说服力不足。
- 演示视频脚本无法用现有 Boss / 精英讲清楚三路线答题方式。
- 当前硬数据不足以支撑作品集案例页。

如果满足上述条件，再考虑：

- 新增 1 个更考路线空间的 Boss。
- 新增 2 个分工明确的精英模板。

## 当前明确不做

- 不重写主流程。
- 不重写 `RunEngine`。
- 不扩成长线局外系统。
- 不做全套正式资产替换。
- 不把作品集做成几十篇文档合集。
- 不把 AI 协作文档当成核心卖点。

## 下一步推荐

1. 先由用户实机体验当前最新版本，重点观察路线是否需要多张牌才能成型、Boss/精英是否体现不同解法、画面是否仍有多余文字和线条。
2. 用户反馈后，由 Codex 先整理问题归因和代码骨架，再给 Kimi 输出定向开发提示词。
3. 只修实机暴露出的明确问题，不继续批量改数值、不继续重构异常系统。
4. 如果路线仍然 1 到 2 张牌就杀穿，优先回查 `upgrades.ts / contentSelectors.ts / RunEngine.ts` 的路线收益和触发条件。
5. 如果 Boss/精英仍像木桩，优先回查 `battleTemplates.ts / RunEngine.ts` 的护卫职责、阶段窗口、弱点与安全窗机制。
6. 如果画面仍乱，优先回查 `GameScene.ts` 的路线浮字、玩家周围线条、弹道拖尾和 Boss 遮罩。
7. 暂不继续作品集材料整理，暂不新增 Boss / 精英 / 路线。
