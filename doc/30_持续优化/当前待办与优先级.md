# 当前待办与优先级

## 更新时间

- `2026-04-29`

## 当前总判断

当前项目已经完成玩家反馈问题修复和一轮专项验收：音量面板、暂停继续、属性显示、拖尾、精英样本、素材黑底和音效层级已经基本可签收。

当前唯一没有闭环的关键项是 Boss 实机样本。Kimi 已尝试通过自然重开寻找 Boss，但 10 次重开仍未稳定触发 Boss，说明问题不再是“Boss 参数先不先改”，而是“缺少测试专用 Boss 强制触发入口”。下一步应先补 QA / debug 入口，稳定进入指定 Boss 模板，再判断 Boss 是否高压但可读。

正确方向仍然是双线并行：

- 游戏线：先补 Boss 定向 QA 入口，拿到可靠 Boss 样本，再根据样本结果做小步体验打磨。
- 作品集线：同步整理能证明设计能力的截图、短视频脚本和参数说明，而不是继续无限加内容。

## P0：Boss 强制触发 QA 入口

目标：让开发和验收不再依赖随机节点，能稳定进入 `boss-hunt`、`boss-bastion`、`boss-lockdown` 之一，并采集 Boss 安全窗、弹幕覆盖、受伤和结算数据。

必须完成：

- `npm run build`
- 新增或改造测试专用入口，允许 QA 脚本指定 Boss 模板。
- 至少强制触发 1 个 Boss，优先 `boss-bastion` 或 `boss-hunt`。
- 如果实现成本低，再覆盖 `boss-lockdown`。
- 采集 `bossSafeWindowMoments`、`bossFirelineCoverage`、Boss 战持续时间、玩家受伤次数、结算状态、console errors。
- 输出至少 1 张 Boss 战截图，用于人工判断安全窗与弹幕密度。
- 验证该入口不会影响正常玩家流程，默认不在普通游玩中开启。

重点看：

- Boss 是否从“不可躲”回到“高压但可读”。
- 安全窗是否真实出现，而不是只在参数表里存在。
- 弹幕覆盖是否仍会连续封死移动空间。
- Boss 压力是否足够，不会因为降密而变成无威胁。
- 入口是否是测试用最小接口，不污染主流程。

## P1：机制可读性小步补强

触发条件：P0 的 Boss 定向样本证明 Boss 仍然不可读、过密、过弱，或玩家仍然不知道“该躲哪里、什么时候反打”。

优先方向：

- Boss 不优先加弹幕密度，而是补阶段预警、安全窗提示、短暂弱点窗口、攻击后反打节奏。
- 精英当前已基本通过专项验收，不作为下一轮优先修复对象；除非新样本证明压迫失控，否则不继续改精英。
- UI 和文字不做长教程，优先补短句提示，例如“躲进缺口”“先拆护卫”“Boss 蓄力后可反打”。
- 音效不做大系统，优先区分预警、受伤、击杀、压力上升和 Boss 阶段变化。

验收重点：

- 玩家是否能在 1~2 次遭遇内理解精英和 Boss 的主要读法。
- Boss 压力是否来自“可读的攻击节奏”，而不是纯粹封满屏幕。
- 精英是否提供不同于普通怪的目标选择，而不是单纯更厚、更快。

## P3：作品集材料三件套

目标：把当前项目转成战斗策划作品，而不是继续做宽。

优先产出：

1. `项目总览一页纸`
2. `战斗参数表`
3. `敌人设计表`

为什么先做这三件：

- 它们能最早暴露“当前项目还缺哪些硬证据”。
- 它们能帮助判断是否真的需要新增 Boss 或精英。
- 它们比继续写大文档更接近可投递材料。

当前补充：

- `精英战案例页` 已经用于承接精英裂口与护卫拆解案例。
- `Boss战案例页` 已经用于承接 Boss 火线、安全窗与三路线答题案例。
- 下一步不是继续写长文，而是给这些材料补标注截图、短视频脚本和可投递排版。

## P4：素材与音效同步优化

目标：服务作品集展示和实机观感，不抢战斗设计主线。

允许做：

- 首批核心视觉资产预览：玩家、标准敌、精英核心、Boss Bastion、XP 球、基础弹道。
- 首批核心音效替换或制作：`shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot`。
- 演示视频需要的 UI / 结果页 / 战斗关键帧截图优化。

暂不建议做：

- 全量正式素材替换。
- 大规模 UI 主题重做。
- 把项目包装成美术或音频作品集。
- 为了素材好看牺牲战斗读局。

## P5：是否新增 Boss / 精英

暂时不建议立刻开做。

触发条件：

- `项目总览一页纸`、`战斗参数表`、`敌人设计表` 做完后，发现当前 Boss 或精英案例说服力不足。
- 演示视频脚本无法用现有 Boss / 精英讲清楚三路线答题方式。
- 当前硬数据不足以支撑作品集案例页。

如果满足上述条件，再考虑：

- 新增 1 个更考路线空间的 Boss。
- 新增 2 个分工明确的精英模板。

## 当前明确不做

- 不重写主流程。
- 不重写 `RunEngine`。
- 不扩成长线局外系统。
- 不做全套正式资产替换。
- 不把作品集做成几十篇文档合集。
- 不把 AI 协作文档当成核心卖点。

## 下一步推荐

1. 先让 Kimi 补“测试专用 Boss 强制触发入口”，不要靠随机路线碰 Boss。
2. 用该入口至少验证 `boss-bastion` 或 `boss-hunt`，产出截图和 debug 数据。
3. 如果 Boss 可读性通过，再进入作品集 Boss 案例截图和短视频脚本。
4. 如果 Boss 不可读，再只针对 Boss 的预警、安全窗、弱点窗口或弹幕节奏做小步修复。
