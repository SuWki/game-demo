> 在 AI 参与度很高、本人掌控度还不够满的前提下，怎么把这个项目整理成一套可信、稳妥、可展示的面试方案。

## 总流程

后续按 4 个阶段推进，不要跳。

### 阶段 1：重建项目掌握

目标：

把项目从“AI 做出来的结果”重新变成“你自己能解释的作品”。

这一步要完成的不是背代码，而是补下面 5 类东西：

1. `项目定位`
   - 它是什么
   - 它不是什么
   - 为什么适合投执行 / 系统 / 战斗策划

2. `核心循环`
   - 为什么是手动走位 + 自动攻击
   - 为什么是一局五轮短局
   - 为什么是节点推进 + 三选一强化

3. `成长结构`
   - 为什么是 `crit / pierce / dash`
   - 为什么路线要分 `starter / bridge / payoff / finisher`
   - 为什么路线不能一张牌成型

4. `敌人与 Boss 出题`
   - 精英在考什么
   - Boss 的安全窗 / signature 在考什么
   - 为什么它们不是更厚血的小怪

5. `验证逻辑`
   - 你是怎么判断一个问题存在的
   - 你改了哪里
   - 你怎么验
   - 结果是什么
   - 还有什么没解决

这一阶段的完成标准：

- 你不用看代码，也能把上面 5 类问题讲成完整句子
- 面试官追问“为什么这样设计”时，你不会只回答“AI 这么写的”

### 阶段 2：收展示材料

目标：

只收你讲得明白的展示材料，不做“大而全”的作品集。

本阶段只保留 5 类材料：

1. `项目总览一页纸`
2. `三路线 showcase`
3. `1 个精英案例`
4. `1 个 Boss 案例`
5. `当前 QA 摘要`

材料筛选原则：

- 优先保留当前 HEAD 对得上的产物
- 优先保留你能解释“问题 -> 修改 -> 验证 -> 收益”的案例
- 不收只好看、但你讲不清的图
- 不收历史太老、和当前版本脱节的截图

### 阶段 3：做面试讲法

目标：

把材料压缩成你能稳定说出口的几套话。

至少准备 4 套：

1. `30 秒版本`
2. `1 分钟版本`
3. `3 分钟版本`
4. `AI 协作追问版本`

这一步的重点不是文采，而是边界稳定。

你必须能稳定讲清：

- 项目目标是什么
- 你做了什么
- AI 做了什么
- 你怎么判断方案好坏
- 当前项目最大的不足是什么

### 阶段 4：追问演练

目标：

把最危险的问题先练掉。

优先练这 8 类：

1. 这个项目到底是不是 AI 做的？
2. 你本人到底负责什么？
3. 为什么要自动攻击，不做手动射击？
4. 为什么是一局五轮？
5. 为什么是这三条路线？
6. 为什么 Boss 要做安全窗 / signature？
7. 你怎么证明这些修改有效？
8. 如果继续做，下一步做什么？

这一阶段的标准不是“回答完美”，而是：

- 不虚
- 不绕
- 不夸大
- 不把自己逼进代码细节死角

## 你现在必须掌握的内容

按优先级分两层。

### 第一层：必须掌握

这些是面试一定会问，必须先拿下。

1. `项目一句话定位`
   - 短局动作构筑原型
   - 不是成熟商业产品
   - 重点展示系统设计、规则约束、验证闭环

2. `核心循环为什么这样搭`
   - 手动走位 + 自动攻击
   - 五轮短局
   - 节点推进
   - 三选一强化

3. `三路线分别解决什么`
   - `crit`：单点压杀、连压兑现
   - `pierce`：找线、拆线、打后排
   - `dash`：贴近、换位、借窗回打

4. `路线为什么要分阶段`
   - starter 让玩家看到方向
   - bridge 让路线开始成立
   - payoff 让打法明显变化
   - finisher 让收口成立

5. `Boss 为什么这么做`
   - 安全窗是让难度可读，不是降难度
   - signature 是战场记忆点，不是单纯开招提示
   - Boss 要像毕业检定，不是厚血小怪

6. `AI 协作边界`
   - AI 负责大量实现、整理、脚本与素材生成
   - 你负责目标定义、问题判断、规则取舍、验收复盘

### 第二层：需要补掌握

这些不一定开场问，但会决定你能不能扛住深追问。

1. 当前模块大结构
   - `RunEngine`
   - 路线推进相关模块
   - UI / Overlay
   - 数据表层

2. 当前固定验证流程
   - `npm run export:data`
   - `npm run build`
   - `npm run preview -- --host 127.0.0.1 --port 4173`
   - `npm run qa:stable-smoke`
   - `node tools/qa-smart-natural-fullrun.mjs`

3. 你手上最重要的 QA 证据是什么
   - stable smoke 证明什么
   - natural fullrun 证明什么
   - 哪些图是 directed sample
   - 哪些图是 natural sample

4. 当前版本的边界
   - 强项是什么
   - 不足是什么
   - 为什么它仍然适合作为求职作品

## 为什么要按这个流程，而不是直接做作品集

因为你现在的真实风险不在“材料不够好看”，而在“你可能讲不过自己材料里的内容”。

如果直接做作品集，常见后果是：

1. 材料写得很满，但你答不出推导过程
2. 一被追问 AI 参与度，整套口径就散
3. 一被追问代码或验证方法，就会退回“这是 GPT 改的”

所以必须先做掌握，再做展示。

这也是你当前项目和普通独立作品最大的区别。

## 面试时必须守住的边界

### 可以大方承认的

1. 项目是 AI 高参与协作开发
2. 代码、素材、音效都有 AI 参与
3. 你不是在证明自己是纯程序或纯美术

### 必须稳住的

1. 你主导了项目方向
2. 你主导了问题判断
3. 你主导了规则约束和验收标准
4. 你知道当前版本强在哪、弱在哪

### 不要说的

1. “这个我也不太清楚，反正 GPT 改出来了”
2. “具体为什么这样我忘了”
3. “我基本没做什么，就是让 AI 写”

更稳妥的说法是：

> AI 参与度很高，但我把重点放在策划更核心的部分：定义目标、拆问题、定约束、验结果、做取舍。对我来说，这个项目的价值不是证明我手写了多少代码，而是证明我能不能把一个战斗原型持续收成可验证、可展示、可复盘的作品。
