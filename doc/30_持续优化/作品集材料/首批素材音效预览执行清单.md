## 文档状态

- 状态：`作品集辅助材料 / 初稿`
- 目标：服务演示视频和实机观感，不扩大成完整资产替换工程
- 上游口径：`doc/40_AI协作/完整素材提示词体系.md`、`doc/40_AI协作/预览出图提示词_首批.md`
- 最新输出：`output/asset-preview/index.html`

## 当前原则

素材和音效可以与作品集同步推进，但必须服从战斗策划展示：

- 先让画面读局更清楚。
- 先让视频截图更有说服力。
- 先替换最影响识别的对象。
- 不为了“更好看”牺牲敌弹、XP、危险圈和路线差异。
- 所有可接入图像必须是透明背景；黑底图层、展示底板、整张矩形背景一律不能进入运行时。

### 透明背景验收

- 预览素材可以放在深色底板上做可读性检查，但最终接入 `public/assets/preview-runtime/visual/` 的文件必须是透明背景。
- 如果源文件来自 `output/asset-preview/visual/`，接入前必须检查并移除黑色背景矩形或黑色底层。
- 玩家、敌人、精英、Boss、弹道、XP、Boss 火线、安全窗都必须满足该规则。
- 透明背景检查不通过时，不允许用代码层混合模式或缩放遮掩问题，必须先修素材。

## 本轮不做

- 不全量替换所有 UI。
- 不做完整动画帧表。
- 不做大规模正式音频接线。
- 不新开资源加载系统。
- 不用素材替换掩盖战斗读局问题。

## 执行顺序

1. 先出玩家、标准敌、XP 球三张图像预览。
2. 用当前战斗截图做静态合成判断：是否清楚、是否混淆。
3. 再出精英核心和 Boss Bastion。
4. 同步试听 `shoot / hit / kill / pickup / hurt` 五个核心音效。
5. 通过 A/B 观察后，再决定是否进入实际资源替换。

## A/B 检查方式

每个预览资产都先做静态或试听检查，不直接替换进主分支。

建议记录：

| 字段 | 说明 |
| --- | --- |
| 资产 ID | 例如 `unit-player-core` |
| 批次 | 1 / 2 / 3 |
| 版本 | v1 / v2 / v3 |
| 是否通过轮廓检查 | 是 / 否 |
| 是否通过颜色检查 | 是 / 否 |
| 是否通过战斗读局检查 | 是 / 否 |
| 问题 | 例如太像敌弹、太写实、太暗、细节太碎 |
| 结论 | 进入替换 / 继续改提示词 / 放弃 |

## 验收输出

每个预览资产至少记录：

- 文件名或生成批次。
- 使用提示词版本。
- 是否通过读局检查。
- 是否适合进入实际替换。
- 如果不通过，原因是轮廓、颜色、层级、还是风格不对。

## 2026-05-01 透明背景硬规则补充

用户明确反馈：图片素材不能带黑色背景。后续所有生成和接入都按以下规则执行：

- 图像生成提示词必须明确写入 `transparent background / 透明背景 / no background plate`。
- 负面提示词必须包含 `black background, dark rectangle background, white background, presentation board, full-frame backdrop`。
- 接入前必须打开文件检查是否存在背景层，尤其是 SVG 内的全画布 `rect`。
- 若素材主体需要暗部，只能保留在主体轮廓内，不能保留整张黑色画布。
- 运行时接入顺序优先：先透明化并复制到 `public/assets/preview-runtime/visual/`，再改 `BootScene / GameScene`。
