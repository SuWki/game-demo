以下提示词用于交给 `5.4 high` 继续开发，目标是提升项目的第一眼观感和求职展示效果，限制为 **不大改玩法主逻辑，不重新开系统，不把逻辑堆回 RunEngine.ts**。

当前仓库前置事实：

- 项目页 `project.html` 已删除，不再继续维护单独项目页。
- `vite.config.ts` 已恢复为普通单入口，不再保留 `project.html` 多入口构建。
- 当前展示主线应围绕游戏本体、README 和视频/截图素材展开。
- 当前固定验证流程仍然是：`npm run export:data -> npm run build -> npm run preview -- --host 127.0.0.1 --port 4173 -> npm run qa:stable-smoke -> natural fullrun`

## 提示词 1：三路线视觉身份拉开

```text
你现在在 E:\codex\auto-shooter-demo 仓库里继续开发。

本轮目标：在不大改玩法和系统结构的前提下，把三条路线的视觉身份再拉开一档，让玩家和招聘方在第一眼就能区分 crit / pierce / dash，不再主要依赖文字解释才能看懂差异。

硬约束：
1. 不新增新系统，不重做战斗主循环，不把路线主逻辑塞回 RunEngine.ts。
2. 优先做低风险展示增强：颜色、chip、关键特效、UI 标识、结果页路线标记、升级卡小视觉线索。
3. 三条路线的视觉口径要稳定统一：
   - crit = 单点爆发 / 收口 / 重击感
   - pierce = 直线穿透 / 裂纹 / 打穿整列
   - dash = 贴近 / 换位 / 回打 / 残影
4. 不要做成花哨的大改版，重点是“更容易读懂”和“更像三种不同玩法”。
5. 玩家可见文本不要回到设计说明腔。

建议优先检查和修改这些位置：
- src/ui/OverlayController.ts
- src/systems/RunEngine.ts
- src/systems/route/RouteProgression.ts
- src/scenes/GameScene.ts
- 与路线视觉表现相关的 data / ui / combat 文件

建议实施方向：
1. 给三路线的 HUD route chip、路线提示、结果页路线标记统一配色和小图形差异。
2. 强化三路线各自最关键的战斗瞬间：
   - crit：暴点、重击、收口时更有压中目标的感觉
   - pierce：打穿、连线、裂纹传播时更明显
   - dash：贴近回打、残影、位移后反击更明显
3. 升级页、异常页、结果页里与路线相关的局部视觉提示更统一，避免“战斗里一套、页面里另一套”。
4. 结果页要更容易一眼看出这局到底是哪条路线成型。

交付要求：
1. 直接修改代码，不只给方案。
2. 跑最少必要验证：
   - npm run build
   - npm run qa:stable-smoke
3. 如果适合，再补 1 组最能说明三路线差异的截图产物路径。
4. 最终返回时按下面格式：

改动文件
每个文件改了什么
这轮解决了什么问题
还剩什么问题
验证结果
截图或产物路径
提交信息
推送结果

注意：
- 不要把“视觉身份拉开”做成纯文案轮。
- 不要引入大规模新资源依赖。
- 保持现有 QA 链路可继续跑通。
```

## 提示词 2：Boss 开场压轴感增强

```text
你现在在 E:\codex\auto-shooter-demo 仓库里继续开发。

本轮目标：增强 Boss 战开场的压轴感和展示效果，让求职视频和首次上手时更容易感到“这一局进入最终检定了”。重点是开场、转场、signature 出现时的戏剧性，不是重做 Boss 机制。

硬约束：
1. 不大改 Boss 核心玩法，不新增复杂新阶段，不重开 Boss 平衡专项。
2. 只做轻量但有效的表现增强：标题、短停顿、屏幕压暗、音画强调、护卫/安全窗提示读感。
3. 不要让表现增强影响 smoke 回归稳定性，也不要把 Boss 页面做成说明文档。
4. 不要为了“炫”而牺牲可读性。

建议优先检查和修改这些位置：
- src/systems/RunEngine.ts
- src/ui/OverlayController.ts
- src/scenes/GameScene.ts
- src/data/battleTemplates.ts
- 与 Boss HUD、Boss signature、safe window、battle intro 相关的文件

建议实施方向：
1. Boss 开战时做一层更明确的“进入最终战”表现：
   - 简短但有分量的标题
   - 短暂停顿 / 压暗 / 镜头或屏幕强调
   - 不要太长，避免拖节奏
2. Boss 护卫和安全窗的读感更明确：
   - 玩家更容易知道现在是在“先处理护卫”还是“争取输出窗”
   - 但不要回到指导腔
3. Boss signature 出现时，视觉或音效上更像一个明确阶段点。
4. 结果页如果有 Boss 相关总结句，可以顺手收紧成更像“检定结论”的说法。

交付要求：
1. 直接改代码，不只提建议。
2. 跑最少必要验证：
   - npm run build
   - npm run qa:stable-smoke
3. 如果能稳定补到 Boss 相关截图或产物，优先保留：
   - boss-signature.png
   - 结果页或 Boss 开场相关截图
4. 最终返回时按下面格式：

改动文件
每个文件改了什么
这轮解决了什么问题
还剩什么问题
验证结果
截图或产物路径
提交信息
推送结果

注意：
- 这是展示增强，不是新一轮 Boss 系统设计。
- 不要把改动扩散成一整轮音频或战斗平衡重做。
```
