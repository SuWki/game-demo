## 四、这个项目为什么要这样设计

这部分是面试中最重要的“设计解释能力”。

### 1. 为什么做“短局 + 节点推进 + 自动射击”

#### 设计原因

目标不是做长线养成，也不是做纯硬核操作射击。  
目标是做一个：

- 进入快
- 反馈快
- 方便连续重开
- 能清楚体现构筑差异

#### 好处

- 短局：更适合体验 build 差异
- 节点推进：让战斗外选择也成为玩法内容
- 自动射击：把操作重点转移到走位、节奏、路线判断

#### 面试可讲版本

我没有把核心放在手动瞄准，而是故意把攻击自动化，把玩家操作价值集中到走位、时机和构筑判断上，这更适合构筑驱动的短局原型。

### 2. 为什么是三条路线：crit / pierce / dash

#### 设计原因

三条路线不是三种不同颜色的伤害加成，而是三种不同的战斗逻辑：

- `crit`：抓窗口、集中爆发、收尾更快
- `pierce`：清线、拆后排、处理群体压力
- `dash`：位移、反击、把规避转成收益

#### 好处

这样做的优点是：

- 路线差异不仅在数值上
- 玩家实际打起来会觉得思路不同
- 更能体现“构筑”而不是“属性堆叠”

### 3. 为什么要分 starter / bridge / payoff / finisher

#### 设计原因

成长不能只表现为“越来越强”，玩家必须感知到阶段变化：

- 我有方向了
- 我开始成型了
- 我能打穿了
- 我开始收尾碾压了

#### 好处

- 玩家知道自己现在缺哪一块
- 重开时有明确目标
- 结果页能更好解释输赢

### 4. 为什么异常节点必须进入 build 体系

#### 设计原因

异常节点如果只是额外奖励，存在感会很弱。  
它应该承担：

- 锁方向
- 补核心
- 做质变

#### 好处

- 玩家会记住“这一局是从这里开始胡的”
- 异常节点真正承担局势转折功能

### 5. 为什么 Boss 不该只是厚血怪

#### 设计原因

Boss 应该是对玩家整局 build 与操作理解的考试。

#### 好处

- 没胡的局会觉得难
- 成型局会觉得能打
- 胡牌局会明显更短、更顺、更稳

### 6. 为什么脚本 QA 不能替代玩家体验

#### 设计原因

脚本能测：

- 能不能通关
- 会不会超时
- 哪些节点更容易死人

但脚本测不到：

- 玩家读不读得懂
- 玩家有没有操作空间
- build 有没有胡起来的爽感

#### 好处

明确这一点，说明项目判断不是只靠数值脚本，而是有体验判断。

## 五、这个项目的优点在哪里

### 1. 它不是只做了表面功能

项目包含：

- 核心玩法循环
- 三条路线
- Boss / 精英设计
- 数据驱动
- 配置工具
- QA 脚本
- 多轮复盘与回滚

这说明它不是单纯的展示 Demo，而是一个持续验证的系统原型。

### 2. 它有真实的问题定位过程

项目中经历过：

- 误以为只是平衡问题
- 后来发现脚本 QA 不能替代手感判断
- 再后来发现旧稳定线并没有被固化成干净快照
- 最终区分出“可信验证基线”和“可玩基线”

这很值钱，因为真实项目最重要的能力之一，就是找到真正的问题，而不是一直修表面症状。

### 3. 它体现了取舍能力

这个项目不是一路只加东西，而是持续做取舍：

- 先修 404，而不是继续调体验
- 先恢复可信基线，而不是继续做新功能
- 先恢复可玩基线，再谈胡牌专项

这种取舍能力比“功能做得多”更重要。

### 4. 它体现了策划与工程协作理解

项目中能够清楚看到：

- 数据驱动玩法如何接入
- QA 如何服务设计判断
- 版本管理失控会如何影响验证
- 契约一致性为何比“少改文件”更重要

这比只会写需求、更接近真实项目协作。

## 七、作为求职项目，你必须掌握哪些

下面分成两部分：游戏 demo 与数据表配置平台。

### A. 游戏 demo 必须掌握的

#### 1. 玩法定位与核心循环

必须能讲清：

- 项目是什么
- 为什么是短局自动射击
- 节点推进的价值是什么
- 一局的核心循环如何运转

#### 2. 三路线设计

必须能讲清：

- `crit / pierce / dash` 各自的设计目标
- 三者为什么不是简单的属性差异
- 路线为什么要区分玩法逻辑

#### 3. 构筑阶段设计

必须能讲清：

- 为什么要分 `starter / bridge / payoff / finisher`
- 怎么判断一局是普通局、成型局还是胡牌局
- build 为什么不能只是越来越强

#### 4. 异常节点设计

必须能讲清：

- 为什么异常节点不能只是额外奖励
- 它在 build 中承担什么功能
- 为什么它应当成为局势转折点

#### 5. Boss / 精英出题

必须能讲清：

- Boss 与精英各自考什么
- 安全区、瞄准线、护卫、输出窗各自解决什么问题
- 为什么 Boss 不应该只是厚血怪

#### 6. 验证方法

必须能讲清：

- QA 脚本看什么
- 为什么脚本不能代替玩家体验
- 怎么看通关率、Boss 到达率、超时、失败节点

#### 7. 技术协作理解

必须能讲清：

- `RunEngine` 大致负责什么
- `OverlayController` 负责什么
- `src/data/*` 如何驱动玩法
- 为什么 `nodes / battleTemplates / RunEngine / types` 耦合很深

### B. 数据表配置平台必须掌握的

#### 1. 平台解决什么问题

必须能讲清：

#### 2. 数据结构设计

必须能讲清：

- 字段

- 默认值
- 校验
- 关联关系

#### 3. 编辑体验设计

必须能讲清：

- 为什么要做筛选
- 为什么要做备注

#### 4. 工程与流程意识
