## 项目一句话

一个基于 `Phaser + TypeScript + Vite` 的 8~12 分钟短局自动射击 Roguelite 原型，核心目标是验证“手动走位 + 自动攻击 + 节点推进 + 战斗内成长”能否支撑三条可读、可复玩的战斗路线，并在精英与 Boss 压力下形成明确的战斗答题。

## 项目定位

这不是系统商业化样本，也不是 UI / 美术 / 音频作品集。

它的展示重点是：

- 战斗回报链：击杀、掉落、吸附、升级、继续追击是否顺。
- 三路线读感：`crit / pierce / dash` 是否在实战中形成不同打法。
- 精英 / Boss 压力设计：中段和终局是否不是“更厚的普通战”。

## 核心玩法

玩家控制机体手动走位，武器自动攻击。每局通过节点推进进入普通战、精英战、生存战、异常事件、强化选择和最终 Boss。战斗中通过击杀敌人拾取 XP，获得升级，并逐步形成三条路线之一：

- `crit`：短窗爆发、热区收束、连续命中后的集中兑现。
- `pierce`：拆线、贯穿、拉轨、清屏和回收。
- `dash`：换位、擦身、借窗、回切反打。

## 我的职责

- 定义短局战斗体验目标和核心循环。
- 设计三条战斗路线的路线语义、成长节奏和后段 payoff。
- 设计普通敌、精英、Boss 的战斗职责和压力结构。
- 组织文档、参数、验证字段和开发提示词，推动原型小步落地。
- 通过自然样本、定向样本、full-flow 回归和 debug 字段复检设计是否成立。

## 解决过的关键问题

### 1. 普通战不只是刷怪

把普通战目标压到“击杀 -> 掉落 -> 吸附 -> 升级 -> 继续追击”的回报链上，避免玩家只是在场上绕圈等自动攻击。

### 2. 路线不只存在于面板

把 `crit / pierce / dash` 的差异落到战场读法、音效声纹、短窗口和 Boss / 精英承接上，而不是只靠升级文字说明。

### 3. 精英和 Boss 不只是更厚

精英战强调“护卫成屏 -> 裂口 -> 追本体”，Boss 战强调火线、安全窗、阶段压力和路线答题。

## 验证方式

- `npm run build`：确认类型和构建不坏。
- full-flow：菜单 -> 战斗 -> 节点 / 升级 / 异常 / 整备 -> Boss -> 结算 -> 重开。
- 自然样本：观察普通玩家路线下的战斗节奏和中断点。
- 定向样本：复检精英裂口、Boss 火线、安全窗和路线 payoff。
- debug 字段：`eliteCrackSeen`、`eliteCrackFollowThroughMoments`、`bossFirelineCoverage`、`bossSafeWindowMoments`、`killPickupContinueMoments` 等。

## 当前版本结论

- 核心流程已经可跑通并能到达结算。
- `crit / pierce / dash` 已经具备基础差异。
- 精英裂口和 Boss 火线已有监控字段和定向样本。
- 系统收口基础能力已经接上：暂停、音量、重开、结果页数据。
- 当前仍需继续复检自然样本，尤其是第 2~3 节点的节奏中断和路线高光稳定度。
