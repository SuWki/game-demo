# 2026-06-17 showcase 展示整理与面试材料框架

## 文档定位

- 状态：`P2-1 准备框架 / 待执行`
- 对应阶段：`P2-1：展示整理与面试材料`
- 依赖前提：`P2-0：showcase 验证链修复与阶段文档同步` 先通过
- 用途：把后续展示整理和面试准备拆成一套可执行框架，避免临时想做什么就做什么

## 先说结论

这一阶段不是继续补玩法，也不是继续大修文案。

这一阶段要做的，是把当前版本整理成一套可以：

1. 给人快速看懂
2. 给人留下记忆点
3. 经得起面试追问
4. 能证明你有战斗策划判断力

的展示材料。

## 一、这阶段最终要交付什么

建议把最终交付控制在 `5 + 1`：

1. `项目总览一页纸`
2. `路线 showcase 材料`
3. `Boss / 精英案例材料`
4. `QA 验证摘要`
5. `面试讲法提纲`
6. `1 个可演示版本入口`

不要再扩成十几份松散文档，也不要把所有历史复盘直接塞给面试官。

## 二、每份材料分别要包含什么

### 1. 项目总览一页纸

目标：让第一次看项目的人，在 `1` 页内知道这是什么、你做了什么、为什么值得看。

必须包含：

1. 项目一句话
2. 核心玩法循环
3. 三条路线分别在打什么
4. 精英 / Boss 在验证什么
5. 你的职责边界
6. 验证方式
7. 当前版本结论

不该写成：

- 开发流水账
- 功能清单
- 技术栈介绍页

### 2. 路线 showcase 材料

目标：证明 `crit / pierce / dash` 不是三套换色数值，而是三种不同战斗读法。

每条路线至少要有：

1. `一句话定位`
2. `starter -> bridge -> payoff` 的成型链
3. `战斗内最值得记住的 1 个画面`
4. `结果页复盘怎么对应战斗过程`
5. `成功局 or 失败局` 至少一套可讲样本

推荐结构：

- `crit`：怎么从压单点走到压爆
- `pierce`：怎么从找线走到打穿
- `dash`：怎么从贴近走到回打收人

路线材料里不要堆太多卡牌名。重点是讲：

- 玩家看到了什么
- 玩家为什么会这样打
- 这一套为什么成立

### 3. Boss / 精英案例材料

目标：证明你不只是做了路线，还做了敌人出题。

至少准备两类案例：

1. `精英案例`
   - 压力来源是什么
   - 裂口在哪里
   - 玩家反打窗口怎么形成

2. `Boss 案例`
   - 这一段 signature 在考什么
   - 安全窗 / 火线 / 护卫干扰怎么配合
   - 为什么它不是“血更厚的小怪合集”

每个案例都尽量用同一套结构：

1. 原问题
2. 修改点
3. 验证方式
4. 结果
5. 还剩什么边界问题

### 4. QA 验证摘要

目标：证明这些展示不是摆拍，而是当前 HEAD 可复现。

必须包含：

1. 固定验证流程
2. 当前可用 QA 产物路径
3. stable smoke 结果
4. natural fullrun 结果
5. 当前版本已知限制

这份材料不是给面试官细看脚本，而是给你自己和面试场景兜底：

- 你说的东西能不能被复现
- 哪些是定向样本
- 哪些是自然样本

### 5. 面试讲法提纲

目标：把“我做了很多东西”压成几段真正能说清的表达。

至少要准备 4 个版本：

1. `30 秒版本`
2. `1 分钟版本`
3. `3 分钟版本`
4. `追问版本`

追问版本至少覆盖：

1. 为什么做自动攻击而不是手动射击
2. 为什么要三路线
3. 为什么 Boss 用安全窗 / signature，而不是单纯堆血和弹幕
4. 你怎么验证这些改动有效
5. AI 在项目里做了什么，你本人做了什么
6. 当前项目最大不足是什么

### 6. 可演示版本入口

目标：当场真要演示时，不会临时找不到入口。

至少明确：

1. 当前演示 URL 或本地启动方式
2. 推荐演示顺序
3. 如果现场时间很短，先演哪一条路线
4. 如果现场网络或环境不好，退化成看哪些截图和结果页

## 三、展示阶段需要准备哪些具体素材

建议按下面 5 类收：

### 1. 截图

至少要有：

1. 首页
2. 升级页
3. `crit` bridge / payoff
4. `pierce` bridge / payoff
5. `dash` bridge / payoff
6. Boss signature
7. 成功局结果页
8. 失败局结果页
9. 结果页详情

### 2. 视频片段

至少准备：

1. `15~30 秒` 总览片段
2. 三路线各 `10~20 秒` 高光
3. `Boss` 一段 signature
4. 一段结果页收尾

### 3. 结果页讲法

不是只放截图，而是要有对应讲法：

1. 这局走了哪条路线
2. 成型到了哪一步
3. 为什么赢 / 为什么输
4. 这一页如何对应前面的战斗过程

### 4. QA 证据

至少整理出：

1. 当前 stable smoke 的 `summary.json`
2. 当前 natural fullrun 的 `summary.json`
3. 关键 showcase 图的目录索引

### 5. 版本说明

至少能明确：

1. 当前展示版本基于哪个 commit
2. 当前有哪些已知问题
3. 哪些画面是自然样本
4. 哪些画面是定向样本

## 四、面试时你必须掌握的点

这部分比截图本身更重要。

### 1. 你要能讲清项目定位

你必须能稳定说清：

- 这是一个 `短局动作构筑战斗原型`
- 不是完整商业游戏
- 展示重点是 `战斗回报链 / 三路线读感 / 精英与 Boss 出题`

### 2. 你要能讲清三路线差异

不要只说：

- crit 是暴击
- pierce 是穿透
- dash 是位移

要讲成：

- `crit` 解决的是单点压杀和连续兑现
- `pierce` 解决的是找线、拆线、打后排
- `dash` 解决的是贴近、换位、借窗回打

### 3. 你要能讲清敌人设计不是背景板

至少能讲：

- 精英为什么需要裂口
- Boss 为什么需要 signature / 安全窗
- 小怪、护卫、Boss 本体如何分工

### 4. 你要能讲清验证逻辑

不能只说“我感觉更好了”。

必须能讲：

1. 我怎么定义问题
2. 我改了哪里
3. 我怎么验
4. 验出来是什么
5. 哪些还没有完全解决

### 5. 你要能讲清 AI 协作边界

这点必须提前准备，不然很容易被追问打散。

建议稳定口径：

1. AI 参与代码实现、文档整理、QA 脚本和批量执行
2. 你本人负责问题判断、设计目标、规则约束、修改取舍、验收结论
3. 展示重点不是“我写了多少代码”，而是“我能不能把一个战斗原型持续改到可验证、可展示、可讲清”

### 6. 你要能讲清当前版本的边界

不要硬装成成品。

要能直接承认：

1. 这更像一个战斗策划原型，不是商业完成品
2. 当前强项是设计闭环和验证意识
3. 当前短板可能在内容量、资产完成度、自然样本稳定度

## 五、这一阶段的推荐执行顺序

前提：`P2-0` 验证链先修好。

然后按这个顺序走：

1. 固定当前可用 QA 产物目录
2. 选每条路线最能打的 1 张图和 1 段片
3. 选 1 个精英案例和 1 个 Boss 案例
4. 补项目总览一页纸到当前版本
5. 写 30 秒 / 1 分钟 / 3 分钟讲法
6. 再回头补简历版和面试追问版

## 六、这阶段不要做什么

1. 不要重新开一轮旧玩法微调
2. 不要把所有历史 QA 图都塞进材料
3. 不要把项目包装成 UI、美术或音频作品集
4. 不要把材料写成十几篇大长文却没有可展示入口
5. 不要回避 AI 协作问题

## 七、完成标准

做到下面这些，才算 `P2-1` 真正进入可执行状态：

1. 你能在 `1` 分钟内讲清项目
2. 你能在 `3` 分钟内讲清一条路线和一个 Boss 案例
3. 你手里有一套当前 HEAD 对得上的截图和 QA 摘要
4. 你知道哪些画面是自然样本，哪些是定向样本
5. 面试官追问“为什么这么设计”“怎么验证”“AI 做了多少”时，你都能答
