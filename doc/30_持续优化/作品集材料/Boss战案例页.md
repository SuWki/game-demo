# Boss 战案例页

## 文档状态

- 状态：`作品集材料 / 初稿`
- 案例主题：如何让 `crit / pierce / dash` 在 Boss 身上被考出来
- 推荐展示对象：`boss-bastion`

## 一句话案例

Boss 不应该只是普通战或精英战的加长版，而应该是整局 build 的最终检定：通过火线、安全窗、护卫和阶段压力，让三条路线在同一个终局场景中产生不同答题方式。

## 初版问题

早期 Boss 容易出现的问题：

- Boss 只是更厚、更久、更吵。
- 阶段变化有逻辑，但玩家不一定能读出“现在考什么”。
- 三路线在 Boss 上容易变成同一种做法：绕圈、等自动攻击、拼血量。
- 火线和护卫如果只是增加弹幕，会压掉路线表达。

## 设计目标

让 Boss 成为最终战斗题：

1. 每个 Boss 有独立主压力。
2. 每个阶段不是单纯数值变化，而是场面读法变化。
3. 三路线有不同过题方式。
4. 压力足够强，但必须给可读安全窗。

## 当前 Boss 分工

| Boss | 主压力 | 更贴近路线 | 设计读法 |
| --- | --- | --- | --- |
| `boss-hunt` | 正面追猎和压线 | `crit` | 抓短窗，集中爆发 |
| `boss-lockdown` | 锁域、压边、换侧 | `dash` | 借压迫换位，回切反打 |
| `boss-bastion` | 护卫、屏卫、远程火线 | `pierce` | 拆屏、清线、找安全窗 |

当前最适合做作品集案例的是 `boss-bastion`，因为它的火线覆盖和安全窗已经有比较清楚的数据支撑。

## 修改思路

### 1. Boss 不是更厚，而是出题

`boss-bastion` 的题目不是“打掉高血量本体”，而是：

- 先读火线迁移。
- 再识别安全口袋。
- 通过护卫和火线之间的空档寻找输出窗口。

### 2. 安全窗是公平性的关键

火线越强，越需要玩家能看见安全窗。

如果只有火线，没有安全窗，Boss 会显得不公平；如果安全窗太宽，Boss 又会失去终局压力。

### 3. 三路线在同一压力下有不同解法

- `crit`：在安全窗中抓短时间爆发。
- `pierce`：拆掉屏卫和成线敌人，维持输出路径。
- `dash`：借火线迁移换边，利用短窗回切。

## 实际落地内容

| 模块 | 落地内容 | 设计作用 |
| --- | --- | --- |
| Boss 模板 | `boss-hunt`、`boss-lockdown`、`boss-bastion` | 三种终局压力分工 |
| 火线压力 | `bossFirelineCoverage` | 衡量火线是否成为主压力 |
| 安全窗 | `bossSafeWindowMoments` | 衡量强压力下是否仍有可读机会 |
| 危险音效 | `pressure / enemyShot / nearMiss / hurt` | 区分压迫、来袭、擦边、受击 |
| 结果页数据 | 战斗胜场、推进节点、路线阶段、结局原因 | 服务作品集视频结尾展示 |

## 当前样本证据

样本来源：`output/playwright/stability-round25/boss-fireline-targeted-v4/summary.json`

| 指标 | 当前值 | 说明 |
| --- | ---: | --- |
| `bossFirelineCoverage` | `0.91` | 火线覆盖率足够高，能形成 Boss 主压力 |
| `bossSafeWindowMoments` | `5+` | 火线压力下仍存在安全窗 |
| `pressure` | `7` | 压力 cue 存在 |
| `enemyShot` | `45` | 敌方火线建立频繁 |
| `nearMiss` | `59` | 擦边风险高，说明火线确实接近玩家 |
| `hurt` | `0` | 定向样本中玩家未受伤，说明高压不等于必伤 |
| `firelineDetected` | `true` | 样本检测到火线结构 |

当前版本 QA 样本：

- `output/qa/current-version/summary.json`
- `resultSeen=true`
- 样本死于 `追猎首领阶段中机体耐久归零`

这说明当前终局压力仍然足够强，但需要再补一个胜利或稳定过关样本，避免作品集只展示失败结尾。

## 当前结论

已经能初步证明：

- `boss-bastion` 可以作为 Boss 案例核心。
- 火线覆盖不是主观描述，已有 `bossFirelineCoverage=0.91` 支撑。
- 安全窗不是文档设想，已有 `bossSafeWindowMoments=5+` 支撑。
- Boss 设计可以被讲成“压力模式 + 公平窗口 + 路线答题”。

暂时不能过度宣称：

- 三路线在 Boss 上已经同等成熟。
- 所有 Boss 都已形成清楚签名。
- 自然样本下玩家都能稳定读到安全窗。

## 作品集展示结构

### 1. 问题

Boss 容易退化成更厚、更吵、更久的普通战。

### 2. 改法

给 Boss 定义主压力：`boss-bastion` 用火线、护卫和安全窗构成终局题。

### 3. 验证

用 `bossFirelineCoverage` 和 `bossSafeWindowMoments` 证明火线和安全窗都真实出现。

### 4. 结论

当前 `boss-bastion` 足以作为作品集 Boss 案例主角，但需要补三路线对比片段和至少一个胜利样本。
