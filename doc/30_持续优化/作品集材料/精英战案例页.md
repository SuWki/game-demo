# 精英战案例页

## 文档状态

- 状态：`作品集材料 / 初稿`
- 案例主题：如何让“先拆护卫，再追本体”成立
- 推荐展示对象：`elite-screen`、`elite-vice`

## 一句话案例

精英战不应该只是“更厚的普通怪”，而应该成为中段小高潮：玩家先面对护卫和火线形成的屏障，拆开结构后看到裂口，再顺着窗口追击本体。

## 初版问题

早期精英战的主要问题不是逻辑缺失，而是体验读法不稳定：

- 精英容易被读成血更多、伤害更高的普通敌。
- 护卫存在，但玩家不一定觉得它们形成了“屏”。
- 裂口逻辑存在，但玩家未必会意识到“现在该追本体”。
- 自动火力可能继续被边缘护卫抢走，导致追击窗口变成数值窗口，而不是战场路径窗口。

## 设计目标

让精英战从“打厚血单位”变成一个清楚的中段战斗题：

1. 护卫先形成阻挡和压迫。
2. 玩家通过击杀、穿透、换位或爆发打开裂口。
3. 裂口出现后，场面、音效和目标选择都提示“可以追本体”。
4. 不同路线在裂口里有不同兑现方式。

## 修改思路

### 1. 把护卫变成屏障

护卫不只是增加敌人数，而是承担遮线、补线和拖场职责。

- `elite-screen` 更强调护卫遮住本体。
- `elite-vice` 更强调补援和远程火线拖场。
- `elite-bulwark` 更偏厚屏顶线，适合后续展示 `pierce` 拆壁垒。

### 2. 把裂口变成可追窗口

裂口不是“本体短暂变弱”，而是“战场路径打开”。

需要同时成立：

- 护卫或弹幕短暂回落。
- 玩家能看见目标优先级变化。
- 命中、追击、拾取或路线 payoff 能接上下一拍。

### 3. 让三路线有不同答题

- `crit`：抓裂口里的短窗爆发。
- `pierce`：利用护卫成线和裂口贯穿本体。
- `dash`：借裂口换位、擦身、回切反打。

## 实际落地内容

| 模块 | 落地内容 | 设计作用 |
| --- | --- | --- |
| 精英模板 | `elite-screen`、`elite-vice`、`elite-bulwark` | 拉开精英战题型 |
| 护卫结构 | escort 数量、恢复、补援和站位差异 | 形成屏障和拆解对象 |
| 裂口窗口 | `eliteCrackSeen`、`eliteCrackFollowThroughMoments` | 验证窗口是否出现且被承接 |
| 表现反馈 | 裂口提示、压力脉冲、短窗口引导 | 让玩家读到“现在可追” |
| 音频反馈 | `elite_crack_open` 语义、危险 cue 保持优先 | 避免精英战听成普通战加响 |

## 当前样本证据

样本来源：`output/playwright/stability-round25/elite-crack-scan/summary.json`

| 模板 | `eliteCrackSeen` | `eliteCrackFollowThroughMoments` | 当前结论 |
| --- | --- | ---: | --- |
| `elite-lockdown` | `false` | `0` | 当前样本未形成裂口承接，需要更多样本或单独复检 |
| `elite-screen` | `true` | `1` | 护卫遮线模板能形成裂口并发生追击承接 |
| `elite-vice` | `true` | `1` | 绞锁补援模板能形成裂口并发生追击承接 |
| `elite-bulwark` | `false` | `0` | 壁垒模板还需要更强的截图和样本支撑 |

音频样本中同时出现：

- `pressure = 11`
- `enemyShot = 10`
- `nearMiss = 13`
- `hurt = 7`
- `kill = 7`
- `pickup = 7`

这说明精英样本中压力、危险、击杀和拾取都在场，但后续仍需确认它们在视频里是否足够可读。

## 当前结论

已经能初步证明：

- `elite-screen` 和 `elite-vice` 能作为作品集精英案例核心材料。
- “护卫成屏 -> 裂口 -> 追本体”不是纯文档概念，已有 debug 字段支撑。
- 精英战可以被包装成战斗策划案例，而不是简单内容堆量。

暂时不能过度宣称：

- 所有精英模板都稳定形成裂口。
- 自然样本中玩家一定会利用裂口。
- 三路线在所有精英模板中都已经同等成熟。

## 作品集展示结构

### 1. 问题

精英不能只是更厚，必须制造一个中段战斗题。

### 2. 改法

用护卫、裂口、目标优先级和短窗口，把精英变成“先拆屏，再追本体”。

### 3. 验证

用 `eliteCrackSeen` 和 `eliteCrackFollowThroughMoments` 证明裂口和追击承接是否发生。

### 4. 结论

当前 `elite-screen / elite-vice` 已能作为案例核心，`elite-lockdown / elite-bulwark` 还需补自然样本和截图。

## 还缺什么

- 一张 `elite-screen` 裂口前后对比截图。
- 一段 10~20 秒精英追击视频。
- 1 组自然样本数据，证明玩家不是靠 debug 定向才追到本体。
- 对 `elite-bulwark` 的复检：它到底是慢热模板，还是裂口反馈不足。
