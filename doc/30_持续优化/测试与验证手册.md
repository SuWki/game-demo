# 测试与验证手册

## 目标

确保每轮修改不是“感觉变好了”，而是有最小可重复验证。

## 最低验证要求

每次开发后至少完成：

1. `npm run build`
2. 一项与本轮问题直接相关的验证
3. 将验证结果写入开发复盘

## 常用验证方式

### 构建验证

- 命令：`npm run build`
- 作用：确认类型和构建没有坏

### 浏览器流程验证

- 目标：确认开始 -> 节点 -> 战斗 / 整备 / 异常 -> 首领 -> 结算 -> 重开 可跑通
- 参考历史脚本与结果：
  - `output/playwright/`

### 指标导出验证

- 页面内可通过：
  - `window.__pilotMetrics`
  - `window.__exportPilotMetrics()`
- 作用：确认局内状态和结果摘要是否被正确记录

### 战斗快照验证

- 页面内可通过：
  - `window.__pilotBattleDebug()`
- 作用：
  - 定向看当前是否处于 battle / elite / boss 样本
  - 辅助复检精英 `eliteRecoverySec / escortRecoveryCount` 这类裂口时机
  - 避免定向战斗截图完全依赖肉眼碰运气

### 专项验证

- 首领自然样本：
  - 参考 `output/qa/boss-pocket-natural-runs.mts`
- 首领阶段模式：
  - 参考 `output/qa/boss-phase-patterns.mts`
  - 参考 `output/qa/boss-phase-signatures.mts`
- 路线流程抽样：
  - 参考 `output/playwright/commitment-pacing/`

## 验证结果怎么写

开发复盘里必须写：

- 用了什么验证
- 结果是什么
- 结论是什么
- 还有什么没验证

## 当前注意事项

- `output/` 是验证资产和脚本区，不是项目事实源
- `tools/` 是辅助工具区，不应作为设计依据
- `progress.md` 是历史工作记录，不再作为当前真相入口

## 固定验证流程

以后默认按这套顺序跑，尽量不要临时改命令：

1. 如果本轮改了 `src/data/upgrades.ts`、`src/data/battleTemplates.ts` 或其它会影响运行时 JSON 的数据文件，先跑一次 `npm run export:data`
2. `npm run build`
3. 启动预览服务，单独占一个终端，不要和 smoke 混在同一个窗口里
4. 如果 4173 已被占用，直接用 Vite 打印出来的下一个可用端口，不要硬冲同一个端口；后续 smoke 统一跟着实际端口走
5. 另开一个终端跑稳定 smoke：`npm run qa:stable-smoke`
6. 如果需要指定输出目录或结果模式，统一通过环境变量传入，不要手改脚本：
   - `PILOT_QA_URL=http://127.0.0.1:4173/game-demo/`
   - `PILOT_QA_OUT_DIR=output/qa/stable-smoke-current`
   - `PILOT_QA_RESULT_MODE=victory|defeat`
7. 先看 smoke 产物里的 `summary.json`，确认：
   - `failed404Urls: []`
   - `consoleErrors: []`
   - `consoleWarns: []`
8. 只有 smoke 通过后，再做人工看图或定向样本验证

### 最稳模板（PowerShell）

预览终端：

```powershell
npm run preview -- --host 127.0.0.1 --port 4173
```

smoke 终端：

```powershell
$env:PILOT_QA_URL='http://127.0.0.1:4173/game-demo/'
$env:PILOT_QA_OUT_DIR='output/qa/stable-smoke-current'
npm run qa:stable-smoke
```

自然 fullrun 终端：

```powershell
$env:PILOT_QA_URL='http://127.0.0.1:4173/game-demo/'
$env:PILOT_QA_OUT_DIR='output/qa/smart-natural-fullrun-current'
node tools/qa-smart-natural-fullrun.mjs
```

### 常见避坑

- 预览服务只起一个，别同时开多个端口相同的实例
- 跑 smoke 前先确认 `appUrl` 和预览端口一致
- 不要把临时浏览器脚本当成正式验证入口
- 如果要补 Playwright 脚本，优先放在 `tools/`，并先做 build 回归再跑
- 内容层或战斗模板改动后，必须同时确认 `public/data/*.json` 已经同步，不要只看 `src/` 的 TypeScript 源码
- 不要把 preview、smoke、natural fullrun 串成一个终端里的连续命令；按“预览 / smoke / 自然样本”三步拆开跑

## 2026-04-25 稳定性与监控补充

### 新增监控字段

- 本轮起，`window.__pilotBattleDebug()` 与 `window.__exportPilotMetrics()` 会统一暴露以下字段：
  - `lateDashWindowMoments`
  - `dashCounterMoments`
  - `eliteCrackSeen`
  - `eliteCrackFollowThroughMoments`
  - `bossFirelineCoverage`
  - `bossSafeWindowMoments`
  - `killPickupContinueMoments`

### 字段使用口径

- `lateDashWindowMoments`：后段 `dash` 借窗兑现时刻数，用于判断自然流里后段 payoff 是否真的成立。
- `dashCounterMoments`：`dash` 换位后追回主动权的短窗口数，用于判断是否只是位移、还是已经形成回切反打。
- `eliteCrackSeen / eliteCrackFollowThroughMoments`：精英裂口是否形成、裂口后是否真正发生追本体承接。
- `bossFirelineCoverage / bossSafeWindowMoments`：`boss-bastion` 火线阶段的压迫覆盖率与安全窗生成次数。
- `killPickupContinueMoments`：普通战“击杀 -> 掉落 / 拾取 -> 继续开火”回报链的连续样本。

### 本轮后推荐的最小验证组合

1. `npm run build`
2. 一次自然 full-flow
3. 一次更长的自然样本复检
4. 一次定向精英裂口样本
5. 一次定向 Boss 火线样本

### 验证注意事项

- 如果自然长样本没有抽到目标路线，先记录为“样本不足”，不要直接误判成“玩法回退”。
- `RunEngine.tick()` 只在 `state.status === 'battle'` 时推进，所以定向验证脚本必须自动处理中途升级 / 事件面板，否则会把“战斗暂停”误读成“阶段没有推进”。
- 定向 Boss 火线复检允许使用：
  - debug 配置里的 `invulnerablePlayer`
  - `window.__pilotDebug.setPressureState()`
- 上述 debug 注入只服务验证，不属于正式玩法逻辑。
## 推荐执行流程（本仓库固定版）

后续默认按这个顺序来，尽量不要临时改命令：

1. 如果本轮改了 `src/data/upgrades.ts`、`src/data/battleTemplates.ts`、`src/data/events.ts`、`src/data/nodes.ts` 或其它会影响运行时 JSON 的内容文件，先跑 `npm run export:data`
2. 再跑 `npm run build`
3. 另开一个终端启动预览：`npm run preview -- --host 127.0.0.1 --port 4173`
4. 如果 4173 被占用，就用 Vite 实际打印出来的可用端口，`PILOT_QA_URL` 也要同步改成那个端口
5. 再另开一个终端跑稳定 smoke：`npm run qa:stable-smoke`
6. smoke 结束后先看 `output/qa/stable-smoke-current/summary.json`
7. 只有 smoke 干净后，再跑自然 fullrun / directed 样本

推荐的 PowerShell 写法：

```powershell
$env:PILOT_QA_URL='http://127.0.0.1:4173/game-demo/'
$env:PILOT_QA_OUT_DIR='output/qa/stable-smoke-current'
npm run export:data
npm run build
npm run preview -- --host 127.0.0.1 --port 4173
npm run qa:stable-smoke
```

补充规则：

- 不要把 preview 和 smoke 串在同一个终端里跑
- 不要手写临时 Playwright 脚本替代仓库脚本
- 不要在没有 `export:data` 的情况下只看 `src/` 改动
- 如果要跑自然 fullrun，先保证 smoke 通过，再单独跑 `tools/qa-smart-natural-fullrun.mjs`
