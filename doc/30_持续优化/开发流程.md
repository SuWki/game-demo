# 开发流程

## 目标

让每轮开发都形成闭环：

- 有明确目标
- 有实现边界
- 有验证方式
- 有复盘文档
- 有新的交接状态

## 每轮开发前

1. 先读：
   - `../00_接手入口/当前交接卡.md`
   - `../20_设计闭环/设计基线与约束.md`
   - 本轮相关设计文档
2. 用一句话写清“本轮只解决什么问题”。
3. 明确本轮不做什么，避免问题蔓延。
4. 确认需要更新的文档清单。

## 开发中

- 优先做最小闭环修改
- 优先使用数据层改动而不是系统层重写
- 避免同时推进多个主题
- 如果发现文档与实现脱节，先标出，再决定先补文档还是先改代码

## 开发后

1. 运行最小验证：
   - `npm run build`
   - 至少一个与本轮问题直接相关的验证
2. 新增一篇开发复盘
3. 更新 `../00_接手入口/当前交接卡.md`
4. 如果设计边界变化，更新对应设计文档与设计闭环文档
5. 检查是否把 `output/`、`tools/`、`progress.md` 误当成当前事实源

## 何时暂停继续开发

- 本轮目标已经变成两个以上问题
- 新问题需要改主流程
- 文档不能解释为什么要这样改
- 验证方式不明确

出现以上情况时，先补文档或重新收束目标。
