# 核心循环设计

## 目标

用尽量少的系统，做出一条可读、可成长、可收尾、可重开的单局体验。

## 当前循环

开始页 -> 进入一局 -> 节点推进 -> 战斗 / 整备 / 异常 -> 战斗内击杀与拾取经验 -> 升级三选一 -> 路线逐步站稳 -> 最终整备 -> 首领战 -> 结算 -> 重开

## 当前循环打磨重点

- 战斗里的击杀不能只等于数字减少，必须带来明确的掉落与兑现感
- 经验球不能只是地上资源点，应该驱动玩家做出“追过去捡”的动作判断
- 升级面板不只是结算插播，它要像一轮战斗回报链的自然延续
- 失败或通关后的重开欲，不只来自路线差异，也来自每一波战斗本身够不够顺手和痛快

## 为什么这样设计

- 用 `WASD` 走位 + 自动攻击，降低操作门槛，把注意力集中在走位、经验路线、升级选择和节点决策上。
- 用轻量节点推进，而不是复杂大地图，避免项目复杂度过早转向地图系统。
- 用战斗内成长，而不是大量局外系统，保证单局内就能看出路线变化。
- 用首领战固定收尾，保证每局都有明确结尾感。

## 单局目标时长

- 目标：`8~12` 分钟
- 原因：便于原型验证、便于重开、便于快速观察路线成型过程

## 当前体验目标

- 前 `30` 秒理解玩法
- 前 `2` 分钟看出方向
- 中段感到路线站稳
- 后段感到收尾和压力变化
- 普通战里也能清楚读出“击杀有爆点、拾取有追击欲、升级有兑现感”
- 失败或通关后愿意马上再来一局

## 当前不做的事

- 不做复杂局外成长
- 不做长线地图探索
- 不做大量剧情驱动
- 不做高度依赖操作连招的动作游戏体验

## 近期打磨补充

- 当玩家已经进入低血时，战斗必须用尽量少的文字把危险感站出来。
- 这类危险感优先通过已有战斗层表达：
  - 屏幕边缘警示
  - 玩家周围的危险脉冲
  - 已有音频系统里的 `pressure` 与战斗 BGM 能量
- 这仍然服务于核心循环本身，因为它直接影响玩家会不会继续完成“追资源、接下一轮输出”的判断。
- 这类补强不应演变成新的提示系统或新的 UI 说明层。
