# 三类选择界面差异化美术对接文档

## 文档目的

当前关卡选择、异常节点选择、属性强化选择如果共用同一套卡片模板，会带来两个问题：

1. 玩家第一眼不知道自己正在做哪类决策。
2. 面板交互太相似，容易误触，尤其是战斗后连续弹出选择时。

这份文档用于给美术明确三类选择界面的差异化设计要求，让它们从**轮廓、位置、颜色、标题、卡片结构、交互确认**上都能一眼区分。

本文件服务于：

- UI 美术出稿
- UI GPT 生成设计图
- 开发 GPT 落地 DOM / CSS

## 总设计原则

三类选择不能只是“同一个卡片模板换颜色”。

它们必须分别对应三种不同语义：

| 界面 | 玩家语义 | 视觉关键词 | 交互感觉 |
| --- | --- | --- | --- |
| 关卡选择 | 选下一站 | 路线、导航、推进 | 选路 |
| 异常节点选择 | 处理风险事件 | 警戒、偏航、代价 | 做风险决定 |
| 属性强化选择 | 调整机体构筑 | 装备、数值、成长 | 补强 |

核心目标：

- 玩家只看外形，不读文字，也能知道当前是哪种选择。
- 玩家知道点下去会发生什么。
- 高风险选择必须比普通选择多一层确认感。
- 强化选择必须看到当前属性，避免盲选。

## 共同底层风格

三类界面仍然属于同一游戏 UI：

- 暗色未来科技
- 哑光黑 / 深蓝灰
- 细描边
- 切角
- 半透明面板
- 克制发光

但每类面板必须拥有不同的“外轮廓”和“信息结构”。

## 一、关卡选择界面

## 设计语义

关卡选择不是抽奖励，也不是处理事件，而是选择下一段作战路线。

玩家应感到：

- “我要去下一站”
- “这几条路风险和收益不一样”
- “我正在推进一条短局路线”

## 推荐名称

- 主标题：`选择下一站`
- 英文标签：`ROUTE SELECT`
- 操作提示：`选择 1 条作战路线`

## 页面轮廓

关卡选择界面应该像一条**横向路线板**，而不是普通弹窗。

布局：

- 位置：屏幕下半区
- 宽度：屏幕 70% 到 78%
- 高度：220 到 300px
- 形状：横向托盘 + 路线连接线
- 卡片：像目的地节点，不像奖励卡

视觉结构：

```text
[ ROUTE SELECT / 选择下一站 ]

    起点节点  ───  候选 A
          ╲
           ───  候选 B
          ╱
    当前段位  ───  候选 C
```

美术可以不画真实地图，但必须有“路线连接感”：

- 背后有细线连接
- 候选项像导航节点
- 当前所在点有一个小型起点标记

## 卡片结构

每个候选节点包含：

1. 节点类型标签
2. 节点名称
3. 一句风险 / 收益说明
4. 底部短标签
5. 连接线入口

示例：

```text
战斗
压制区
敌群密集，奖励稳定
[经验] [普通]
```

## 颜色规则

- 普通战斗：暖橙
- 精英战：橙红
- 强化节点：青蓝
- 异常节点：紫色
- Boss：红橙高亮

颜色只作为识别辅助，主区别靠外形和布局。

## 防误触设计

关卡选择建议采用：

- hover 时只预览
- 第一次点击选中
- 选中后出现 `确认路线` 按钮

如果开发第一版想简化，也至少要有：

- 明显 selected 状态
- 点击区域不小于 `280 x 160`
- 卡片之间间距不低于 `20px`

## 美术交付状态

必须交付：

- 1 个候选节点状态
- 2 个候选节点状态
- 3 个候选节点状态
- hover
- selected
- disabled / locked 可选

## 二、异常节点选择界面

## 设计语义

异常节点不是普通奖励，也不是普通路线。

玩家应感到：

- “这不是稳定收益”
- “我在处理一次风险事件”
- “每个选项都有代价”

## 推荐名称

- 主标题：`异常接入`
- 英文标签：`ANOMALY EVENT`
- 操作提示：`选择 1 种处理方式`

## 页面轮廓

异常节点应该像一个**警戒终端 / 风险授权界面**。

和关卡选择的区别：

- 不使用路线连接线
- 不使用平稳横向路线板
- 整体更集中、更紧张
- 面板边缘可有断线、警戒条、扫描噪点

布局：

- 位置：屏幕中央偏下
- 宽度：屏幕 58% 到 66%
- 高度：340 到 430px
- 左侧：事件说明 / 风险摘要
- 右侧：2 到 3 个处理选项

视觉结构：

```text
[ ANOMALY EVENT / 异常接入 ]

左侧风险摘要             右侧处理选项
┌────────────┐        ┌─────────┐
│ 异常标题     │        │ 方案 A   │
│ 收益         │        ├─────────┤
│ 代价         │        │ 方案 B   │
│ 风险等级     │        └─────────┘
└────────────┘
```

## 卡片结构

异常选项卡必须同时显示：

1. 处理方式
2. 获得什么
3. 付出什么
4. 风险标签

示例：

```text
强行接入
获得一次高品质强化
失去 18% 当前生命
[押注]
```

## 颜色规则

- 主色：异常紫
- 风险色：橙红
- 收益色：青蓝或金色
- 背景比普通面板更深

异常面板不能看起来像普通强化面板。

## 防误触设计

异常节点必须比普通节点更防误触。

建议交互：

1. 第一次点击选中选项
2. 面板底部出现确认按钮：`确认处理`
3. 高风险选项确认按钮用橙红边线

至少要做到：

- 选项中的“代价”必须与收益同等可见
- 高风险项不能只靠小字说明
- 不能整卡点击后立即无反馈跳走

## 美术交付状态

必须交付：

- 默认异常面板
- 低风险选项
- 高风险选项
- selected
- confirm 状态
- 代价高亮状态

## 三、属性强化选择界面

## 设计语义

属性强化选择是机体构筑界面。

玩家应感到：

- “我正在补强当前 build”
- “我能看到自己现在缺什么”
- “我能比较三张强化的价值”

## 推荐名称

- 主标题：`机体强化`
- 英文标签：`LOADOUT UPGRADE`
- 操作提示：`选择 1 项强化`

## 页面轮廓

属性强化界面应该像一个**机体调校台 / 装备配置界面**。

和关卡选择、异常选择的区别：

- 必须显示当前属性
- 卡片更像模块化强化件
- 布局更稳定、更清晰
- 不应有异常噪点或路线连接线

## 桌面布局

位置：屏幕下半区到中下区。

整体：

- 宽度：屏幕 72% 到 78%
- 高度：330 到 390px

结构：

```text
[ LOADOUT UPGRADE / 机体强化 ]

┌ 当前属性 ┐   ┌ 强化 A ┐ ┌ 强化 B ┐ ┌ 强化 C ┐
│ 伤害     │   │ 品质   │ │ 品质   │ │ 品质   │
│ 射速     │   │ 名称   │ │ 名称   │ │ 名称   │
│ 暴击     │   │ 效果   │ │ 效果   │ │ 效果   │
│ 穿透     │   │ 标签   │ │ 标签   │ │ 标签   │
└────────┘   └───────┘ └───────┘ └───────┘
```

左侧当前属性模块建议宽度：

- `300 ~ 340px`

右侧三张强化卡：

- 单卡 `280 ~ 320px`
- 卡间距 `24 ~ 30px`

## 当前属性模块

必须显示：

- 伤害
- 射速
- 弹速
- 暴击率
- 暴击伤害
- 穿透
- 多重射击
- 生命
- 移速
- 当前路线倾向

可选显示：

- 当前等级
- 当前品质倾向
- 当前构筑标签

展示规则：

- 使用紧凑列表
- 分两列
- 字号小但清楚
- 当前 hover 强化影响的属性应高亮
- 不显示公式
- 不显示内部变量名

## 强化卡结构

每张强化卡包含：

1. 品质角标
2. 强化名称
3. 核心效果
4. 影响属性标签
5. 路线 / 通用标签

示例：

```text
蓝
高速馈电
射速 +18%
[射速] [通用]
```

## 稀有度视觉

- 白：低亮灰蓝边
- 绿：稳定绿色细边
- 蓝：青蓝细亮边
- 紫：紫色能量角标
- 金：金色能量框，不能过度闪

## 防误触设计

强化选择比关卡选择更频繁，因此要减少误触：

- 卡片之间留足间距
- hover 时展示影响属性
- selected 状态必须强
- 第一版可以单击即选，但需要明确点击反馈
- 如果是最终整备或金色高价值项，建议使用二次确认

## 美术交付状态

必须交付：

- 普通升级强化面板
- 最终整备强化面板
- 白 / 绿 / 蓝 / 紫 / 金 五种品质角标
- hover 状态
- selected 状态
- 当前属性模块默认状态
- 当前属性模块高亮状态

## 三类界面一眼区分规则

## 轮廓区分

| 界面 | 外轮廓 |
| --- | --- |
| 关卡选择 | 横向路线托盘，有连接线 |
| 异常节点 | 中央警戒终端，有风险摘要 |
| 属性强化 | 机体调校台，有当前属性面板 |

## 位置区分

| 界面 | 位置 |
| --- | --- |
| 关卡选择 | 更低，更像路线板 |
| 异常节点 | 更居中，更像警戒弹窗 |
| 属性强化 | 中下方，更像配置台 |

## 颜色区分

| 界面 | 主色 |
| --- | --- |
| 关卡选择 | 按节点类型变化，整体偏路线蓝灰 |
| 异常节点 | 紫 + 橙红 |
| 属性强化 | 青蓝 + 稀有度色 |

## 交互区分

| 界面 | 交互 |
| --- | --- |
| 关卡选择 | 选中路线，再确认路线 |
| 异常节点 | 选中处理方式，再确认处理 |
| 属性强化 | 选强化，属性面板同步高亮 |

## 文案区分

| 界面 | 标题 |
| --- | --- |
| 关卡选择 | `选择下一站` |
| 异常节点 | `异常接入` |
| 属性强化 | `机体强化` |

## 美术交付清单

美术需要交付以下稿件：

1. 关卡选择：1 / 2 / 3 候选节点三种布局
2. 关卡选择：hover / selected / confirm 状态
3. 异常节点：默认 / selected / 高风险 / confirm 状态
4. 属性强化：普通强化 / 最终整备两种状态
5. 属性强化：当前属性模块默认 / 高亮状态
6. 属性强化：五种品质角标
7. 三类界面的切角、边框、发光、扫描线规范
8. 三类界面的移动端压缩草图

## 开发落地建议

开发不应继续用一个模板硬套三类界面。

建议拆成三个 DOM 组件：

- `RouteChoicePanel`
- `AnomalyChoicePanel`
- `UpgradeChoicePanel`

共同复用：

- 基础面板 token
- 按钮样式
- 字体层级
- 卡片 hover 动效

但不要复用：

- 外轮廓
- 标题区结构
- 卡片内部信息层级
- 交互确认方式

## 验收标准

第一版实现后，至少满足：

- 玩家不读说明，也能分出三类选择界面
- 异常节点不会被误认为普通奖励
- 强化选择时能看到当前属性
- 关卡选择有路线推进感
- 三类面板都不遮挡战场核心区域太久
- 1366x768 下不超框
- 玩家可见中文无乱码

## 当前建议优先级

1. 先重做属性强化选择，因为它最影响误触和决策质量。
2. 再重做异常节点选择，因为它最需要风险感和二次确认。
3. 最后重做关卡选择，因为它需要路线感，但风险低于前两者。

这样推进可以最快解决“看不出点的是什么”和“容易误触”的问题。
