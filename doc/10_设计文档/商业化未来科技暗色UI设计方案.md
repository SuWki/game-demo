# 商业化未来科技暗色 UI 设计方案

## 文档定位

这是一份**不依赖当前旧设计口径**的全新 UI 视觉方案。

目标不是讨论“现有文档怎么继续迭代”，而是直接给出一套更接近市面商业化产品质感的未来科技暗色风 UI 方案，用于：

- 重新定义开始页、局内 HUD、选择面板、结算页的统一视觉语言
- 直接交给 UI GPT 产出界面设计图或高保真稿
- 再交给开发 GPT 将设计落地为实际前端界面

这份方案默认服务于：

- Web 端
- 16:9 主视口
- 桌面端优先
- Phaser 画面 + DOM UI 叠加
- 节点推进 Roguelite / 自动射击 / 中高节奏战斗

## 一句话方向

这是一个**未来战术试飞系统**风格的产品界面：

- 暗色底
- 高级金属黑与深蓝灰
- 局部高亮青蓝能量光
- 极少量暖色用于危险和奖励
- 界面像高端战术终端，不像网页卡片系统

如果要对标市面感受，应该更接近：

- 高端科幻射击游戏的菜单与 HUD 语言
- Roguelite 的清晰成长反馈
- 商业化游戏的分层、动效和质感控制

而不是：

- 原型期网页面板
- 纯霓虹赛博风
- 花哨但不清晰的特效堆叠

## 视觉关键词

- dark tactical sci-fi
- matte black
- gunmetal blue
- cyan energy
- orange alert
- precise
- modular
- premium
- focused
- restrained

## 绝对避免

- 白底卡片
- 强紫色赛博朋克主调
- 过饱和霓虹描边
- SaaS 仪表盘式布局
- 大量说明性文字面板
- 低端手游感按钮
- 花里胡哨但没有层级的发光边框

## 核心体验目标

### 1. 玩家一进入开始页就知道这是“成品方向明确”的游戏

- 不再像测试入口
- 有品牌感
- 有战斗感
- 有重开欲望

### 2. 局内 HUD 应该专业、克制、清晰

- 让战场是主角
- 让 HUD 像战术终端
- 不是让 HUD 变成厚重面板墙

### 3. 选择面板要像“战术决策”，不是“抽卡页面”

- 节点选择像路线决策
- 强化选择像战斗配置
- 事件选择像高风险权限操作

### 4. 结果页要像“战报结案”，不是简单成绩单

- 告诉玩家这局是怎么打完的
- 强化重开冲动
- 有完成感和复盘感

## 总体视觉语言

## 1. 材质语言

- 主材质：哑光深色金属面板
- 次材质：半透明深蓝灰玻璃
- 强调材质：能量线、扫描线、窄条高亮、细分割框
- 危险材质：橙红警告灯带
- 奖励材质：青蓝或金色细亮边

视觉重点应放在：

- 结构边界
- 细节线条
- 发光层级
- 节奏型动画

而不是大面积贴图。

## 2. 色彩方案

### 基础色

- 页面主底色：`#090d12`
- 次底色：`#101722`
- 面板底色：`rgba(14, 22, 32, 0.88)`
- 分割线：`rgba(170, 204, 228, 0.14)`

### 主强调色

- 科技蓝：`#6fe7ff`
- 能量青：`#44c8ff`
- 冷白：`#ecf7ff`

### 功能色

- 危险橙红：`#ff7b57`
- 成功绿：`#6ee7a8`
- 奖励金：`#ffc96b`
- 异常紫：`#a98cff`

### 路线品牌色

- 暴击：`#ff8b6b`
- 穿透：`#62d9ff`
- 穿梭：`#8df7a6`

原则：

- 屏幕大面积必须维持暗色和低饱和
- 高纯度颜色只负责关键信息和品牌识别
- 不允许整屏泛蓝光或泛紫光

## 3. 字体方案

### 中文

- `Source Han Sans SC`
- `Noto Sans SC`
- 或同级别现代无衬线黑体

### 英文与数字

- `Orbitron` 仅用于极少量标题或数码标签
- 主体仍用与中文统一的无衬线字体

### 字重策略

- 大标题：800
- 关键标签：700
- 正文与核心信息：600
- 辅助说明：500

避免：

- 过细字重
- 大量全大写英文
- 像程序调试界面的密集小字

## 4. 形状语言

- 轻斜切角矩形
- 横向长条状态模块
- 细边框
- 局部切角高亮
- 环形扫描元素
- 细长分隔条

不建议整页大量圆角卡片。

更适合的感觉是：

- 战术终端
- 装备仓 UI
- 高端射击游戏菜单

## 页面级设计

## 开始页

## 页面定位

开始页应该像“进入一次正式作战试飞”的入口。

不是简陋按钮页，也不是复杂首页。

## 布局结构

### 左侧主信息区

左侧占屏幕约 38%。

内容从上到下：

1. 产品英文眉标
2. 中文主标题
3. 一句战斗定位副标题
4. 当前版本或模式信息
5. 主按钮区
6. 次级入口区

### 右侧视觉锚点区

右侧占屏幕约 42% 到 48%。

放一张核心视觉：

- 未来战斗机体 / 无人作战单元
- 悬浮于暗色战术背景
- 背后有环形雷达、扫描线和数据切层

如果资源不足，可以先用程序化视觉替代：

- 三层环形扫描仪
- 斜切数据板
- 远景战场光点
- 缓慢漂移的战术网格

## 内容层级

### 眉标

建议样式：

- 小号大写英文
- 字距拉开
- 低亮度

示例：

- `TACTICAL RUN SIM`
- `OPERATION NODE`

### 中文主标题

要短、硬、好记。

建议 4 到 6 个字。

标题不做厚重描边，不做夸张科幻字效。

### 副标题

一句话说清玩法感受：

- 节点推进
- 自动射击
- 成长构筑

语气要像商业化产品文案，不像设计注释。

### 主按钮区

只保留一个最强主按钮：

- `开始作战`

次按钮：

- `继续上次`
- `战斗记录`
- `设置`

### 底部小信息

建议放：

- 当前版本
- 输入方式
- 一句极简提示

例如：

- `WASD 移动 · 自动开火 · 8-12 分钟单局`

## 开始页视觉细节

- 主按钮使用深色底 + 青蓝发光边 + 轻微扫描动效
- 次按钮统一线框风格
- 右侧视觉不应该比标题更亮
- 背景要有层次，但不能像视频片头
- 页面默认静态，高级感靠节奏和材质，不靠乱动

## 开始页动效建议

- logo / 标题轻微上浮淡入
- 主按钮边缘有慢速能量扫描
- 背景环形视觉有极弱旋转或脉冲
- 鼠标 hover 只做轻量抬亮，不做夸张弹跳

## 局内 HUD

## 页面定位

HUD 要像高端射击游戏的战术层，而不是网页数据板。

## 信息优先级

必须常驻：

1. 生命
2. 经验 / 升级进度
3. 当前阶段 / 波次
4. 当前目标

弱常驻：

5. 当前路线倾向
6. 临时提示

不要常驻：

- 大段说明
- 多列统计表
- 大面积装备栏

## HUD 布局

### 左上：生命 + 经验

形式：

- 两条细长条
- 左侧大数字
- 条内极弱渐变
- 外围细线边框

生命条：

- 冷白数字
- 条体用绿光或冷青绿
- 低血时进入橙红外缘闪烁

经验条：

- 主色用能量青
- 每次拾取时做短促推动感

### 上中：阶段 / 波次

用一个小型战术胶囊显示：

- `PHASE 02`
- `WAVE 3 / 5`

可带极小副标题：

- `MID RUN`

### 右上：当前目标

用一个轻量任务模块显示：

- `清除残敌`
- `生存倒计时`
- `追击精英`
- `进入首领战`

目标组件要比普通 HUD 更有一点边缘高亮，但不能太厚。

## 局内提示系统

### 提示分类

- 路线提示
- 危险提示
- 阶段提示
- 奖励提示

### 表现规则

- 所有提示统一在上中偏下区域出现
- 每次只允许一条主提示抢焦点
- 提示条必须短
- 左侧有功能标签
- 主文案不超过一行

### 视觉示例

- 标签：`ROUTE`
- 文案：`暴击回路开始升温`

- 标签：`ALERT`
- 文案：`火线压上`

- 标签：`BOSS`
- 文案：`主核暴露`

## 选择面板设计

## 节点选择面板

### 目标

让玩家感觉像在选下一段作战路线。

### 结构

- 面板位于屏幕下半部
- 1 / 2 / 3 张卡均可适配
- 卡片横向铺开
- 背后保留战场可见

### 卡片层级

1. 节点类型标签
2. 节点标题
3. 一句说明
4. 底部收益 / 风险提示

### 视觉气质

- 战斗节点：暖橙高亮边
- 强化节点：青蓝高亮边
- 事件节点：紫色高亮边

卡片不做纯色大底，而是深色半透明面板 + 局部亮边。

## 强化三选一面板

### 目标

让玩家感觉自己在做战斗构筑，而不是抽奖。

### 结构

- 标题区
- 当前属性快照区
- 稀有度提示
- 三张强化卡
- 卡片上直接显示核心收益

### 当前属性快照区

强化选择界面必须让玩家看到自己当前机体状态，否则三选一会变成“只看卡面，不知道补什么”。

推荐布局：

- 左侧或上方放一个 `当前属性` 模块
- 右侧或下方放三张强化卡
- 桌面端优先使用左侧属性模块 + 右侧三选一卡组
- 小屏端属性模块压缩成横向短条，放在卡组上方

当前属性模块只显示影响决策的核心属性，不显示全量调试数据。

建议展示：

- 伤害
- 射速
- 弹速
- 暴击率
- 暴击伤害
- 穿透
- 多重射击
- 生命
- 移速
- 当前路线倾向

表现规则：

- 使用紧凑数值表，不做大卡片堆叠
- 当前强化会影响的属性，应在属性模块中轻微高亮
- 不显示内部字段名
- 不显示复杂公式
- 属性模块像机体状态面板，而不是 RPG 角色面板

### 强化卡视觉

- 白 / 绿 / 蓝 / 紫 / 金 的区别主要体现在：
  - 右上角品质角标
  - 边框能量强度
  - 底部细纹理层次

### 强化卡建议结构

1. 强化名
2. 一句核心效果
3. 小标签：通用 / 暴击 / 穿透 / 穿梭 / 生存 / 机动
4. 品质角标

## 事件 / 异常面板

### 目标

比强化更危险、更未知、更像一次权限操作。

### 风格

- 深色更深
- 紫色与橙红混合警示
- 有轻微故障线
- 不做花哨 glitch 海报感

## 结算页

## 页面定位

结算页不是统计报表，而是一次战斗结束后的“作战结案”。

## 布局结构

与开始页保持同构，形成前后呼应。

### 左侧信息区

从上到下：

1. 英文眉标
2. 中文结果标题
3. 本局路线摘要
4. 本局关键信息
5. 操作按钮

### 右侧视觉区

使用与开始页同语言但不同状态的视觉锚点。

如果胜利：

- 冷青蓝 + 成功绿
- 环形结构更稳定、更收束

如果失败：

- 暗红 + 低亮熄火状态
- 视觉缩退，不要夸张“失败惩罚感”

## 结算页内容层级

### 标题

- 胜利：`作战完成`
- 失败：`本次中断`

### 摘要行

格式建议：

- `${路线名} · ${构筑评价} · ${结局描述}`

例如：

- `穿透路线 · 线压成型 · 倒在主核火线`
- `暴击路线 · 过热收割 · 成功清除战区`

### 数据区

只保留最关键的 4 项：

- 等级
- 战斗数
- 清理节点数
- 本局主要成长方向

不要堆十几个统计指标。

### 按钮

- 主按钮：`再来一局`
- 次按钮：`返回开始页`
- 次按钮：`查看记录`

## 响应式原则

## 桌面端

- 开始页左右分区
- 局内 HUD 贴边
- 面板浮于战场之上

## 小屏端

- 开始页改为上下结构
- HUD 压缩为两行
- 选择卡片改为纵向滚动或两层堆叠

但整体风格必须保持统一，不得退化成移动端网页卡片。

## 动效方向

## 动效气质

- 克制
- 精准
- 有机械感
- 有能量流动感

## 推荐动效

- 微扫描
- 细边流光
- 卡片浮现
- 目标锁定环轻脉冲
- 结果页锚点收束

## 不推荐动效

- 面板乱飞
- 大面积辉光扩散
- 过多弹性动效
- 像二次元手游抽卡那样的庆祝特效

- 暗色系
- 高级、克制、商业化

- 像高端科幻战术射击游戏的菜单和 HUD

游戏类型关键词：

- node-based roguelite

- build crafting

- boss finish

请重点设计以下界面：

1. 开始页

结算页要求：

- 像战斗结案页
- 信息简洁但有完成感
- 让玩家有重开冲动

请输出：

1. 整体视觉方向说明
2. 颜色、字体、材质、动效建议
3. 每个页面的高保真设计说明
4. 页面线框结构
5. 可交给前端实现的组件清单

避免：

- 白底卡片
- SaaS 后台风
- 紫色赛博朋克泛滥
- 花哨但不专业
- 低端手游感
- 过于测试版或原型版

## 开发 GPT 直接使用提示词

下面这段可直接交给开发 GPT：

---

你现在要实现一套全新的商业化未来科技暗色系游戏 UI。

注意：

- 这次不要沿用旧设计文档风格
- 不要继续按现有 UI 样式小修小补
- 请以“商业化未来科技暗色系”作为新的视觉主方向
- 但不要重写游戏主流程、不要重写 RunEngine、不要引入复杂新系统

你要基于现有 Phaser + TypeScript + Vite 项目，重点改造：

1. 开始页
2. 局内 HUD
3. 节点选择面板
4. 强化三选一面板，必须包含当前属性快照模块
5. 事件 / 异常面板
6. 结算页

实现要求：

- UI 用 DOM + CSS 为主
- 战场仍由 Phaser 驱动
- 用 CSS variables 建立新的视觉 token
- 统一颜色、材质、边框、阴影、字体、动效
- 让开始页和结算页形成同构关系
- 让 HUD 更薄、更专业、更像战术终端
- 让选择面板更像商业游戏中的构筑 / 路线选择界面
- 让强化三选一界面同时显示当前关键属性，方便玩家判断本次强化价值

设计风格要求：

- 深黑 / 深蓝灰底色
- 青蓝能量强调
- 橙红危险点缀
