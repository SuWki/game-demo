# 界面线框与落地清单

## 文档状态

- 状态：`当前生效 / UI执行稿`
- 上游依据：`视觉与UI设计规范.md`、`UI页面固定规则.md`
- 下游引用：`画面与UI验收清单.md`、`../40_AI协作/美术与UI统一对接文档.md`
- 使用对象：UI、程序、策划、协作 GPT

## 说明

本文件不再讨论“可以怎么设计”。

本文件只回答：

- 每个页面固定有什么元素
- 每个元素放哪里
- 明确不能出现什么

任何页面改动，必须先满足本文件。

## 页面总览

当前版本固定 4 组 UI：

1. 开始页
2. 战斗 HUD
3. 选择界面
4. 结算页

## 1. 开始页

## 固定规则

- 使用全屏背景。
- 标题居中放在上中区域。
- 主按钮组居中纵向排列。
- 当前版本只保留真实可用按钮，不伪造不存在的系统入口。
- 默认按钮为：
  - `开始游戏`
  - `导出记录`
- 按钮做成独立大按钮，不放进大黑框里。
- 标题和按钮直接压在背景上。

## 固定布局

```text
┌──────────────────────────────────────────────┐
│                                              │
│                 游戏标题                      │
│                                              │
│              [开始游戏]                      │
│              [导出记录]                      │
│                                              │
│                                              │
└──────────────────────────────────────────────┘
```

## 必须出现

- 游戏标题
- 至少 1 个主按钮
- 当前版本的功能按钮组
- 按钮整体居中
- 开始页背景图或背景场景

## 禁止出现

- 左右分栏大黑框
- 右侧信息盒
- 顶部终端条
- 路线说明卡
- 统计卡组
- 大段玩法说明
- 黑色玻璃大面板
- 右侧附加说明文案块

## 2. 战斗 HUD

## 固定规则

- 左上角只保留 HP、EXP 和进度条。
- 玩家头顶必须显示血条。
- 顶部中间第一行显示波次信息。
- 顶部中间第二行显示当前关卡玩法。
- 不再使用右上目标框。
- 左上信息不再外包一整块大黑底。

## 固定布局

```text
┌──────────────────────────────────────────────┐
│ HP 110/110                                   │
│ [HP条]                                       │
│ EXP 7/29                                     │
│ [EXP条]                                      │
│                    第 3 波                   │
│                    歼灭                      │
│                                              │
│                [玩家头顶血条]                │
│                                              │
└──────────────────────────────────────────────┘
```

## 必须出现

- 左上角 HP 数值
- 左上角 HP 条
- 左上角 EXP 数值
- 左上角 EXP 条
- 玩家头顶血条
- 顶部中间波次
- 顶部中间玩法类型
- 顶部信息居中对齐
- 左上状态条紧贴屏幕边角但保留安全边距

## 禁止出现

- 右上角目标框
- 右上角路线框
- phase track
- 常驻大提示条
- 大面积 HUD 容器
- 多余说明性标签
- 任何覆盖中场的大号信息板

## 3. 选择界面

## 固定规则

- 只保留一个顶部标题。
- 标题下方只保留 4 个选择框。
- 选择框为主内容，不再增加额外摘要。
- 所有选择页统一遵守这条规则：
  - `选择路线`
  - `选择强化`
  - `异常处理`
  - `最终整备`
- 选择框统一尺寸和节奏。
- 页面其余区域只留必要留白，不再塞说明组件。

## 固定布局

```text
┌──────────────────────────────────────────────┐
│                                              │
│                 选择强化                      │
│                                              │
│     [选项1]  [选项2]  [选项3]  [选项4]       │
│                                              │
└──────────────────────────────────────────────┘
```

## 单卡允许内容

- 标题
- 1 到 2 行效果说明
- 可选的小角标，例如稀有度或类型
- 轻量图标或路线标记

## 单卡禁止内容

- phase track
- 当前进度总结
- 顶部副说明盒
- 右侧辅助说明
- 额外统计模块
- “当前路线进度”这类面板外信息
- 卡片外悬浮说明条

## 4. 结算页

## 固定规则

- 结算信息放在页面中部。
- 下方只允许 2 个主按钮：
  - `返回主界面`
  - `重新开始游戏`
- 本局数据必须展示在中间结算区域。
- 中间结果区域可做一块亮色结果板，但不能做左右双栏。
- 两个按钮固定放在页面底部主操作位。

## 必须展示的数据

- 胜利 / 失败
- 本局路线
- 等级
- 战斗数
- 节点数
- 本局时长
- 本局总结
- 胜负状态必须最大最先读到

如果某项数据当前没有现成来源，先空缺实现，不允许用多余 UI 代替。

## 固定布局

```text
┌──────────────────────────────────────────────┐
│                                              │
│                  胜利/失败                    │
│                                              │
│              本局路线 / 等级 / 战斗 / 节点     │
│                 本局时长 / 本局总结            │
│                                              │
│        [返回主界面]   [重新开始游戏]           │
│                                              │
└──────────────────────────────────────────────┘
```

## 禁止出现

- 右侧信息栏
- 第三个按钮
- 导出记录按钮
- 复杂统计报表
- 左右双栏结算卡
- 黑色终端式大底板
