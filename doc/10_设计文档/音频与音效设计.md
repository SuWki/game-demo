## 当前项目中的声音职责

本项目是短局节点推进自动射击原型。声音的首要职责不是“把场面做满”，而是帮助玩家更快读懂并更愿意继续打下去。

当前声音必须服务五件事：

- 让玩家立刻知道自己是否打中了、打死了、捡到了
- 让玩家在低血、近失和高压阶段更快读到危险
- 让普通战、精英战、生存战、Boss 战一进场就不像同一张皮
- 让 `crit / pierce / dash` 三条路线在实战里有可重复辨识的听觉性格
- 让开始、阶段推进、结果和重开构成完整单局闭环

## 设计原则

### 1. 可读性优先于装饰性

- 声音优先回答“刚才发生了什么”
- 不用大段 UI 和文字去解释已经能由声音读出来的事情
- 不靠氛围声掩盖战斗读感不足

### 2. 短、近、硬，避免空

- 当前项目更适合近场、短尾、快速起音的声音设计
- 不建议大量长混响、超宽空间尾巴或过度电影化拖尾
- 否则会把短局战斗的节奏打软

### 3. 先分层，再做细节

声音层级应先分清：

- 状态音乐
- UI 提示
- 玩家动作
- 命中与击杀
- 敌方压迫与来袭
- 路线高光
- 战斗模板签名
- 结果收尾

先把层级分开，再去做“好不好听”的优化。

### 4. 反馈要推动下一拍

本项目的核心回报链不是停在“这一击发生了”，而是要推动下一拍动作：

- `hit` 要推动继续开火
- `kill` 要推动追掉落
- `pickup` 要推动追下一目标
- `crit / pierce / dash` 要推动路线 mini-high 成立

所以声音设计不能只给事件盖章，还要给“继续压上去”的冲动。

### 5. 不新增重系统

音频设计允许继续增强，但不建议为了声音单独开新的运行时大系统。

当前优先策略仍然是：

- 沿现有 `AudioCue` 和音乐状态扩写
- 在现有 `RunEngine -> GameScene -> PilotAudio` 链路里接线
- 用少量层级化音频规则，而不是引入复杂 middleware 心智

## 总体听觉方向

## 核心风格

建议整体方向统一为：

- 近未来训练场
- 电子脉冲
- 金属火花
- 低频撞击
- 压缩过的战场能量

这不是写实军武，也不是纯像素复古，更不是空灵太空歌剧。

更准确地说，它应该听起来像：

- 一个正在高强度试飞和战术模拟的竞技场
- 战斗反馈被刻意压缩成短、明确、能立刻读懂的信号

## 关键词

- 干脆
- 压迫
- 带电
- 短促
- 咬合
- 推进
- 收束

## 应避免的听觉问题

- 所有 cue 都像同一类 UI 提示音
- 战斗里全是高频尖声，没有低频支撑
- 低血和高压状态只靠音量变大，没有语义变化
- 路线差异只剩颜色不同，声音上听不出来
- Boss 与普通战只有“更响”，没有结构变化

## 二级混音优先级

从高到低建议如下：

1. 玩家受击 / 近失 / 关键危险
2. 命中确认 / 击杀兑现
3. 开火基础节奏
4. 路线高光与精英裂口
5. 敌人 relay 与场地签名
6. 背景音乐
7. 次级 UI 点按

这意味着：

- 音乐应该持续存在，但在关键反馈上要让路
- 高频小 cue 数量要克制，避免覆盖真正重要的危险音

## 音乐设计

## 1. Menu 音乐

### 目标

- 给出“准备开始试飞”的预备感
- 不要太热，不要先把整局高潮透支

### 情绪

- 冷静
- 有期待
- 有轻微启动感

### 编曲建议

- 中低速脉冲
- 简单音型循环
- 轻 pad + 细 lead
- 不要太厚的低频

### 听感关键词

- 待命
- 准备通电
- 轻微悬念

## 2. Battle 音乐

### 目标

- 成为普通战的持续动力底盘
- 让战斗听起来“正在往前滚”，而不是静态背景

### 情绪

- 持续推进
- 中等压迫
- 可长时间循环不烦

### 编曲建议

- 更密的节拍步进
- 稳定 bass ostinato
- 短促 lead 点火
- 少量噪声打击强化“战场电火花”

### 结构建议

- A 段：普通推进
- A' 段：略抬高张力
- 循环长度不宜太长，优先保证稳定感

## 3. Boss 音乐

### 目标

- 立刻告诉玩家“这不是普通战”
- 强化阶段变化和收束感

### 情绪

- 更高压
- 更明确的目标压迫
- 更强的收尾感

### 编曲建议

- bass 更重
- 节拍更密
- accent 更硬
- 允许出现更明显的阶段转折音型

### Boss 子类型签名

#### `boss-hunt`

- 关键词：正面顶压、逼近、直接压上
- 音乐建议：更直、更重的脉冲推进

#### `boss-lockdown`

- 关键词：封位、锁场、挤压空间
- 音乐建议：更密、更紧的切分与压拍

#### `boss-bastion`

- 关键词：屏卫、火线、拖场、迁火
- 音乐建议：加入更明显的交叉高频节奏与中高频“火线移动”层

## 4. Result 音乐

### 目标

- 给玩家一个明确结尾
- 让重开有动机

### 胜利

- 上扬
- 收束
- 有“完成试飞”感

### 失败

- 下坠
- 熄火
- 但不要太重，以免阻断立即重开

## 战斗模板的听觉签名

## 1. 普通战

### 目标

- 最稳定的推进模板
- 不靠夸张大特效，而靠持续清楚的节奏回报

### 听感

- 节拍明确
- hit/kill/pickup 层最清晰
- 敌群压迫偏均衡

## 2. 精英战

### 目标

- 听起来像“先顶、先封、再给裂口”
- 裂口要能被耳朵和眼睛一起读到

### 听感

- 压迫层更厚
- 短时收招时频谱腾空
- 路线高光更容易被听见

### 关键设计

- 精英压迫期：低频与中频更密
- 裂口期：压迫层短退，让 `crit / pierce / dash` 的高光有空间
- 追击期：用更明确的 transient 把“现在能冲”做出来

## 3. 生存战

### 目标

- 强调持续压迫和换位
- 不强调击杀收束，而强调“顶住”

### 听感

- 敌方威胁层更连续
- 近失、来弹、压迫脉冲更重要
- 玩家开火和击杀要稍微后退一点，避免误读为纯爽刷

## 4. Boss 战

### 目标

- 明确进入最终解决阶段
- 阶段变化必须能听见

### 听感

- 高压
- 更大体量
- 更少琐碎点音，更多结构型事件

## 路线专属声音设计

## 1. `crit` 暴击路线

### 体验关键词

- 升温
- 爆发
- 连续命中后的集中兑现

### 声音关键词

- 上扬
- 聚焦
- 发热
- 收割

### 核心音色

- 明亮三角 / 方波瞬态
- 带火花感的高频闪点
- 较短但明显上冲的音高包络

### 事件表现

- 普通命中时不必每次都很亮
- 当进入 overdrive、低血收割、精英裂口追击时，声音要明显更“烫”

### 正式资产建议

- `crit-hit`
- `crit-kill`
- `crit-overdrive-enter`
- `crit-chain-rise`
- `crit-elite-window`

## 2. `pierce` 穿透路线

### 体验关键词

- 贯穿
- 拆线
- 清线
- 扩面

### 声音关键词

- 切开
- 拉线
- 穿透
- 拖尾

### 核心音色

- 带高速切割感的中高频噪声
- 明显的线性拖尾
- 偏冷、偏锋利

### 事件表现

- 重点不是单点爆，而是“一串被拆开”
- 打穿护卫、清一线敌人时，要听起来像战场结构被切开

### 正式资产建议

- `pierce-pass-through`
- `pierce-echo`
- `pierce-line-clear`
- `pierce-escort-breach`
- `pierce-elite-follow-through`

## 3. `dash` 穿梭路线

### 体验关键词

- 换位
- 擦身
- 蓄能
- 反打

### 声音关键词

- 相位滑移
- 气流撕开
- 脉冲反冲

### 核心音色

- 低频起冲 + 高频风切
- 带一点空间撕裂感，但尾巴依然要短
- 不要做成传统奇幻闪现

### 事件表现

- dash 的满足点在“换出位置以后，反打一拍成立”
- 所以除了 dash 本体，还要设计 dash 后那一拍的 carry

### 正式资产建议

- `dash-start`
- `dash-pass`
- `dash-graze`
- `dash-pulse`
- `dash-drive-active`

## UI 与流程声音设计

## 1. `click`

- 用途：普通悬停与点按
- 目标：轻，不抢戏
- 建议时长：40ms~90ms
- 建议变体：3 个

## 2. `confirm`

- 用途：节点确认、返回确认、功能确认
- 目标：比 click 更稳、更像“决定已生效”
- 建议时长：90ms~180ms
- 建议变体：2 个

## 3. `start`

- 用途：进入试飞、结果页重开
- 目标：带启动感，明确拉开单局
- 建议时长：180ms~420ms
- 建议变体：2 个

## 4. `upgrade`

- 用途：升级三选一、整备收益确认
- 目标：亮、上扬、明确奖励感
- 建议时长：180ms~320ms
- 建议变体：3 个

## 5. `anomaly`

- 用途：异常节点确认、异常面板特殊操作
- 目标：和普通奖励区分开，带一点不稳定和偏折感
- 建议时长：220ms~420ms
- 建议变体：3 个

## 6. `result`

- 用途：结果页落地
- 目标：告诉玩家这一局已经封口
- 建议时长：250ms~600ms
- 建议变体：胜利 / 失败各 1 组

## 玩家战斗主链声音设计

## 1. `shoot`

### 目标

- 让玩家知道自己在稳定输出
- 不依赖 hit 才知道“有在开火”

### 设计要求

- 短
- 有点火感
- 可以高频重复但不能刺耳

### 资产建议

- 基础开火 4 变体
- 轻 route tint 版本 3 组

## 2. `hit`

### 目标

- 让“打实了”一耳朵成立

### 设计要求

- 要比 shoot 更硬
- 要有轻微低频砸点
- 不要太长，避免打成糊墙

### 资产建议

- 普通命中 5 变体
- 精英命中 3 变体

## 3. `kill`

### 目标

- 让“这一只已经收掉”成立
- 同时推动回收链

### 设计要求

- 比 hit 更上扬
- 允许更亮一点
- 但不能像老虎机大中奖

### 资产建议

- 普通击杀 4 变体
- 强敌击杀 2 变体

## 4. `pickup`

### 目标

- 让玩家愿意追过去捡
- 听起来像收益正在回灌下一拍

### 设计要求

- 轻亮
- 有吸附和回收感
- 可连吃不烦

### 资产建议

- 单拾取 4 变体
- 连拾取叠层 2 组

## 5. `hurt`

### 目标

- 玩家受击必须明确
- 要和 near miss 明确分家

### 设计要求

- 更重
- 更低
- 更像真正被撞到，而不是一声警告

### 资产建议

- 受击主体 3 变体
- 危险状态加强版 1 组

## 6. `nearMiss`

### 目标

- 告诉玩家“刚才差一点”
- 让方向和擦身感成立

### 设计要求

- 更轻、更尖
- 更像掠过
- 避免和 hurt 混淆

### 资产建议

- 近失掠过 4 变体
- 左右方向略有频谱差异

## 7. `enemyShot`

### 目标

- 帮助玩家提前读到战场火线

### 设计要求

- 不一定比玩家开火更响
- 但要更危险、更“冲你来”

### 资产建议

- 通用来弹 4 变体
- 远程敌专属 tint 2 组

## 8. `pressure`

### 目标

- 服务高压阶段、精英脉冲、Boss 压进

### 设计要求

- 更偏低频
- 更像“压上来”
- 不应像 UI 提示或普通命中

### 资产建议

- 普通 pressure 2 变体
- 精英 pressure 2 变体
- Boss pressure 2 变体

## 敌人家族音效设计

普通敌家族已经在玩法上承担不同人格，声音也应承担相同职责。

## 1. `relayStandard`

- 语义：补线、顶前排、接上压力
- 音色：短、稳、偏中频
- 体感：像队形补位

## 2. `relaySkirmisher`

- 语义：绕侧、切入、打歪你的站位
- 音色：更斜、更快、更尖
- 体感：像一道侧切

## 3. `relayBrute`

- 语义：重压、顶线、肩冲
- 音色：低频更厚、更钝、更沉
- 体感：像体量压上来

## 4. `relayRanged`

- 语义：补枪、火线续上、站位支援
- 音色：中高频更明显，带一点机械支架感
- 体感：像火线被重新架起来

## 精英与 Boss 专属事件设计

## 1. 精英进场

- 目标：让玩家立刻知道“核心目标出现了”
- 建议：不是单纯 boss 版 start，而是更像“高压单位进入战区”

## 2. 精英压迫脉冲

- 目标：让“先顶、先封”的阶段成立
- 建议：低频脉冲 + 中频短促机械打点

## 3. 精英裂口打开

- 目标：明确告诉玩家“现在可以追”
- 建议：短时腾空、切开、退压的组合

## 4. 精英裂口追击

- 目标：让 follow-through 不只靠视觉
- 建议：给 `crit / pierce / dash` 各自留下可区分的裂口追击音

## 5. Boss 转段

- 目标：阶段切换必须能听见
- 建议：结构性 downbeat + 模式变化，不只是播一个长提示音

## 6. `boss-bastion / fireline`

- 目标：把“火线迁移”和“安全窗变化”做出听觉结构
- 建议：
  - 火线齐射：中高频交错短 burst
  - 压边迁火：左右移动感更强
  - 安全袋切换：可以用短吸入或短降噪做“窗口打开”感

## 资产制作规范建议

## 时长建议

- 高频交互类：40ms~120ms
- 战斗即时反馈：50ms~180ms
- 高光类：120ms~320ms
- 状态切换类：250ms~900ms

## 频谱建议

- 命中与击杀必须有足够的中频核心，避免只剩高频火花
- 压迫与受击必须有稳定低频信息
- 近失和切线类 cue 主要靠中高频塑形

## 变体数量建议

- 高频战斗主链每类至少 4 个变体
- 高光类每类至少 2~3 个变体
- UI 类每类 2~3 个即可

## 空间与尾巴建议

- 默认短尾
- 仅 Boss 转段和结果收尾允许更明显空间
- 普通战尽量避免长混响抢读感

## 响度与混音建议

## 基本原则

- 音乐持续存在，但永远不是最重要的
- 战斗里关键 SFX 必须能穿出来
- 高压时应优先保证危险提示，不是保证音乐完整性

## Ducking 建议

- `shoot`：轻 duck
- `hit / enemyShot / nearMiss`：中轻 duck
- `kill / crit / relayBrute`：中 duck
- `hurt / pressure / boss phase`：强 duck

这和当前程序音频策略一致，正式资产阶段建议继续沿用。

## 声音密度控制

- 普通战里同时最活跃的高频 cue 不应超过 3 类
- 当 `nearMiss` 和 `hurt` 连续出现时，要主动压低次级花火类 cue
- 精英裂口阶段应给路线高光留出空间

## 玩家体感验收

至少应满足：

- 不新增与当前原型目标无关的大系统

- 保持当前 `AudioContext` 解锁逻辑可用
- 保持 `menu / battle / boss / result` 四种状态切换稳定
- 保持高优先级 cue 在真实浏览器运行里可触发、可统计、可快照
- 保持 full-flow 回归时不出现“声音逻辑接上了但实际不可听”的回退

## 当前阶段结论

当前项目已经有一套最小可用的程序化音频骨架，但它仍然属于“反馈闭环版本”，不是正式资产方案。

后续正式音频设计应继续遵守当前项目主线：

- 核心循环优先
- 战斗回报链优先
- 路线实战辨识优先
- Boss 收尾结构优先

也就是说，声音设计的成功标准不是素材数量，而是玩家能不能更快听懂局势，并且更想再开一局。

## 2026-04-24 手感与危险 cue 补充

本轮没有扩新 `AudioCue`，而是沿现有 `routeFocus / encounter / intensity` 加强同一 cue family 的语义差异。

- `pierce` 的最小听觉签名继续向“冷、线性、切开、拉通”靠拢：`shoot / hit / kill / pickup` 在 `routeFocus = pierce` 时会带更窄的中高频拉线和短噪声切线。
- `hurt` 现在应比 `nearMiss` 更低、更重、更短促确定，混音 duck 也更强；验收时玩家闭眼也应能区分“已经中伤”和“刚刚擦边”。
- `nearMiss` 应更尖、更薄、更像掠过，避免和受击低频主体混在一起。
- `pressure` 应更偏低频和持续压迫，Boss/精英语境下更厚；它不应该听起来像普通 `enemyShot`。
- `enemyShot` 继续代表火线建立，Boss/精英语境下可以更低更紧，但优先级仍低于 `hurt` 和关键 `pressure`。

当前正式资产替换时必须保留这些分层，不应把程序化 cue 全部替换成同质 UI beep。

### 当前音效最需要拉开的差异

#### 页面级

- 开始页是“待命和启动”
- 结果页是“结案和重开”

这两者不能只靠同一套 UI 点击音撑住。

#### 战斗级

- `shoot` 是稳定底拍
- `hit` 是确认
- `kill` 是兑现
- `pickup` 是回收与追下一口
- `hurt` 是危险落地
- `nearMiss` 是险而未中

这几类 cue 的层级必须明确，否则战斗会听成一团。

#### 敌人与压力级

- `standard` 应该中性、稳、补位
- `brute` 应该更厚、更重、更顶
- `skirmisher` 应该更轻、更快、更斜切
- `ranged` 应该更像火线被架起来

#### 路线级

- `crit` 不是更响，而是更热、更集中、更像收口
- `pierce` 不是更亮，而是更锐、更线性、更像切开通道
- `dash` 不是只有风声，而是更像压缩换位后再释放

## 2026-04-20 程序化音频收口补充

这一节记录当前代码里已经落地的最小音频差异口径，后续继续替换正式资产时，优先保留这些语义，不要回退成“所有 cue 都只是不同音高的提示音”。

### 1. 现阶段音频上下文已经至少分三层

- 路线层：`routeFocus = crit / pierce / dash / null`
- 战斗层：`encounter = ordinary / elite / boss / survive / flow`
- 强度层：`intensity = 0 ~ 1`

这三层上下文已经足够支撑当前版本的最小差异，不建议为了这一轮再新开音乐状态机。

### 2. 当前最应该被听见的差异

- `shoot` 不是 UI beep，而是稳定输出底拍。
- `hit` 要比 `shoot` 更实、更带低频咬合。
- `kill` 要明确比 `hit` 更像“这一只收掉了”。
- `pickup` 要像回灌下一拍，而不是普通奖励提示。
- `hurt / nearMiss / pressure` 必须三分家：
  - `hurt` 更重、更低，代表已经中伤。
  - `nearMiss` 更尖、更薄，代表擦身而过。
  - `pressure` 更像一整拍压上来的结构提示。

### 3. 现阶段三路线最小听觉签名

- `crit`
  - 更热、更上扬、更集中。
- `pierce`
  - 更冷、更线性、更像切开和拉通。
- `dash`
  - 更偏低频起冲和相位滑移，暂时不求最强记忆点，但不能再听成普通 shoot/hit 的副本。

### 4. 当前普通战 / 精英 / Boss 的差异口径

- 普通战：
  - 先保证 `shoot / hit / kill / pickup` 这条主链最清楚。
- 精英战：
  - `enemyShot / pressure` 可以更厚，但要给裂口追击留空间。
- Boss 战：
  - 继续沿现有 `boss` 音乐状态和更重的 `pressure` 处理，不为了这一轮重写整套大音乐系统。

## 2026-04-24 dash 后段 payoff 音频补充

本轮没有新增 `AudioCue`，而是继续沿 `routeFocus / encounter / intensity` 做同一 cue family 的 `dash` 差异化，目标是让后段 `dash` 更像“擦身、折返、追回主动权”。

当前新增口径：

- `dash` 的重点不只是 `dash` 动作 cue 本身，还包括动作之后那一拍的 `hit / kill carry`。
- `dash hit` 现在应更像低中频擦身回切：
  - 比通用 `hit` 更有折返感
  - 但不能吃掉危险层的空间
- `dash kill` 现在应更像追回主动权后的收口：
  - 不是 `crit` 的上扬爆发
  - 也不是 `pierce` 的冷线切开
  - 而是短促、向前、带一点回拉的兑现
- `hurt / nearMiss / pressure / enemyShot` 的语义层本轮不动：
  - `hurt` 仍然最重
  - `nearMiss` 仍然最尖
  - `pressure` 仍然偏低频结构压迫
  - `enemyShot` 仍然代表火线建立
- 如果后续正式资产替换让 `dash` 更亮、更长或更像风声，导致上述四类危险 cue 被盖掉，视为回退。

当前验收口径：

- `dash` 在后段应该比之前更容易和 `pierce` 分开：
  - `pierce` 偏拉轨、穿层、清线
  - `dash` 偏擦身、折返、回切反打
- 混战里仍要能听清 `hurt / nearMiss / pressure / enemyShot`。
- 音频补强必须服务短局战斗读感，不能为了做路线个性把危险提示稀释掉。
