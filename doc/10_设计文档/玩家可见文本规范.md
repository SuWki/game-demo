# 玩家可见文本规范

## 文档目的

统一游戏内所有玩家可见文本的撰写规则，确保文案简洁、易懂、不使用内部设计/开发语言。

## 核心原则

### 1. 禁用词汇清单

以下词汇**禁止**出现在玩家可见文本中：

| 禁用词 | 替代方案 | 示例 |
|--------|----------|------|
| 窗口 | 时间/时机 | "无伤窗口" → "无伤时间" |
| 短窗 | 短时机 | "短窗爆发" → "短时机爆发" |
| 推进 | 前进/进行 | "推进当前路线" → "强化当前路线" |
| 构筑 | 组合/搭配 | "构筑完成" → "搭配完成" |
| 承接 | 继续/触发 | "承接连击" → "继续连击" |
| 回切 | 返回/切换 | "回切路线" → "切换路线" |
| 主路线 | 主流派 | "选择主路线" → "选择主流派" |
| 功能开发中 | 即将开放 | （直接移除或改为"即将开放"） |
| 检查装备 | 准备/强化 | "检查装备" → "准备就绪" |
| 调整构筑 | 调整搭配 | "调整构筑" → "调整搭配" |

### 2. 描述长度控制

- **强化描述**：不超过 15 个字符
- **事件描述**：不超过 30 个字符
- **节点标题**：不超过 8 个字符
- **提示文本**：不超过 20 个字符

### 3. 数值描述规范

- 不使用小数点（0.15 → 15%）
- 百分比优先于小数
- 避免连续多个数值（"暴击+5%，爆伤+10%" → "暴击与爆伤提升"）

### 4. 流派机制描述规范

#### 暴击流（破绽机制）
- 使用"破绽"、"标记"、"爆发"等词
- 避免"暴击率"、"暴击伤害"等属性词汇
- 示例：
  - ✅ "命中概率留下破绽"
  - ✅ "破绽持续时间延长"
  - ❌ "暴击率提升"
  - ❌ "暴击伤害+20%"

#### 穿透流（裂纹机制）
- 使用"穿透"、"裂纹"、"回响"、"扩散"等词
- 避免"穿透次数"、"弹道速度"等属性词汇
- 示例：
  - ✅ "子弹可穿透命中后排"
  - ✅ "裂纹扩散范围扩大"
  - ❌ "穿透+1"
  - ❌ "弹速提升"

#### 穿梭流（脉冲机制）
- 使用"脉冲"、"充能"、"反击"、"擦弹"等词
- 避免"冷却缩短"、"伤害加成"等属性词汇
- 示例：
  - ✅ "脉冲充能速度提升"
  - ✅ "满层脉冲触发反击"
  - ❌ "冷却-15%"
  - ❌ "伤害+10"

### 5. 修复类描述

统一使用"修复损伤"代替：
- ❌ "恢复生命值"
- ❌ "治疗"
- ❌ "回血"
- ✅ "修复损伤"

### 6. 简洁化规则

删除以下冗余信息：
- 对精英/Boss的倍率说明（移至系统提示）
- 触发条件的详细数值（显示在效果层）
- 内部机制术语（"堆叠层数"→"叠加"）

### 7. 结算与复盘文本规则

结算页、复盘页、路线提示和结果摘要要按“玩家复盘”来写，不按“系统说明”来写。

- 同一页里，`summary`、`route recap`、`build summary`、`replay prompt` 不能反复讲同一件事。
- 每一行只保留一个信息点，能合并就合并，能删就删。
- 主结算页三段分工要固定：
  - `summary` 只下结论，不重复阶段名和节点名。
  - `route recap` 只讲这把怎么往前走，优先写转折点、异常节点和阶段跃迁。
  - `build summary` 只讲最后差在哪，不再重复“停在某节点”。
- 详情页里的失败原因、路线复盘、转折点也要分工明确：
  - 失败原因只说断点，不回头复述整条路线。
  - 路线复盘只说形成过程，不再补一句同义结论。
  - 转折点只说哪一下把局面往前推了，不写成事件日志。
- 不要把 `原因：`、`建议：`、`目标：`、`注意：`、`优先`、`下局可以` 这类指导口吻直接堆到玩家可见文本里。
- 不要写“像日志一样”的句子，尤其是节点编号、阶段名、原因、建议连着重复出现时，要改成更自然的复盘句。
- 不要让句尾标点在拼接后叠加成 `。`、`，`、`；` 的混合串，生成时统一收尾。
- 如果某一行已经说过路线阶段，下一行就不要再重复阶段名，改写成新的信息。
- 同屏避免复读：
  - 不允许上一句说“停在这里”，下一句再说“断在这里”。
  - 不允许上一句说“已经成型”，下一句只换词再说一次“已经接上 / 已经走到这层”。
  - 不允许把节点名、阶段名、失败原因同时塞进两到三行里反复出现。
- 失败原因应该说什么：
  - 只说最后缺的那一下，比如“收尾没接住”“前排还没拆开”“异常来晚了”。
- 失败原因不该说什么：
  - 不写教学建议，不写操作指导，不写内部机制解释。
- 路线复盘应该说什么：
  - 先有方向，再到成型，再到转折，让玩家一眼看懂这把怎么走到这里。
- 路线复盘不该说什么：
  - 不把“停在某节点”“为什么输”再抄一遍。
- 转折点应该说什么：
  - 只写真正把路线往前推了一层的那一下，优先写异常节点和关键件。
- 转折点不该说什么：
  - 不写“已处理 / 已执行 / 已确认”这类后台口吻。

## 实施检查清单

修改文本时需检查：

- [ ] 是否包含禁用词汇
- [ ] 是否超过长度限制
- [ ] 是否使用玩家语言而非设计语言
- [ ] 是否包含内部技术术语
- [ ] 是否重复了上一行已经说过的信息
- [ ] 是否像系统说明、AI 建议或操作指引
- [ ] 是否与当前机制匹配
