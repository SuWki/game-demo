# 美术资产与画面设计规范

## 文档状态

- 状态：`当前生效 / 美术执行稿`
- 上游依据：`完整体验设计方案.md`、`视觉与UI设计规范.md`
- 下游引用：`美术资产规格表.md`、`画面与UI验收清单.md`、`../40_AI协作/美术与UI统一对接文档.md`
- 使用对象：策划、美术、UI、程序、协作 GPT

## 文档目的

这份文档回答四件事：

- 这款游戏现在应该长成什么样。
- 哪些旧画面语气已经不再采用。
- 美术执行时什么必须先成立，什么可以后补。
- 后续概念稿、图形件、敌人、弹道、场地和界面包装该按什么边界产出。

## 当前生效的一句话定义

这不是“低照度战术终端感”的信息产品，也不是极简网页样机。

当前生效的美术方向是：

`冷核机体 vs 热态火线`

玩家是冷色高亮核心，敌人与危险是热色压制单元，场地是压力结构，UI 是战斗的一部分。

## 不再采用的旧表达

以下说法不再作为当前版本的主语气：

- `低照度战术终端感`
- `终端待命`
- `托盘式决策`
- `低噪音读局`
- `极简科技终端首页`

原因不是它们完全错误，而是它们过于平、过于网页、过于像原型工具，无法支撑这款游戏需要的危险感、重开欲望和敌我对冲。

## 美术总原则

### 1. 先读运动，再读细节

- 所有对象都必须先在移动、闪避、压场和弹幕中可读。
- 轮廓、色相、前后层级优先于贴图和局部花纹。
- 任何静态好看但运动后不可读的方案都不合格。

### 2. 先分敌我，再分职责

- 玩家与敌人必须先在 0.5 秒内被分开。
- 敌人内部再通过轮廓和偏色区分 `standard / brute / skirmisher / ranged`。
- 精英和 Boss 必须比普通敌人多一个明确层级，而不是只放大。

### 3. 危险必须长在画面里

- 危险不主要靠 toast 和说明文字成立。
- 火线、封位、裂口、追击窗口、安全窗必须先被画面读到，再被文字确认。

### 4. 场地不是背景插画

- 场地首先是压力分布图。
- 不做大面积写实地景，不做复杂遮挡，不做分散注意力的装饰堆叠。
- 背景、危险区、扫线和安全口袋都要服务走位判断。

### 5. 程序化语言优先于重资产

- 当前项目适合几何块、发光边、扫描纹、粒子、描边、半透明遮罩。
- 正式美术资产必须能与程序化语言融合，而不是把现有战场语义推翻重来。

### 6. 透明背景是战斗资产硬规则

- 所有战斗单位、弹道、特效、拾取物、Boss 火线、安全窗图形件在生成和接入时都必须使用透明背景。
- 不允许把黑色、深灰色、白色或展示底板烘进素材本体。
- 如果图像生成工具输出了黑底预览，必须先抠掉背景或重出透明背景版本，再进入 `public/assets/preview-runtime/visual/`。
- 素材可以在预览页用深色底板检查可读性，但导出的可接入文件本身必须只包含主体、发光、半透明特效和必要边缘。
- 接入前必须在深色战场和透明棋盘底上各检查一次，确认没有残留黑边、黑块或整张矩形底。

## 颜色规范

### 玩家侧

- 玩家主体：`#F4FAFF`
- 玩家边光：`#73D8FF`
- 玩家冷核：`#BFE9FF`
- 玩家低血警戒：`#FF7E72`

设计原因：

- 冷白蓝能在深底上稳定突出。
- 与敌方暖色天然对冲，识别成本最低。
- 适合“脆但精确”的机体定位。

### 普通敌人侧

- 标准敌主色：`#D94F7A`
- 厚重敌主色：`#C84D5D`
- 侧切敌主色：`#FF5F95`
- 远程敌主色：`#B77CFF`
- 敌方共用暗部：`#7A2942`
- 受击高亮：`#FF9CB6`

设计原因：

- 普通敌统一属于热压阵营，但要在同阵营内读出职责差异。
- `standard` 走标准洋红，读作基础压线。
- `brute` 更偏砖红，读作重、厚、顶线。
- `skirmisher` 更亮更跳，读作侧切和绕进。
- `ranged` 偏紫，读作远程、架火、预热。

### 精英与 Boss

- 精英核心：`#FFB56A`
- 精英高亮：`#FFD39A`
- 护卫 / 屏卫：`#A06DD8`
- Boss 主核：`#FF9462`
- Boss 高亮：`#FFD7B0`
- Boss 危险阶段：`#FF6F5E`
- Boss 火线辅助：`#C78BFF`

设计原因：

- 精英应该被读成“当前主问题”，不是大一点的普通敌人。
- Boss 仍属于敌方体系，但必须更像战场中心事件。
- 紫色屏卫和橙红主核一起出现时，能快速读出“核心 + 保护结构 + 火线”。

### 弹道与危险

- 玩家基础弹道：`#F6FBFF` + `#73D8FF`
- 暴击路线弹道：`#FF8F70`
- 穿透路线弹道：`#68D4FF`
- 穿梭路线弹道：`#9CFF97`
- 普通敌弹：`#FF5B63`
- 普通敌弹边光：`#FF8E95`
- Boss 弹道：`#FF7A5C`
- Boss 火线：`#FFB36B`
- Boss 火线高亮边：`#FFE1A6`
- 危险预热环：`rgba(255,122,92,0.35)`
- XP 球：`#9CFF97`

设计原因：

- 玩家弹道保持冷芯，路线差异放在边光和命中反馈。
- 普通敌弹必须一眼是危险，所以走暖红。
- Boss 弹道必须高于普通敌弹一个层级，所以改用更橙、更热、更像压场火线的颜色。
- XP 球必须和敌弹彻底分开，所以固定使用成长感荧绿。

## 形体规范

### 玩家机体

- 轮廓要求：短、尖、稳，尽量近对称。
- 核心要求：中心必须有冷核亮点。
- 运动要求：朝向一眼可读，不依赖复杂尾焰。
- 气质要求：不是英雄立绘，是战术突击单元。

### 普通敌人

- `standard`：中等体块，轮廓平衡，适合批量出现。
- `brute`：更宽、更厚、更低，像前压盾体。
- `skirmisher`：更尖、更窄、更前倾，像切入针体。
- `ranged`：更规整，带发射口或预热结构，像架火节点。

### 精英

- 精英本体要像核心节点，不像杂兵放大版。
- 护卫要像围绕核心运转的屏障组件。
- 裂口出现时，屏卫必须让出楔形追击通道。

### Boss

- `boss-hunt`：前压感最强，像主动逼近的猎压主核。
- `boss-lockdown`：更像封位装置，空间压缩感最强。
- `boss-bastion`：更像火线阵地，屏卫和扫线结构最重。

## 场地与背景规范

### 背景分层

- 底层：深空黑蓝渐变和轻体积雾。
- 中层：网格、节点、扫线痕、扇区刻度。
- 上层：战斗模板专属危险带、迁火弧线、安全口袋边界。

### 背景目的

- 让玩家知道危险从哪里来。
- 让玩家知道哪里正在被压缩。
- 让玩家知道哪里可能出现可追击的口子。

### 明确禁止

- 写实地形大贴图。
- 大面积散乱霓虹。
- 复杂环境遮挡。
- 与战斗无关的装饰性信息图层。

## UI 图形件规范

### 界面气质

- 现在的 UI 不是“后台工具”，而是“战斗系统的外延”。
- 一级操作名称保持直白，气质放到副标题、形体和光效里。
- 主按钮看起来要像能启动一局战斗，不像平静信息入口。

### 一级用词

- `开始`
- `记录`
- `路线选择`
- `强化选择`
- `异常处理`
- `最终整备`
- `再来一局`

### 二级语气

- 可以继续使用 `切入 / 清场 / 成线`、`短结案 / 快回顾 / 强 CTA` 这类副文案。
- 不再把一级按钮写成过于抽象的命令词，避免牺牲首轮理解速度。

### 图形件要求

- 用切角、短粗条、方向缺口、半透明压板、边缘高亮表现战斗感。
- 不再使用大面积均匀圆角白卡或过于像网页产品的平卡布局。
- HUD 永远优先保护中场。

## 当前版本要先做出来的东西

### P0

- 玩家机体和玩家弹道的冷核识别。
- 四类普通敌的轮廓差异和职责偏色。
- 普通敌弹与 XP 球绝不混淆。
- 精英核心与护卫层级。
- Boss 弹道与普通敌弹的层级差。
- 菜单、HUD、选择面板、结果页的统一图形母设。

### P1

- 路线专属命中特效与边光。
- 精英裂口与追击通道的完整画面语言。
- Boss 模板间更强的场地签名差异。
- 结果页与开始页的情绪强化包装。

### P2

- 更细的材质分层。
- 更完整的粒子语法。
- 更丰富的局部破损、受击、溶解、热量回落表现。

## 明确不做的内容

- 商店、背包、图鉴、长剧情、角色立绘前台。
- 需要大批量叙事插画才能成立的包装。
- 与短局战斗核心无关的重 meta 资产。

## 执行方式

- 方向判断以本文件为准。
- 具体制作尺寸、层级、导出、动画预算以 `美术资产规格表.md` 为准。
- 是否合格以 `画面与UI验收清单.md` 为准。
# 2026-04-23 Boss 安全区生成规则补充

- Boss 绿色安全区属于战斗语义对象，不是纯装饰区块。
- 当前实现以“基础移速 248 × 1.5 秒反应时间 = 372px”作为安全区中心生成距离目标。
- 条形安全窗会在当前轴向上尽量接近该距离；pocket 绿色安全区会按二维中心距离接近该距离。
- 如果当前屏幕边界不足以放下完整安全区，允许夹到可见范围内的最大合法距离，但不允许重新退回纯随机位置。
- 后续调 Boss 强度时优先调反应时间、窗体尺寸或 linger 时间，不建议只靠随机偏移制造压力。
