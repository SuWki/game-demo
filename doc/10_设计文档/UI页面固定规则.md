# UI页面固定规则

## 文档状态

- 状态：`当前生效 / 布局冻结稿`
- 最新依据：`商业化未来科技暗色UI布局与Web实现文档.md` 和用户提供的商业化暗色科技 UI 参考图
- 优先级：高于其他 UI 风格说明
- 使用对象：UI、程序、策划、协作 GPT

## 核心原则

从本版开始，页面布局以商业化未来科技暗色 UI 参考图为最新标准。

- 布局可以按本文件执行，不再沿用“居中标题 + 居中按钮”的旧开始页标准。
- 风格必须统一为未来科技暗色系。
- 允许继续优化材质、描边、发光、动效、字体、按钮状态。
- 未经用户明确确认，不允许跳回绿色卡通风、网页落地页风、SaaS 后台风。

## 总体视觉结构

所有页面必须围绕以下语言：

- 主底色：深黑、深蓝灰、枪铁色。
- 主强调：青蓝能量光。
- 危险强调：橙红。
- 奖励/胜利强调：金色或青绿色。
- 形状语言：切角面板、细描边、雷达环、扫描线、模块化长条。
- 信息密度：商业化游戏 UI，不做后台报表，不做说明文档页。

## 固定页面布局

### 1. 开始页

固定布局：

- 左侧为主信息区。
- 右侧为大型环形核心视觉锚点。
- 左上角保留编号/页面标签，例如 `01 START SCREEN`。
- 主信息区从上到下排列：眉标、主标题、副标题/玩法说明、状态信息、主按钮、次按钮。

固定元素：

- 英文眉标
- 游戏主标题
- 一句玩法定位
- 当前局数/胜场/路线状态
- 主按钮：开始作战
- 次按钮：战斗记录
- 右侧雷达环或核心机体视觉

禁止项：

- 不准改回居中小卡片开始页。
- 不准改成绿色卡通森林页。
- 不准做成网页 landing page。
- 不准让按钮浮在没有结构的空白中心。

### 2. 战斗 HUD

固定布局：

- 左上：HP、EXP 与对应进度条。
- 顶部中间：波次信息。
- 顶部中间下方：当前玩法，如 `歼灭 / 生存 / 精英 / Boss战`。
- 右上可保留轻量目标模块，若实现成本或遮挡风险高，可暂不显示。
- 角色头顶：短血条。

禁止项：

- 不准用大黑框包 HUD。
- 不准遮挡屏幕中心战斗区域。
- 不准新增大段常驻说明。

### 3. 选择页

固定布局：

- 面板位于战场上方的中下区域。
- 顶部居中显示选择标题。
- 下方显示 3 张主要选择卡；若系统实际给 4 个选项，允许扩展为 4 卡，但必须保持同一套商业化卡面语言。
- 卡片是主内容，不额外增加右侧说明栏。
- 可保留编号标签，例如 `03 NODE / UPGRADE SELECTION`。

固定元素：

- 页面编号/模式标签
- 选择标题
- 路线/强化/事件卡组
- 卡片内的类型、品质、标题、效果摘要、确认标签

禁止项：

- 不准使用极简空白卡。
- 不准使用绿色/浅色卡通卡面。
- 不准加右侧大说明栏。
- 不准把选择页做成普通网页表单。

### 4. 结算页

固定布局：

- 左侧为战报信息区。
- 右侧为环形核心视觉锚点和简短 debrief 信息。
- 左上角保留编号/页面标签，例如 `04 RESULT SCREEN`。
- 战报区从上到下排列：眉标、结果标题、本局统计、总结、按钮组。

固定元素：

- 胜负标题
- 路线
- 生存时间
- 等级
- 节点数
- 本局总结
- 主按钮：再来一局
- 次按钮：返回机库/返回主界面
- 右侧视觉锚点

禁止项：

- 不准做成纯居中成绩单。
- 不准做成后台报表。
- 不准加第三个按钮，除非用户明确要求。

## 开发执行规则

- 本文件是当前 UI 布局最高标准。
- `商业化未来科技暗色UI布局与Web实现文档.md` 是当前 Web 实现参考。
- 如果代码与本文件冲突，以本文件为准修正代码。
- 后续如果需要改布局，必须先更新本文件并得到用户确认。
- 如果只是改风格，必须在本文件的固定布局内调整。
