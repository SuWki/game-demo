# 肉鸽胡牌爽感 2.0 设计方案

## 1. 目标

本方案不是继续做“数值更强”，而是把玩家体验改成三段式：

1. 早期能看懂自己在养什么
2. 中期能明确感到 build 开始成型
3. 后期能明显进入“胡了”的兑现状态

核心目标只有一句话：

**让玩家能感受到这局是普通、成型、胡牌三种完全不同的体验。**

---

## 2. 现状判断

当前版本已经有基础路线路线层、成型层、晚期 payoff 层，但还存在四个问题：

1. 路线过散，玩家一开始要处理的分叉太多
2. 异常节点存在感有，但没有进入 build 体系
3. 文案偏系统、偏 AI，像说明书，不像选择
4. 结果页只是在报数，没有把“这把怎么成/怎么没成”讲清楚

所以问题不是“再压一点数值”。
问题是**结构没有把胡牌感显出来**。

---

## 3. 设计原则

### 3.1 少而清楚

路线要少，节点要清楚，玩家一眼知道：

- 我现在在养哪条路
- 我现在缺哪一块
- 这次选择是在补强、成型，还是兑现

### 3.2 玩法优先，数值其次

每条路线必须改变玩家的操作方式，而不是只改伤害数字。

### 3.3 质变要可见

玩家要能清楚感受到：

- 第一次拿到方向件
- 第一次拿到核心件
- 第一次进入胡牌态

### 3.4 失败要可解释

失败不能只是“没过”，要能分清：

- 没成型
- 成型晚了
- 晚期没兑现
- 操作失误

---

## 4. 路线简化方案

### 4.1 结构收敛

建议把路线选择从“多分叉复杂理解”改成“少分叉、强引导”。

#### 早期

- 只暴露少量清晰路线
- 重点让玩家建立方向感
- 不让玩家一开始就同时面对太多语义近似的牌

#### 中期

- 开始出现路线核心件
- 开始让玩家知道这局往哪条线收

#### 晚期

- 主要给 payoff / finisher
- 让成熟 build 更容易兑现，不再继续补洞

### 4.2 标签语义固定

现有标签建议固定为：

- `starter` = 方向件
- `bridge` = 核心件
- `payoff` = 毕业件
- `finisher` = 终局兑现件

这里的关键不是改名，而是把这四层变成明确体验：

- 方向件：告诉玩家“这局在往哪走”
- 核心件：告诉玩家“这局开始成了”
- 毕业件：告诉玩家“这局能打穿了”
- 终局件：告诉玩家“这局可以收了”

### 4.3 路线池权重原则

后期池不再平均分配。

建议原则：

- early：`starter` / `bridge` 轻倾斜
- mid：`bridge` 明显占比提升
- late：`payoff` 优先
- finalPrep / nodePrep：`payoff` + `finisher` 最高

目标不是“每次都出毕业件”，而是：

**成熟 build 更容易在后半段拿到兑现件。**

---

## 5. 异常节点重做方案

### 5.1 现有问题

现在异常节点像“额外奖励”。

但玩家真正需要的是：

**异常节点应该是 build 的第二次质变点。**

也就是说，它不只是给资源，而是改变整局构筑的形状。

### 5.2 异常节点定位

异常节点建议分三类：

#### A. 方向型异常

作用：

- 帮玩家更快决定路线
- 强化当前主线
- 把“还在犹豫”的局面变成“开始收束”

例子方向：

- 锁定当前流派
- 提高当前路线权重
- 让下一次选择更偏向当前路线

#### B. 核心型异常

作用：

- 直接补主机制
- 补核心件缺口
- 让 build 更快进入成型

例子方向：

- 当前流派核心数值强化
- 核心机制触发频率提升
- 核心收益翻倍但附带代价

#### C. 质变型异常

作用：

- 让玩法结构发生变化
- 把“能打”变成“胡了”

例子方向：

- crit 变成连锁爆发
- pierce 变成穿透清线统治
- dash 变成位移反击统治

### 5.3 异常节点和 build 的关系

异常节点不能再是独立岛屿，要和路线绑定。

建议规则：

1. 每条路线至少有 1 个方向型异常联动
2. 每条路线至少有 1 个核心型异常联动
3. 每条路线至少有 1 个质变型异常联动

这样玩家才会觉得：

- 拿到异常节点不是“额外收益”
- 而是“这局真的翻了”

### 5.4 异常节点的选择体验

异常节点最好不是“看不懂的抽象词”，而是直接告诉玩家：

- 它在帮哪条路
- 它会怎么改玩法
- 它是补强还是质变

---

## 6. 文案审查方案

### 6.1 现在的问题

当前文案里存在几类偏 AI / 偏系统表达：

- 权重
- 适配
- 效率
- 路径
- 节点
- 模型
- 复合收益

这些词不是不能用，但不能当主表达。

### 6.2 文案目标

每张牌、每个节点、每个异常，都要尽量回答三件事：

1. 这是什么
2. 它会让我怎么打
3. 它成了以后有多强

### 6.3 文案替换方向

建议把“系统语言”换成“玩家语言”：

- “提高命中效率” -> “更容易打穿”
- “提升资源利用率” -> “更容易成型”
- “增强适配性” -> “更容易接成一套”
- “提高路径权重” -> “更容易拿到这条路的关键件”

### 6.4 文案分层

建议统一为三层：

- 短标题：只讲结果
- 副标题：讲触发方式
- 说明：讲成型后的变化

例子：

- 短标题：连爆更强
- 副标题：连续命中后更容易触发爆发
- 说明：这张牌拿到后，crit 会从稳定输出转成滚雪球爆发

---

## 7. 结果页改造方案

### 7.1 结果页不只报数

结果页应该变成复盘页。

它需要告诉玩家：

- 这把是怎么成的
- 这把为什么没成
- 哪个阶段开始进入胡牌态
- 哪个节点是关键转折
- 下一把该往哪条线补

### 7.2 建议补充的信息

结果页建议固定展示：

- 路线名称
- build 阶段：方向 / 成型 / 胡牌 / 终局
- 关键强化列表
- 关键异常节点
- 节点推进轨迹
- 失败原因摘要
- 最后死在哪个节点

### 7.3 对玩家的实际价值

这样结果页就不只是“你输了”。

它会变成：

- 我这把差什么
- 我下一把该追什么
- 我是不是差一个关键件就能胡

这会显著提高重开意愿。

---

## 8. 路线样板建议

建议先只拿一条路做样板，不要三条一起开。

### 8.1 推荐样板：crit

原因：

- 最容易做出明显质变
- 最容易让玩家感到“爆发链条起来了”
- 最容易从普通状态过渡到胡牌状态

### 8.2 样板目标

`crit` 至少要清楚分成四段：

1. 方向件：开始知道这是暴击流
2. 核心件：暴击链路开始稳定
3. 毕业件：爆发窗口明显放大
4. 终局件：清场和收尾能力明显超标

### 8.3 另外两条路的定位

- `pierce`：穿透清线、后排压制、线性统治
- `dash`：位移反击、规避收益、操作转伤害

但这两条建议放在 crit 样板跑顺以后再扩。

---

## 9. 实施顺序

### 第一阶段

- 简化路线池
- 固化 starter / bridge / payoff / finisher 的语义
- 把 late / finalPrep / nodePrep 的权重往 payoff / finisher 倾斜

### 第二阶段

- 异常节点重做
- 路线绑定异常联动
- 把异常节点从“奖励”改成“质变”

### 第三阶段

- 文案全面审查
- 去掉系统味、AI味
- 统一玩家语言

### 第四阶段

- 结果页复盘化
- 补 build 阶段、关键件、失败原因

### 第五阶段

- 用 `crit` 做样板完整验证
- 再复制到 `pierce`、`dash`

---

## 10. 验收标准

### 路线层

- 玩家一眼能看出当前路线
- 路线选择更少更清楚
- 后期更容易拿到 payoff / finisher

### build 层

- 至少能清楚感知“方向 -> 核心 -> 毕业”
- 异常节点能改变 build 结构
- 不是只有数值提升，而是玩法变化

### 文案层

- 不再像参数说明
- 主要描述玩家感受和战斗结果

### 结果页

- 能复盘“这把怎么成/怎么没成”
- 能告诉玩家下一把该追什么

---

## 11. 风险

1. 路线压得太少，可能导致前期选择变单调
2. 异常节点做得太强，可能压过主路线
3. 文案去系统化后，如果不够准确，可能反而让信息变糊
4. 结果页信息过多，可能变成新的阅读负担

所以这套方案要按“先收敛，再质变，再复盘”的顺序做，不能一口气全铺开。
