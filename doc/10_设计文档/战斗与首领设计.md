# 战斗与首领设计

## 战斗层目标

战斗不是单纯刷怪，而是承担三件事：

- 给玩家明确压力
- 给玩家成长反馈
- 给路线差异提供落地场景

## 当前战斗回报链目标

当前普通战要能清楚成立一条回报链：

- 打中时知道自己命中了
- 打死时知道这一只已经被你收掉
- 掉经验时愿意主动追过去捡
- 捡到后能明显感觉这波收益正在把下一轮战斗推起来

如果这条链断掉，哪怕路线内容还在，战斗也会显得“能玩，但不够爽”。

## 当前战斗家族

- 普通歼灭
- 精英压制
- 生存压制
- 首领战

## 设计原则

- 普通战承担最稳定推进
- 精英战承担拆掩护和追击本体的压力
- 生存战承担持续压迫和节奏变化
- 首领战承担最终收尾和阶段变化
- 普通战的击杀、掉落、吸附和升级衔接必须足够顺，不然核心循环会显得发闷

## 首领设计为什么不能只堆数值

如果首领只是更肉、更多怪，玩家会把它理解成普通战加量版。

所以当前首领战强调：

- 阶段切换
- 阶段提示
- 短时强提示
- 持续压迫模式
- 更明显的目标识别

## 当前首领设计边界

- 首领已经有独立节点语义
- 首领模板和普通战模板分开管理
- 运行时仍复用战斗主流程，不额外上独立首领系统
- 后续如果要继续提升首领体验，优先补“可读的阶段压力”，而不是简单堆血量

## 当前首领主要风险

- `屏卫主核` 的后段火线阶段在普通构筑中的覆盖率偏低
- 这说明首领收尾体验仍有局部不稳定，而不是主流程失效

## 当前战斗打磨边界

- 优先补击杀兑现、拾取节奏、战场可读性
- 可以继续补轻量音效和表现反馈
- 不通过重写战斗系统来制造爽感
- 不因为一轮战斗打磨就把项目拉回 Boss 专项轮或地图专项轮
## 近期战斗补充结论

- 普通战斗除了击杀回报链，还要在低血时快速读到“危险已经压上来”。
- 这类危险感目前允许的做法仍是轻量补强：
  - 屏幕边缘危险色带
  - 玩家周围的危险圈和受击后压迫提示
  - 提升 `battle / boss` 音乐与 `hit / kill / pickup / pressure` cue 的整体能量
- 这些都属于现有表现层和音频层的继续压实，不是新系统。
- 当前验证结果表明：低血自然样本里危险感已经更容易被读到，但没有明显遮挡战场主要信息。

## 2026-04-15 战斗补充结论

- 当前普通战打磨可以继续沿三条线推进，但都必须留在现有战斗骨架里：
  - 敌人出手后的短破绽窗口
  - `crit` 的收割兑现节奏
  - `pierce` 的贯穿清线读感
- 允许的做法：
  - 用现有敌人状态补“短 recovery / punish window”
  - 用现有子弹、脉冲、目标选择和音频 cue 强化 `crit / pierce` 的即时爽点
  - 用轻量渲染把“现在能追击、现在能清线”做得更容易看懂
- 不建议的做法：
  - 不要新增独立连招系统
  - 不要把敌人公平性问题改写成大规模 AI 重做
  - 不要为了爽感把满屏文字说明重新塞回战斗界面
- 当前已验证成立的一点是：
  - 在不改主流程的前提下，普通战已经可以同时补“公平性”和“爽点”，而不是只能二选一。

## 2026-04-15 第 2 次战斗补充

- 当前普通战又往前推进了一层：
  - 回报链现在不仅要让玩家知道“这一波赚到了”，还要帮助下一波敌人更快续上
  - 敌人家族的恢复和再压上节奏，也要读起来像不同打法，而不是同样的追人球
- 当前允许继续补的内容：
  - 轻量 battle flow surge
  - 普通敌人恢复期和再进攻期的微行为人格
  - 与 `tempoPulse` 相关的移动、追击和清线手感
- 当前不建议做的事：
  - 不要用粗暴堆怪量去伪造节奏更快
  - 不要因为想让敌人有性格，就重写一整套行为树
- 这轮后可以确认：
  - 普通战已经开始有“越打越顺、越打越会往下一拍滚”的感觉，这比单纯多加特效更接近真正的核心战斗优化。

## 2026-04-15 第 3 次战斗补充

- 当前战斗层的主问题已经从“普通战会不会掉拍”进一步收窄成：
  - 精英战能不能稳定读出比普通战更高一级的压迫层次。
  - 路线爽点能不能在实战里重复出现，而不是只在升级和结果页被理解。
- 当前允许的做法：
  - 用现有敌人状态补“压迫脉冲 -> 短收招窗口 -> 再压上”的精英节奏。
  - 用现有目标选择、子弹命中、击杀兑现和脉冲表现，补 `crit / pierce` 的 live mini-high。
  - 用现有普通敌人行为继续做家族协同，而不是把它们维持成四种孤立单兵。
- 当前已成立的新读法：
  - 精英开始更像“先顶、先封、先拉开，再给你一个短处理窗口”的战斗，而不是单纯血更厚。
  - `standard / brute / skirmisher / ranged` 更像在共同塑造场面：
    - `standard` 负责贴前排补线。
    - `brute` 负责带线顶压。
    - `skirmisher` 负责绕侧切回。
    - `ranged` 负责借屏射击。
  - `crit / pierce` 的实战爽点开始更依赖战场时机，而不是只靠面板累计。
- 当前仍不建议做的事：
  - 不要为了继续拉开精英层次而开新系统或重写 AI。
  - 不要把这轮重新做成 Boss 轮或纯表现层轮。
- 本轮验证结论：
  - 普通战家族人格继续上升。
  - 精英压迫层次已经开始成立，但下一轮仍需要继续看自然样本里是否足够稳、足够常被玩家读出来。

## 2026-04-15 第 4 次战斗补充

- 当前战斗层的主问题进一步收窄成：
  - 精英本体与护卫之间的 handoff 是否已经足够稳定。
  - 精英收招后的裂口窗口是否已经足够容易被玩家读成“现在该追击本体了”。
- 当前允许的做法：
  - 用现有 `pressurePulseSec / recoverySec / tacticCooldownSec` 让护卫跟着精英脉冲同步压上。
  - 用现有护卫恢复窗口和轻量渲染，把“屏裂开了”做得更容易看懂。
  - 让 `crit / pierce` 在这些裂口里多拿到一点即时兑现，而不是新开系统。
- 当前不建议做的做法：
  - 不要为了这类联动去新开精英专属系统或行为树。
  - 不要把这轮重新做成 Boss 轮、地图轮或纯 UI 轮。
- 本轮验证结论：
  - `npm run build` 通过。
  - `output/playwright/battle-feel-pass/round15/full-flow/summary.json` 中 `resultSeen = true`、`replaySeen = true`、`consoleErrors = []`。
  - `output/playwright/battle-feel-pass/round15/general-check/battle-opening.png` 与 `battle-pressure.png` 未见普通战画面回退。
- 当前残余风险：
  - 定向精英截图验证还没有稳定命中自然样本，因此“精英裂口窗口是否足够常被读出”仍需下一轮继续复检。

## 2026-04-15 第 5 次战斗补充

- 当前战斗层继续只补精英战里的“裂口追击”，没有把主线切回普通战大修、Boss 专项或新系统。
- 当前允许的做法：
  - 用现有 escort / recovery / rangedCooldown / target 选择，让裂口不只是数值上的短停顿，而是实际把追击路让出来。
  - 用轻量楔形追击提示，把“现在该追本体”做成战场里的读感，而不是额外说明文字。
  - 用极小的 QA 快照口子复检精英窗口，不把验证重新做成新框架。
- 这轮新成立的读法：
  - 精英收招后，护卫会更像“从本体前面裂开”，而不是原地一起变软。
  - 自动火力在裂口期更容易顺着窗口去追精英本体，场面更接近“先拆屏，再追击”的解题感。
  - `crit / pierce` 的即时兑现会更稳定落在裂口后的追击上，而不是只在普通战里亮一下。
- 当前验证结论：
  - `npm run build` 通过。
  - `output/playwright/battle-feel-pass/round16/full-flow/summary.json` 中 `resultSeen = true`、`replaySeen = true`、`consoleErrors = []`。
  - 定向精英 rerun 已能复现 `eliteRouteChosen = true`、`eliteBattleSeen = true`。
- 当前残余风险：
  - 精英战的“命中样本”已经可复现，但精确裂口帧仍有一定采样时机波动，还需要继续复检，不适合现在就宣布精英层完全签收。

## 2026-04-15 第 6 次战斗补充

- 当前战斗层在不改主流程的前提下，已经可以继续补更“拿起来就能感觉到”的反馈层：
  - 开火声必须稳定存在，不能只剩命中后才有声响
  - 受击与近失要有明确区分，避免玩家分不清是声音太小还是没触发
  - 移动手感允许有轻量起步冲感、转向爆发和短滑移，但不能改成飘忽的新系统
  - 不同 battle family 允许有更清晰的场地签名，让普通战 / 精英战 / 生存战一进场就不像同一张皮
- 当前允许的做法：
  - 在现有 `PilotAudio` 里补 `shoot / hurt / enemyShot / nearMiss` 这类即时 cue，并继续沿现有 BGM 模式做轻量增益
  - 在现有 `BattleState` 里补轻量 `velocity / boost / turn-burst` 承接，服务移动与开火一体化手感
  - 在现有 `GameScene` 渲染层里继续补战场底纹、推进导向和 pressure backdrop，而不是新增独立玩法系统
- 当前不建议的做法：
  - 不要把移动手感优化写成复杂冲刺树、闪避系统或独立受击系统
  - 不要为了做“关卡特色”去重开地图可视化主线
  - 不要用满屏说明文字去解释战场，而是继续让反馈本身可读
- 这轮后可以确认的一点：
  - 当前项目的主缺口已经不只是“战斗能不能读懂”，还包括“战斗拿在手里是不是已经有劲、有声、有差异”。
## 2026-04-15 第 7 次战斗补充

- 当前主线继续停留在“核心循环 / 核心战斗打磨”，没有切回地图可视化、Boss 专项或新系统开发。
- 这轮重点继续收窄成三件最直接的战斗反馈：
  - 击中确认
  - 受击方向确认
  - 连杀滚动一拍
- 当前允许继续做的做法：
  - 沿现有 `BattleState` 与 `GameScene` 渲染层补玩家外圈的来向提示，而不是加解释性说明。
  - 沿现有 `tempoPulse / moveBoost / shotFlash` 骨架，把“击杀后一拍还在往前滚”的感觉压实。
  - 只在 `PilotAudio` 里做轻量 battle 音乐和 `hit / hurt / kill / enemyShot / nearMiss` cue 抬升，不重写音频系统。
- 当前不建议做的做法：
  - 不要为了更爽去新开武器系统、连招系统或独立受击系统。
  - 不要把这轮重新做成 UI 轮、Boss 轮或地图轮。
- 这轮后能成立的判断是：
  - 普通战已经更接近“打中就知道打中了，被打就知道从哪来，连杀就知道节奏滚起来了”的即时战斗体验。
