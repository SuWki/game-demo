# Auto-Shooter 项目复盘报告

**复盘时间**: 2026-05-25  
**项目周期**: 约3个月（Codex+Kimi协作开发）  
**用户角色**: 方向把控 + 需求提出 + 验收判断  
**AI角色**: 详细设计 + 代码实现 + 文档产出  

---

## 一、项目真实分工模式

### 实际协作方式

| 环节 | 用户 | AI (Codex+Kimi) |
|------|------|-----------------|
| **方向制定** | ✅ 提出核心体验目标 | ❌ |
| **系统设计** | ⚠️ 审核/否决/调整 | ✅ 出完整方案 |
| **数值设计** | ⚠️ 提出体感目标 | ✅ 设计公式和配表 |
| **代码实现** | ❌ 基本不参与 | ✅ 全部代码 |
| **配置工具** | ❌ 提需求 | ✅ 完整实现 |
| **验证测试** | ✅ 游玩+提反馈 | ⚠️ 辅助分析 |
| **文档产出** | ❌ 审阅 | ✅ 大量设计文档 |

### 关键认知

> **这个项目是你"验收"出来的，不是"亲手做出来"的。**

这不是缺点——利用AI提效是现代策划的必备能力。但求职时必须诚实面对：
- ✅ 你能**定义问题**和**判断好坏**
- ✅ 你能**和AI协作**完成原型
- ❌ 你**不能直接回答**很多设计细节
- ❌ 你**还没掌握**配置表设计和数值公式推导

## 二、知识盲区分析

### 盲区1：配置表底层结构

**现状**:
- 你知道配置表"长什么样"
- 你能在配置编辑器里修改数值
- 但你**说不清为什么这样设计表结构**

**具体盲区**:
```typescript
// 你能看到这段代码，但回答不了：
interface UpgradeConfig {
  id: string;
  category: 'crit' | 'pierce' | 'dash' | 'generic';
  rarity: Rarity;
  effects: ContentEffect[];  // 为什么是数组？支持多效果吗？
  modifiers: StatModifiers;  // 这些数值怎么来的？
}

// 盲区问题：
// 1. 为什么选择这些字段？每个字段的设计意图是什么？
// 2. effects数组和modifiers对象的区别和关系？
// 3. 如果新增一种效果类型，需要改哪些地方？
// 4. 稀有度倍率是怎么推导出来的？
```

**需要补课**:
- 游戏配置表设计范式（扁平vs嵌套、继承vs组合）
- 数据驱动架构的基本原理
- 如何从零设计一个可扩展的升级系统数据结构

### 盲区4：设计文档的"为什么"

**现状**:
- 文档很多很全
- 但让你回答"为什么选择这种设计"，你会卡壳

**示例问题**:
- 为什么是三路线，不是四路线或两路线？
- 为什么dash有invincible frame，其他路线没有？
- 为什么elite的护卫设计成"锚定"而不是"追击"？
- 为什么Boss要分3个phase，不是2个或4个？

**注意**: 这些问题AI能回答，但你需要内化成自己的理解。

## 三、求职策略调整

### 原策略（过于乐观）

> "我有完整项目，可以主投战斗策划"

### 调整后的策略

> "我有AI协作经验 + 原型验证能力，正在系统学习战斗策划底层知识"

### 面试口径建议

**不要这样说**:
- ❌ "我设计了三条路线"
- ❌ "我做了数值平衡"
- ❌ "我实现了配置编辑器"

**要这样说**:
- ✅ "我定义了自动射击+流派构建的核心体验方向"
- ✅ "我在AI协助下验证了三种战斗风格的差异化"
- ✅ "我主导了多轮体验迭代，学会了用自然样本和定向样本验证设计"
- ✅ "我意识到自己在数值推导和配置设计上还需要深化，正在系统补课"

### 适合的岗位调整

| 岗位 | 原评估 | 调整后 |
|------|--------|--------|
| **战斗策划** | 主投 | 可以投，但要诚实说明协作模式 |
| **系统策划** | 不建议 | 更不建议（配置表设计是盲区）|
| **执行策划** | 没考虑 | **重点考虑**（适合当前能力层级）|
| **策划实习生** | 不考虑 | **可以考虑**（如果接受降薪换学习）|

**执行策划的优势**:
- 对数值推导的要求相对较低
- 重在落地和迭代，你的AI协作经验是加分项
- 有机会跟着主策学习底层设计方法

## 四、具体学习计划

### 阶段1：夯实基础（2-4周）

目标：能回答"为什么这样设计"

**任务清单**:
1. **配置表设计**
   - 重读 `upgrades.ts`、`battleTemplates.ts`、`enemyArchetypes.ts`
   - 画出每个配置的数据结构图（字段关系、引用关系）
   - 思考题：如果要新增一个"灼烧"效果，需要改哪些文件？

2. **数值公式**
   - 重读 `balance.ts`、`combatFormulas.ts`
   - 每个公式手算一遍，理解参数变化对结果的影响
   - 思考题：如果要把游戏时长从8分钟改为15分钟，哪些数值需要调整？

3. **战斗循环**
   - 重读 `RunEngine.ts` 的 `tick()` 方法
   - 画出游戏主循环的流程图
   - 思考题：每帧都做了什么？哪些可以优化？

### 阶段2：复盘重构（2-3周）

目标：假设没有AI，你能重做一遍

**任务清单**:
1. **手写简化版配置表**
   - 不看代码，自己设计一个升级系统的配置结构
   - 然后对比现有设计，分析差异

2. **手推数值曲线**
   - 假设敌人血量随轮次增长，设计一个合理的公式
   - 考虑：线性增长？指数增长？对数增长？为什么？

3. **拆解RunEngine**
   - 尝试用伪代码重写 `RunEngine` 的核心循环
   - 目标：按职责拆分（EnemySystem / ProjectileSystem / RouteSystem）

### 阶段3：面试准备（持续）

**必会问题清单**:

**项目相关**:
1. 为什么选择做自动射击+Roguelike？
2. 三条路线的核心差异是什么？（要能说出"空间要求"层面）
3. 你是怎么验证精英/Boss设计是否成立的？
4. 如果让你再做一次，你会在架构上做什么不同选择？

**设计理论**:
1. 游戏战斗设计的核心是什么？（建议答案：决策空间 + 反馈节奏）
2. 怎么设计一个"有辨识度"的敌人？
3. 怎么平衡三路线，让没有一条特别强或特别弱？

**诚实问题**:
1. 这个项目有多少是你自己做的，多少是AI做的？
   - **建议回答**: "我负责方向定义和体验判断，AI协助完成详细设计和代码实现。这个项目帮我学会了如何定义战斗问题和验证设计假设，也让我意识到自己在数值推导和系统架构上需要继续学习。"
