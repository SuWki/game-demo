## 项目一句话

这是一个基于 `Phaser + TypeScript + Vite` 的 Web 端短局节点推进自动射击原型。
仓库名虽然叫 `unity-learning`，但当前重建版本不是 Unity 项目，所有实现和判断都必须以当前 Web 代码为准。

## 体验目标

验证“手动走位 + 自动攻击 + 战斗内升级 + 轻量节点推进”能否在 `8~12` 分钟内支撑三条清晰、可复玩的流派路线，并让玩家在结算后愿意马上再开一局。

当前体验链路是：

开始页 -> 进入一局 -> 普通战 / 精英战 / 生存战 -> 节点选择 -> 强化选择 -> 异常事件 -> 最终整备 -> Boss 战 -> 结果页 -> 重开

## 当前主问题

当前主线已经从“路线单点补强”转成“全链路游玩体验是否足够顺、足够清楚、足够想再打一局”，同时要为求职作品留下能证明设计能力的证据链。

优先关注：

- 普通战的“击杀 -> 掉落 -> 吸附 -> 升级 -> 继续追击”回报链是否顺。
- 战斗手感是否足够跟手，移动、开火、命中、击杀、拾取是否形成连续身体感。
- `shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot` 是否能在混战里分得开。
- `crit / pierce / dash` 三条路线是否不是单纯数值，而是能形成“入口 -> 承接 -> 兑现”的构筑链。
- 精英战和 Boss 战是否能考验不同路线的解法，而不是只提供更厚的血条。
- 背景、路线特效、Boss 安全区、敌弹、XP 球是否同时可读，不互相抢信息。
- 镜头、全屏闪、边框脉冲、背景层不能造成眩晕或误读。
- 玩家可见文字不能出现乱码、英文占位或过度技术化表达，提示要短、准、通俗。

## 当前最新结论

截至 `2026-05-15`：

- 当前主流程可运行，菜单、战斗、节点、升级、异常、最终整备、Boss、Boss 收尾和结果页都已接通。
- 背景、敌人、Boss、命中特效、路线尾迹等预览素材已经部分接入，项目视觉不再是纯测试占位，但仍要防止背景和特效干扰读局。
- 镜头预测偏移、抖动、穿梭缩放和连杀边框缩放已收敛，下一步需要实机确认是否解决眩晕感。
- 关卡选择前的“进度条感”装饰已改成“下一站 / 选择规则”说明，仍需确认玩家是否一眼能懂。
- `crit / pierce / dash` 已有 `starter / bridge / payoff / finisher` 分层、路线牌上限、价值审计、敌人状态标记和 11 张关键牌真实机制接线。
- 路线价值审计硬违规 0、超预算 0 只能说明预算健康，不代表三路线已经完成构筑体验。
- 当前路线体验仍需人工实机回答：第几张路线牌开始成型、是否仍 1 到 2 张杀穿精英/Boss、`pierce` 蓝色裂纹是否看得清、`crit` 是否仍强于另外两条路线。
- Boss 安全区、区外惩罚、区内清弹和 Boss 氛围层已接入，但 Boss 是否“高压但公平”仍需人工验证。
- 当前 P0/P1 回归重点是玩家可见体验收口：游戏内设计语、玩家周围无意义线条、路线牌难懂描述、Boss/精英读局提示都要优先清理。
- 强制 Boss / debug 战斗入口不再把 `[DEBUG]` 写入玩家 HUD；如截图里还看到 `[DEBUG]`，先确认是否为旧 QA 截图残留。
- 玩家周围表现层原则已经明确：不要恢复常驻路线线条、路线冷却条、路线光环或大型圆环；但敌方瞄准线、Boss 安全区、精英护卫关系线、近失/受击方向属于读局信息，不能误删。
- 路线牌描述已经通过 `ROUTE_DESCRIPTION_OVERRIDES` 做统一覆盖，后续新增路线牌也必须写清“触发条件 + 实际收益”，不能只写表现词或内部设计语。

### 当前最重要的未完成项

- 路线构筑验收：确认三路线是否真的依赖多张牌组合，而不是拿到单张高价值牌就变成路线。
- 关卡与敌人职责：普通战、精英战、生存战、Boss 战需要给玩家不同任务，而不是都只是清怪。
- 操控与舒适度：移动、拾取、镜头、背景、全屏反馈要先通过人工体感，再继续加表现。
- 表现层读局：路线特效、Boss 安全区、敌弹、XP 球、背景贴片不能混成视觉噪音。
- 求职作品证据链：需要能展示“问题 -> 设计假设 -> 修改方案 -> 验证数据/截图 -> 结果复盘”的材料，而不是只展示最终画面。

## 三条路线

- `crit` 暴击路线：升温、爆发、连续命中后的集中兑现。
- `pierce` 穿透路线：拆线、贯穿、拉轨、清线和回收。
- `dash` 穿梭路线：换位、擦身、蓄能反打和节奏循环。

路线设计不是开局直接锁死，而是：

前段给方向 -> 中段站稳 -> 后段兑现 -> Boss 战验证

## 代码地图

主入口：

- `src/main.ts`

- `src/scenes/MainMenuScene.ts`：开始页、开始按钮、导出入口

## 每轮开发流程

1. 先读 `START_HERE.md` 和 `当前交接卡.md`。
2. 明确本轮只解决一个主问题。
3. 阅读对应专题设计文档和 AI 对接文档。
4. 先用中文说明判断：当前项目是什么、当前阶段是什么、本轮要解决什么、不做什么、准备改哪些文件。
5. 再改代码。
6. 至少执行 `npm run build`。
7. 按任务性质做 full-flow、debug 面板、音频快照或截图验证。
8. 新增一篇 `doc/30_持续优化/开发复盘/日期_主题.md`。
9. 更新 `当前交接卡.md`。
10. 如果设计边界变化，同步更新 `10_设计文档` 与 `20_设计闭环`。

## 验证最低标准

任何实际开发完成后，至少要说明：

- `npm run build` 是否通过。
- 是否跑过菜单 -> 战斗 -> 节点 / 强化 / 异常 / 整备 -> Boss / 结果页的完整流程。
- 是否有 `consoleErrors`。
- 如果改战斗手感，说明移动、开火、命中、击杀、拾取链条是否改善。
- 如果改音频，说明 `shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot` 是否更可辨。
- 如果改路线，说明 `crit / pierce / dash` 是否没有回退。
- 如果改精英或 Boss，说明是否做过定向调试样本。
