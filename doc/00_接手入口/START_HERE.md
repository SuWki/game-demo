## 文档目的

这份文档是本项目的无上下文接手总入口。
新接手者只看这份文档，也应该能知道：项目是什么、现在做到哪、下一步该做什么、哪些事情不能做、该读哪些文档、该改哪些代码、该怎么验证。

## 项目一句话

这是一个基于 `Phaser + TypeScript + Vite` 的 Web 端短局节点推进自动射击原型。
仓库名虽然叫 `unity-learning`，但当前重建版本不是 Unity 项目，所有实现和判断都必须以当前 Web 代码为准。

## 体验目标

验证“手动走位 + 自动攻击 + 战斗内升级 + 轻量节点推进”能否在 `8~12` 分钟内支撑三条清晰、可复玩的流派路线，并让玩家在结算后愿意马上再开一局。

当前体验链路是：

开始页 -> 进入一局 -> 普通战 / 精英战 / 生存战 -> 节点选择 -> 强化选择 -> 异常事件 -> 最终整备 -> Boss 战 -> 结果页 -> 重开

## 当前主问题

当前主线已经从“路线单点补强”转成“全链路游玩体验是否足够顺、足够清楚、足够想再打一局”。

优先关注：

- 普通战的“击杀 -> 掉落 -> 吸附 -> 升级 -> 继续追击”回报链是否顺。
- 战斗手感是否足够跟手，移动、开火、命中、击杀、拾取是否形成连续身体感。
- `shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot` 是否能在混战里分得开。
- `crit / pierce / dash` 三条路线是否都有基本实战签名。
- 精英战是否稳定读成“护卫成屏 -> 裂口 -> 追击本体”的解题型高压层。
- `屏卫主核` 的后段火线阶段仍是 Boss 监控项，不能在战斗打磨中回退。
- 玩家可见文字不能出现乱码、英文占位或过度技术化表达，提示要短、准、通俗。

## 当前最新结论

截至 `2026-04-26`：

- 普通战回报链已经基本站稳，但仍要继续防回退。
- `pierce` 已补入轻量 `pierceFlow` 手感窗口，穿透命中、回声、裂口贯穿和拾取承接会短暂形成“拉轨”感。
- `dash` 后段 payoff 和持续签名已经做过一轮兑现，定向样本能看到折返追击、借窗反打和回切承接。
- 移动起步、停手、反向转向已比早期更干脆，但仍不应通过大幅加移速来解决所有手感问题。
- `PilotAudio` 已沿现有 cue 增强 route tint 和危险语义，没有新增复杂音频系统。
- `window.__pilotAudioDebug()` 已能返回 `routeFocus / encounter / intensity`，用于验证音频上下文是否正确同步。
- `2026-04-25` 自然样本与 Boss / 精英监控显示，`dash` 补强没有明显破坏普通战、精英战和 Boss 主链路。
- 当前更值得做的是操控手感、打击手感、音效层级和通俗提示的整体补强，而不是继续扩 `dash` 内容池。
- 文档和代码里仍要重点扫描乱码与玩家可见技术词，尤其是 toast、节点/升级说明、危险提示和结算文本。
- 当前程序化表现已经更像游戏现场，但还不是正式美术 / 音频资产签收态。

## 三条路线

- `crit` 暴击路线：升温、爆发、连续命中后的集中兑现。
- `pierce` 穿透路线：拆线、贯穿、拉轨、清线和回收。
- `dash` 穿梭路线：换位、擦身、蓄能反打和节奏循环。

路线设计不是开局直接锁死，而是：

前段给方向 -> 中段站稳 -> 后段兑现 -> Boss 战验证

## 代码地图

主入口：

- `src/main.ts`

场景：

- `src/scenes/MainMenuScene.ts`：开始页、开始按钮、导出入口
- `src/scenes/GameScene.ts`：主战斗场景、输入、渲染、HUD 同步、调试面板同步
- `src/scenes/ResultScene.ts`：结果页、重开、返回菜单

系统：

- `src/systems/RunEngine.ts`：单局主循环、战斗、节点、升级、异常、路线、结果
- `src/systems/PilotAudio.ts`：程序化音乐、SFX、ducking、cue 上下文、音频快照
- `src/systems/MetricsTracker.ts`：埋点与导出
- `src/systems/MetaProgression.ts`：局外轻量统计

UI：

- `src/ui/OverlayController.ts`：HUD、选择面板、异常面板、结果页、toast
- `src/ui/BattleDebugPanel.ts`：调试面板
- `src/style.css`：DOM UI 视觉样式

数据：

- `src/data/balance.ts`：数值公式、经验、磁吸、移动、路线参数
- `src/data/battleTemplates.ts`：普通战、精英战、生存战、Boss 战模板
- `src/data/nodes.ts`：节点推进
- `src/data/upgrades.ts`：强化定义
- `src/data/events.ts`：异常事件
- `src/data/contentSelectors.ts`：内容分发权重
- `src/data/routes.ts`：路线定义
- `src/data/enemyArchetypes.ts`：普通敌家族

类型：

- `src/game/types.ts`：核心共享语义。改这里必须同步文档。

## 每轮开发流程

1. 先读 `START_HERE.md` 和 `当前交接卡.md`。
2. 明确本轮只解决一个主问题。
3. 阅读对应专题设计文档和 AI 对接文档。
4. 先用中文说明判断：当前项目是什么、当前阶段是什么、本轮要解决什么、不做什么、准备改哪些文件。
5. 再改代码。
6. 至少执行 `npm run build`。
7. 按任务性质做 full-flow、debug 面板、音频快照或截图验证。
8. 新增一篇 `doc/30_持续优化/开发复盘/日期_主题.md`。
9. 更新 `当前交接卡.md`。
10. 如果设计边界变化，同步更新 `10_设计文档` 与 `20_设计闭环`。

## 验证最低标准

任何实际开发完成后，至少要说明：

- `npm run build` 是否通过。
- 是否跑过菜单 -> 战斗 -> 节点 / 强化 / 异常 / 整备 -> Boss / 结果页的完整流程。
- 是否有 `consoleErrors`。
- 如果改战斗手感，说明移动、开火、命中、击杀、拾取链条是否改善。
- 如果改音频，说明 `shoot / hit / kill / pickup / hurt / nearMiss / pressure / enemyShot` 是否更可辨。
- 如果改路线，说明 `crit / pierce / dash` 是否没有回退。
- 如果改精英或 Boss，说明是否做过定向调试样本。
