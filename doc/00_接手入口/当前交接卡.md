## 当前项目是什么
- 一个基于 `Vite + TypeScript + Phaser` 的俯视角轻量化 Roguelite 飞行射击原型。
- 玩家在节点地图中选择路线，进入战斗，拾取 XP，获得升级，并通过 `crit / pierce / dash` 三条路线形成不同战斗倾向。
- 当前版本继续坚持“程序化表现优先”：先把读局、手感、反馈和节奏做扎实，不急着替换大规模正式美术和音频资产。

## 当前最需要解决的问题
- Kimi 修复验收：音量面板、暂停继续、素材透明、拖尾、属性显示需要用 full-flow 和专项样本复检。
- Boss 战复检：弹幕密度下调后需验证是否从“不可躲”回到“高压但可读”，安全窗是否足够明显。
- 精英机动复检：机动性提升后需观察是否导致近战压迫过强。
- Boss / 精英机制：如果仍像木桩，下一轮补可读预警、弱点窗口、护卫/裂口/短冲锋等单点机制，不直接堆血量或弹幕。
- 操控手感：自然样本中第 2~3 节点的打断问题仍需观察。
- 音效反馈：需实机听感复检，确认 `kill` 不盖过 `hurt / pressure`。
- 提示和文字：新增 toast、节点、升级、结算文案时仍必须跑乱码扫描。

## 下一轮建议
优先做一轮“体验修复验收与自然样本复检”，而不是继续扩路线内容池或新增 Boss。

建议开发顺序：
1. 先验收 Kimi 已修的 7 个玩家反馈问题。
2. 再做 Boss / 精英专项样本，确认高压、可读和反打窗口是否成立。
3. 然后复检音效层级，尤其是 `kill`、`hurt`、`pressure` 是否互相遮盖。
4. 如果验收通过，再进入作品集截图、短视频脚本和素材音效 A/B 展示。
5. 如果验收不通过，再给 Kimi 开一轮“小步修复提示词”，只针对失败项修，不扩系统。
